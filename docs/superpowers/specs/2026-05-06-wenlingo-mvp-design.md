# Wenlingo MVP 功能与需求设计

日期：2026-05-06

## 1. 摘要

Wenlingo（小文星球）MVP 是一个浏览器优先的半真实产品，用于验证小学中文语文阅读与写作成长的最小学习闭环。MVP 的第一优先级是跑通完整学习数据飞轮，同时把 AI 陪练质量作为硬性门槛。

MVP 要验证孩子能否完成：

```text
简化家长登录
-> 选择孩子档案
-> 完成极简诊断
-> 获得今日推荐任务
-> 完成句子与作文真实训练
-> 收到 AI 陪练反馈
-> 更新能力画像与游戏化进度
-> 家长查看周报或阶段报告
-> 系统推荐下一轮任务
```

Wenlingo 不是通用作文助手，也不是代写工具。它的定位是 AI 语文陪练：帮助孩子回忆、组织、表达、修改和看见进步，但不替孩子生成可直接提交的作文。

## 2. MVP 目标

### 2.1 核心目标

验证一个半真实学习闭环是否成立：

- 孩子能完成诊断、训练、反馈、修改、结算、再推荐；
- 家长能看见孩子练了什么、哪里进步、下一步练什么；
- 系统能根据训练数据持续更新能力画像。

### 2.2 AI 质量目标

AI 反馈必须做到：

- 不代写；
- 温和鼓励；
- 具体指出优点；
- 给出 1 到 3 个可执行修改任务；
- 输出能被后端稳定解析的结构化结果；
- 对孩子友好，对家长专业但不制造焦虑。

### 2.3 内测对象

第一阶段内测围绕 4 个孩子档案：

- 1 个真实孩子：作为主线体验和难度校准样本；
- 1 个表达空泛型模拟孩子；
- 1 个作文结构薄弱型模拟孩子；
- 1 个阅读概括薄弱型模拟孩子。

真实孩子第一阶段优先提升：

- 把句子写具体、生动；
- 作文选材和细节展开。

## 3. 非目标

MVP 暂不做：

- 老师端、班级管理、多家庭正式运营后台；
- 商业化支付；
- 大规模阅读库；
- 精细化中文阅读难度指数；
- OCR 手写作文识别；
- 语音输入；
- 移动 App；
- 开放式 AI 语文聊天助手；
- 排行榜、社区分享、商城、宠物养成、复杂技能树；
- 一键生成作文；
- 标准范文或可直接提交的完整作文；
- 复杂自适应学习算法。

## 4. 交付形态

MVP 是半真实产品：

- 作文训练和句子训练必须接入真实 LLM、真实保存训练数据、真实更新能力画像；
- 阅读训练可以使用少量内置文章和题目；
- 登录、周报和 Dashboard 可以简化，但必须能支撑真实演示和早期家庭内测；
- 第一版运行在桌面浏览器和平板浏览器中；
- 未来 App 应复用同一套后端 API。

推荐技术形态：

```text
Next.js 前端
-> FastAPI 后端
-> PostgreSQL 数据库
-> LLM Provider 抽象
```

## 5. 用户与能力画像

### 5.1 孩子端

孩子端要简单、友好、行动导向。能力画像只展示 3 个维度：

- 读懂力；
- 写具体力；
- 会修改力。

孩子不需要看到复杂能力拆解，也不需要看到过于精确的分数。界面应强调“这次哪里变强了”。

### 5.2 家长端

家长端要更专业、细致、可解释。能力画像保留 6 个维度：

- 理解；
- 概括；
- 表达；
- 观察；
- 结构；
- 修改。

家长报告应回答：

- 孩子最近练了什么；
- 哪些地方有具体进步；
- 当前薄弱点是什么；
- 下一步应该练什么；
- 作文修改前后有什么变化。

## 6. 核心用户流程

### 6.1 首次使用流程

```text
家长登录
-> 创建或选择孩子档案
-> 孩子完成极简诊断
-> 系统生成第一张粗能力画像
-> Dashboard 推荐今日任务
-> 孩子完成第一个句子或作文任务
-> 战斗结算记录成长
-> 家长生成阶段报告
```

极简诊断应像“小文星球入门小试炼”，而不是严肃考试。建议耗时 3 到 5 分钟，包含：

- 1 个句子升级题；
- 1 个 80 到 120 字小写作题，或 1 组选材追问题；
- 阅读能力可在孩子第一次完成阅读任务后再补充。

初始能力画像要明确是“第一张能力草图”，后续会随着训练数据逐步变准。

### 6.2 日常训练流程

默认训练时长为 10 到 15 分钟，同时保留 5 到 8 分钟轻练入口。

```text
孩子打开 Dashboard
-> 看到今日推荐任务
-> 选择主线任务或轻量任务
-> 完成训练
-> 收到 AI 反馈
-> 修改或确认收获
-> 进入战斗结算
-> 能力画像更新
-> 系统推荐下一步
```

### 6.3 家长查看流程

```text
家长登录
-> 选择孩子
-> 查看本阶段概览
-> 查看能力变化、最佳修改、当前薄弱点
-> 查看 AI 生成的周报或阶段报告
-> 必要时切换到其他模拟孩子档案
```

## 7. 孩子端 Dashboard

孩子端 Dashboard 是行动入口，不是静态资料页。

优先级：

1. 系统推荐的今日任务；
2. 地图入口；
3. AI 教练入口；
4. 能力、等级、最近进步。

### 7.1 今日任务

首页默认展示：

- 1 个主线任务：通常是作文任务，或从作文延伸出的句子升级任务；
- 1 个轻量任务：通常是 5 到 8 分钟句子工坊。

今日任务保证学习闭环继续向前走。

### 7.2 地图

地图提供自由探索感。MVP 地图包含：

- 句子工坊；
- 作文城堡；
- 阅读峡谷。

孩子可以自由选择地点，但系统推荐任务仍是主路径。

### 7.3 AI 教练

首页中的 AI 教练是学习导航员：

- 解释今日任务；
- 鼓励孩子开始；
- 提醒下一步练什么。

AI 教练不做开放式聊天，不回答“帮我写一篇作文”这类请求。进入具体任务后，它才变成任务陪练，负责追问、点评和修改建议。

### 7.4 成长反馈

孩子端展示：

- 读懂力、写具体力、会修改力；
- 等级和经验；
- 最近徽章或成就；
- 最近一次具体进步。

## 8. 训练模块

### 8.1 作文城堡

作文城堡是 MVP 的主线训练模块。

支持 3 种入口：

- 输入作文题目；
- 从题目灵感中选择；
- 粘贴已有初稿。

题目灵感由两部分组成：

- 内置题库：四年级常见主题，如“难忘的一件事”“我学会了___”“推荐一个好地方”；
- AI 兴趣生成：孩子选择兴趣或最近经历后，AI 给出 3 个题目灵感。

从题目开始时，流程为：

```text
选择或输入题目
-> AI 追问 3 到 5 个选材问题
-> AI 整理素材卡
-> AI 生成提纲框架
-> 孩子写初稿
-> AI 点评初稿
-> AI 识别 1 到 3 个问题怪物
-> AI 给出 1 到 3 个修改任务
-> 孩子提交二稿
-> AI 对比修改前后
-> 战斗结算
```

从已有初稿开始时，跳过选材追问和提纲框架，直接进入点评、修改任务、二稿对比。

提纲只能给框架，不给可照抄段落。素材卡只能整理孩子自己的回答，例如时间、地点、人物、动作、心情和细节。

作文反馈包含：

- 鼓励式点评卡：2 个具体优点；
- 1 到 3 个改进点；
- 1 到 3 个问题怪物；
- 1 到 3 处关键句批注；
- 1 到 3 个修改任务。

修改任务必须小而可执行，例如：

- 加一个动作描写；
- 加一句心理活动；
- 把一句空泛句写具体；
- 加一个过渡句；
- 让结尾感受更清楚。

### 8.2 句子工坊

句子工坊是高频轻练模块。

句子来源：

- 系统给句：默认入口；
- 从孩子作文中抽句；
- 孩子自己输入普通句。

训练类型：

- 加细节；
- 加动作或神态；
- 加心理；
- 加修辞。

系统每次只推荐一种训练重点。真实孩子第一阶段优先推荐：

- 加细节；
- 加动作或神态。

句子训练完成后，AI 反馈：

- 哪些地方变具体了；
- 下一步还可以怎么改；
- 对应能力如何变化；
- 获得什么经验、徽章或结算结果。

### 8.3 阅读峡谷

阅读峡谷在 MVP 中保持轻量，不做完整阅读产品。

职责：

- 更新孩子端读懂力；
- 更新家长端理解和概括维度；
- 给出一个阅读到写作的迁移技巧。

流程：

```text
选择内置文章
-> 阅读文章
-> 完成 3 到 5 道题
-> AI 给出温和反馈
-> 更新阅读相关能力
-> 获得一个写作迁移技巧
-> 战斗结算
```

写作迁移技巧示例：

- 写景时可以加入声音；
- 写人时可以用动作表现心情；
- 写事时可以选一个重要画面慢慢写。

## 9. 能力更新模型

后端内部存储 6 维能力：

- 理解；
- 概括；
- 表达；
- 观察；
- 结构；
- 修改。

孩子端映射为 3 维：

- 读懂力：理解 + 概括；
- 写具体力：表达 + 观察 + 部分结构；
- 会修改力：修改 + 二稿质量变化。

能力更新采用规则 + LLM 混合：

- 规则决定任务影响哪些能力、最大变化幅度、是否必须完成二稿；
- LLM 判断孩子是否真的加入了细节、动作、心理，或完成了有效修改；
- UI 弱化绝对分数，强调趋势和证据。

## 10. 游戏化系统

MVP 游戏化要轻量完整，不做复杂养成。

包含：

- 经验值；
- 等级；
- 徽章；
- 地图关卡；
- 问题怪物；
- 战斗结算。

不包含：

- 宠物养成；
- 商城；
- 虚拟货币经济；
- 复杂技能树；
- 排行榜。

问题怪物代表具体语文问题，例如：

- 空泛表达；
- 流水账叙述；
- 细节缺席；
- 结尾没力；
- 概括不清。

奖励必须映射真实学习行为，不能只奖励点击次数。

## 11. 家长周报与阶段报告

产品概念保留“周报”，MVP 同时支持基于当前数据随时生成“阶段报告”。

报告包含：

- 本阶段练习概况；
- 能力变化；
- 本阶段最佳修改；
- 当前 1 到 2 个薄弱点；
- 下一阶段建议。

报告语气要求：

- 专业；
- 温和；
- 具体；
- 不制造焦虑；
- 强调进步和下一步行动。

## 12. AI 系统设计

AI 调用由后端统一编排。任务类型包括：

- 题目灵感生成；
- 作文选材追问；
- 素材卡整理；
- 提纲框架生成；
- 作文点评；
- 二稿对比；
- 句子升级反馈；
- 阅读答案反馈；
- 周报或阶段报告生成；
- 代写请求识别。

所有关键 AI 输出必须使用结构化 JSON，并通过 schema 校验。校验失败时，后端应重试或返回保守兜底反馈。

### 12.1 反代写三层防线

1. Prompt 层：明确禁止完整可提交作文、标准范文、直接代写。
2. 产品层：不提供“帮我写全文”入口，只提供追问、素材卡、提纲、点评、修改任务。
3. 检测层：识别孩子的代写请求或 AI 过界输出，并转成陪练式引导。

示例引导：

```text
我不能替你写完整作文，但可以帮你想一想这件事里最值得写的画面。
```

## 13. 技术架构

推荐架构：

```text
Next.js 前端
-> FastAPI 后端
-> PostgreSQL 数据库
-> LLM Provider 抽象
```

前端负责：

- 浏览器和平板浏览器体验；
- 页面、交互和状态管理；
- 调用后端 API。

后端负责：

- 孩子数据；
- 训练记录；
- 作文版本；
- 能力画像；
- Prompt 和 LLM 编排；
- LLM 输出校验；
- 反代写逻辑；
- 报告生成。

### 13.1 核心数据对象

- `ParentUser`：简化家长账号；
- `StudentProfile`：孩子档案；
- `AbilityProfile`：能力画像；
- `Assessment`：极简诊断结果；
- `Essay`：作文任务；
- `EssayVersion`：作文初稿、二稿等版本；
- `SentenceTraining`：句子训练记录；
- `ReadingSession`：阅读训练记录；
- `GameEvent`：经验、等级、徽章、问题怪物和结算记录；
- `Report`：周报或阶段报告；
- `LLMCallLog`：LLM 调用日志。

`LLMCallLog` 应记录任务类型、输入摘要、输出结构、校验结果和错误信息，用于调试 AI 质量。

### 13.2 部署路径

MVP 不做重 DevOps，但保留生产路径：

- 后端可 Docker 化；
- 从第一版开始使用 PostgreSQL；
- 使用数据库迁移工具管理 schema；
- 使用环境变量管理 LLM key；
- 保留日志、错误记录和 LLM 调用记录；
- 前端和后端可独立部署；
- 后端未来可部署到云服务器或容器平台；
- 未来 App 可复用 FastAPI API。

## 14. 成功指标

### 14.1 产品行为指标

- 真实孩子完成极简诊断；
- 真实孩子一周至少完成 3 次训练；
- 真实孩子至少完成 1 次作文初稿到二稿闭环；
- 真实孩子至少完成 3 次句子升级；
- 真实孩子至少完成 1 次轻量阅读任务；
- 家长至少查看 1 份阶段报告。

### 14.2 学习质量指标

- 二稿相较初稿至少在一个维度上可见改善，例如细节更多、动作更具体、结构更清楚；
- 句子升级后能明显减少“很美”“很开心”“很好玩”这类空泛表达；
- 阅读训练能产生至少一个可迁移到作文的小技巧；
- 能力画像能随着训练记录变化，而不是静态展示。

### 14.3 AI 质量指标

- AI 不输出完整可提交作文；
- AI 每次反馈先给具体优点；
- 修改任务控制在 1 到 3 个；
- 孩子端语言适合小学生理解；
- 家长报告专业、冷静、不焦虑化；
- 结构化 AI 输出能被后端稳定解析。

### 14.4 体验指标

- 孩子能理解今日任务要做什么；
- 孩子能理解问题怪物代表哪类写作问题；
- 主线任务小步骤能在 10 到 15 分钟内完成；
- 轻量句子任务能在 5 到 8 分钟内完成；
- 家长能理解孩子哪里进步了、下一步该练什么。

## 15. MVP 验收标准

当系统能真实演示并保存以下闭环时，可以认为 MVP 第一版达标：

```text
家长登录
-> 选择真实孩子档案
-> 完成极简诊断
-> Dashboard 推荐今日任务
-> 孩子完成一次句子训练
-> 孩子完成一次作文点评和二稿修改
-> 系统更新能力画像和游戏事件
-> 家长生成阶段报告
-> 系统推荐下一轮任务
```

3 个模拟孩子应能展示不同画像：

- 表达空泛型；
- 作文结构薄弱型；
- 阅读概括薄弱型。

MVP 最终要回答 3 个问题：

1. 孩子是否愿意走完这个学习闭环？
2. AI 反馈是否像陪练，而不是代写或冷冰冰的批改器？
3. 家长是否能看到孩子正在变强的证据？
