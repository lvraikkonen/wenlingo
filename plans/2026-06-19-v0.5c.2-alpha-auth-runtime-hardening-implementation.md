# V0.5c.2 Alpha Auth Runtime Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove MVP demo runtime bypasses and add operator-visible `ParentSession` controls before broader external Alpha usage.

**Architecture:** Keep FastAPI as the auth/session authority and Next.js as a session-aware client. Add small session operation helpers used by Admin routes and an ops cleanup command; migrate tests to explicit authenticated fixtures before deleting the demo route and Web fallback. Preserve demo assets only as dev/test/archive material.

**Tech Stack:** FastAPI, SQLModel/SQLAlchemy, pytest, Next.js App Router, React, TypeScript, Vitest, Playwright, Railway ops commands.

## Scope Check

This plan covers two related surfaces: runtime demo removal and session operations. They should stay in one implementation plan because both protect the same Alpha auth boundary and share tests around `ParentSession`, family ownership, and no-demo fallback behavior.

Do not add:

- New AI learning tasks.
- Session count auto-limits.
- New scheduler or worker.
- Admin charts, filters, exports, or inactive-session UI.
- A full authenticated rewrite of the old MVP browser E2E.
- A production `DEMO_MODE_ENABLED` escape hatch.

## Required Implementation Order

Follow this order exactly:

1. Add authenticated API test fixtures while `/api/auth/demo-login` still exists.
2. Add session operation service helpers, cleanup command, and Admin session APIs.
3. Migrate tests away from demo login and direct runtime demo seed dependency.
4. Delete `/api/auth/demo-login`.

@dataclass(frozen=True)
class RevokeParentSessionResult:
    revoked: bool
    session_id: str


@dataclass(frozen=True)
class RevokeAllParentSessionsResult:
    revoked_session_count: int


@dataclass(frozen=True)
class ParentSessionCleanupResult:
    scanned_count: int
    eligible_count: int
    deleted_count: int
    reason_counts: dict[str, int]
    revoked_cutoff: datetime
    expired_cutoff: datetime


def active_parent_session_statement(account_id: str):
    now = utcnow()
    return select(ParentSession).where(
        ParentSession.account_id == account_id,
        ParentSession.revoked_at.is_(None),
        ParentSession.expires_at > now,
    )


def active_parent_sessions_for_account(db: Session, account_id: str) -> list[ParentSession]:
    return sorted(
        db.exec(active_parent_session_statement(account_id)).all(),
        key=lambda row: (row.last_seen_at, row.created_at, row.id),
        reverse=True,
    )


def revoke_parent_session_for_account(
    db: Session,
    account_id: str,
    session_id: str,
) -> RevokeParentSessionResult:
    parent_session = db.get(ParentSession, session_id)
    if parent_session is None or parent_session.account_id != account_id:
        raise LookupError("parent session not found")

    if parent_session.revoked_at is not None or _as_utc(parent_session.expires_at) <= utcnow():
        return RevokeParentSessionResult(revoked=False, session_id=parent_session.id)

    parent_session.revoked_at = utcnow()
    db.add(parent_session)
    return RevokeParentSessionResult(revoked=True, session_id=parent_session.id)


def revoke_active_parent_sessions_for_account(
    db: Session,
    account_id: str,
) -> RevokeAllParentSessionsResult:
    active_sessions = active_parent_sessions_for_account(db, account_id)
    now = utcnow()
    for parent_session in active_sessions:
        parent_session.revoked_at = now
        db.add(parent_session)
    return RevokeAllParentSessionsResult(revoked_session_count=len(active_sessions))


def cleanup_parent_sessions(
    *,
    db: Session,
    revoked_retention_days: int,
    expired_retention_days: int,
    execute: bool,
) -> ParentSessionCleanupResult:
    if revoked_retention_days < 0 or expired_retention_days < 0:
        raise ValueError("retention days must be zero or positive")

    now = utcnow()
    revoked_cutoff = now - timedelta(days=revoked_retention_days)
    expired_cutoff = now - timedelta(days=expired_retention_days)
    rows = db.exec(select(ParentSession)).all()
    eligible: list[tuple[ParentSession, str]] = []
    for parent_session in rows:
        if (
            parent_session.revoked_at is not None
            and _as_utc(parent_session.revoked_at) <= revoked_cutoff
        ):
            eligible.append((parent_session, "revoked"))
            continue
        if _as_utc(parent_session.expires_at) <= expired_cutoff:
            eligible.append((parent_session, "expired"))

    reason_counts = {
        reason: sum(1 for _, row_reason in eligible if row_reason == reason)
        for reason in ("expired", "revoked")
        if any(row_reason == reason for _, row_reason in eligible)
    }

    if execute:
        for parent_session, _ in eligible:
            db.delete(parent_session)
        db.commit()

    return ParentSessionCleanupResult(
        scanned_count=len(rows),
        eligible_count=len(eligible),
        deleted_count=len(eligible) if execute else 0,
        reason_counts=reason_counts,
        revoked_cutoff=revoked_cutoff,
        expired_cutoff=expired_cutoff,
    )
```

import argparse

from sqlmodel import Session

from app.db.session import engine
from app.services.parent_sessions import cleanup_parent_sessions


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(description="Clean expired and revoked parent sessions.")
    mode = parser.add_mutually_exclusive_group()
    mode.add_argument("--dry-run", action="store_true", help="Preview eligible rows without deleting.")
    mode.add_argument("--execute", action="store_true", help="Delete eligible session rows.")
    parser.add_argument("--revoked-retention-days", type=int, default=30)
    parser.add_argument("--expired-retention-days", type=int, default=30)
    return parser


def main(argv: list[str] | None = None) -> int:
    args = build_parser().parse_args(argv)
    if args.revoked_retention_days < 0 or args.expired_retention_days < 0:
        raise SystemExit("retention days must be zero or positive")

    execute = bool(args.execute)
    with Session(engine) as session:
        result = cleanup_parent_sessions(
            db=session,
            revoked_retention_days=args.revoked_retention_days,
            expired_retention_days=args.expired_retention_days,
            execute=execute,
        )

    mode = "execute" if execute else "dry-run"
    print(
        " ".join(
            [
                f"mode={mode}",
                f"scanned_count={result.scanned_count}",
                f"eligible_count={result.eligible_count}",
                f"deleted_count={result.deleted_count}",
                f"reason_counts={result.reason_counts}",
                f"revoked_cutoff={result.revoked_cutoff.isoformat()}",
                f"expired_cutoff={result.expired_cutoff.isoformat()}",
            ]
        )
    )
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

# MVP Demo Flow Archive

Date: 2026-06-19
Status: Archived in V0.5c.2

## What The MVP Demo Validated

The MVP demo flow validated that a family could enter WenLingo quickly, choose one
of four seeded children, complete a learning loop, and see parent-visible progress.
It was useful for proving the early Draft → AI feedback → Revision → Comparison
→ Encouragement loop before WenLingo had product-grade accounts.

## Original Runtime Shape

- Browser home page called `/api/auth/demo-login`.
- The API seeded `demo@wenlingo.local` with parent id `p1`.
- The API seeded children `s1`, `s2`, `s3`, and `s4`.
- The browser linked directly to child dashboards without requiring a real
  `ParentSession`.

## Why It Was Removed

By V0.5a, WenLingo had `ParentAccount`, `ParentSession`, Magic Code login, and
server-side sessions. By V0.5c.1, same-origin auth, auth failure UX, and
localStorage identity cleanup were stable enough for external Alpha. Keeping an
unauthenticated demo route in production/runtime after that point increased risk
and made login failures harder to diagnose.

## Alpha Replacement

External Alpha users now enter through `/alpha/start`, verify a Magic Code, create
or load a linked family, create children, and use session-aware product APIs.
