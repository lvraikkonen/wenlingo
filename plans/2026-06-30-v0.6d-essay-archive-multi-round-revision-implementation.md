# V0.6d Essay Archive + Multi-Round Revision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship V0.6d essay archive, right-side child drawer, parent restore, and linear multi-round revision with safe idempotency and retry recovery.

**Architecture:** Add round-aware essay versioning and revision attempts at the data layer, then build a focused archive service that all child, parent, and revision routes share. Keep Writing Castle as the primary writing surface: archive selection loads latest child-authored content and AI guidance into the existing essay page editor, while parent surfaces provide summary-first review and restore.

**Tech Stack:** FastAPI, SQLModel, Alembic, Pydantic v2, existing Prompt Registry/AI runner, Next.js App Router, React Testing Library/Vitest, Playwright.

## Hard Guards

1. V0.6d is the official version name. `V0.6c.1` appears only as historical context in the approved spec.
2. Hide and restore ship together. Do not expose child hide unless the parent list and restore path are implemented.
3. New `EssayVersion` writes must set non-null `round_index`.
4. Revision submit must check existing `EssayRevisionAttempt` by idempotency key before checking stale latest version.
5. Revision submit must reserve `essay_id + base_version_id + target_round_index` before LLM work.
6. Do not keep a database transaction open while calling the LLM. Commit the pending `EssayRevisionAttempt` reservation before LLM work; completion/failure updates happen in a second short transaction.
7. Round 3 and later never create another full essay XP settlement.
8. Archive recency for the child drawer is `last_version_submitted_at`, not hide/restore time.
9. Frontend continue actions use backend-derived `can_continue_revision`; `needs_revision` is only an educational recommendation signal.
10. Existing `essay_revision_comparison` remains the prompt key. Prompt and UI copy must be pairwise / round-neutral.
11. No archive or event payload includes full essay content except version/detail APIs that intentionally return child-authored drafts.
12. Parent and child archive detail/visibility routes are separate. Do not use frontend-supplied `actor_type` as an authorization or surface selector.
13. Use the existing V0.6c `topic_origin` runtime enum: `teacher_provided | ai_topic_idea | direct_draft`. Do not introduce a second archive-only topic-origin vocabulary.

```python
def get_version_label_for_round(round_index: int) -> str:
    if round_index < 1:
        raise ValueError("round_index must be positive")
    if round_index == 1:
        return "first_draft"
    if round_index == 2:
        return "revision"
    return f"revision_round_{round_index}"


def get_round_index(version: EssayVersion) -> int:
    if version.round_index is not None:
        return version.round_index
    if version.version_label == "first_draft":
        return 1
    if version.version_label == "revision":
        return 2
    if version.version_label.startswith("revision_round_"):
        return int(version.version_label.removeprefix("revision_round_"))
    raise ValueError(f"unknown essay version label: {version.version_label}")
```

- [ ] **Step 4: Implement attempt/idempotency order**

Implement route flow in this exact order:

1. Short transaction A: require essay and reject assessment-only essays.
2. Short transaction A: load same-key `EssayRevisionAttempt`.
3. Short transaction A: if completed, return existing `new_version_id` payload.
4. Short transaction A: if failed, return retry metadata.
5. Short transaction A: if pending and not expired, return 202.
6. Short transaction A: if pending is older than `REVISION_ATTEMPT_TIMEOUT_SECONDS`, mark it `comparison_failed` with `error_code = "attempt_timeout"` and commit before returning retry metadata.
7. Short transaction B: load latest round.
8. Short transaction B: compare `base_version_id` to latest; return 409 before LLM if stale.
9. Short transaction B: calculate `target_round_index`.
10. Short transaction B: create pending attempt with `submitted_content_hash`.
11. Short transaction B: commit the pending attempt / target-round reservation before LLM work.
12. If reservation commit conflicts, return 202 or 409 before LLM.
13. Transaction-free section: call `essay_revision_comparison()` without holding an open DB transaction.
14. Short transaction C: reload attempt and essay, create next `EssayVersion`, mark attempt completed, and clear `submitted_content` after `new_version_id` is durable.
15. Short transaction C: apply full settlement only for round 2.
16. Short transaction C: apply limited revision growth only for round 3 and 4 when content threshold passes.
17. Short transaction C: commit and return payload.

Do not keep a database transaction open while calling the LLM. The pending
`EssayRevisionAttempt` reservation must be committed before LLM work.
Completion/failure updates happen in a second short transaction.

Add `REVISION_ATTEMPT_TIMEOUT_SECONDS = 180` in `essay_archive.py` and a helper:

```python
def mark_stale_pending_attempts_failed(session: Session, *, now: datetime) -> int:
    cutoff = now - timedelta(seconds=REVISION_ATTEMPT_TIMEOUT_SECONDS)
    attempts = session.exec(
        select(EssayRevisionAttempt).where(
            EssayRevisionAttempt.status == "pending_comparison",
            EssayRevisionAttempt.updated_at < cutoff,
        )
    ).all()
    for attempt in attempts:
        attempt.status = "comparison_failed"
        attempt.error_code = "attempt_timeout"
        attempt.updated_at = now
        session.add(attempt)
    return len(attempts)
```
