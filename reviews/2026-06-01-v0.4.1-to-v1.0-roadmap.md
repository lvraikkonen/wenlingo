## Phase 1: V0.5 — 用户地基 + Alpha 扩展 (~3-4 周)

**主题**: 从"浏览器身份"升级为"持久账号"，为扩大 Alpha 做准备

### 为什么这是第一优先

当前 `wenlingo_alpha_parent_id` 存储在 `localStorage`。清除浏览器数据 = 丢失家庭。PRD §22.1 定义了用户系统，但一直未实现。这是所有后续功能的**硬前置依赖**——没有持久身份，就无法做通知、无法做成长记录、无法做付费、无法让用户换设备。

同时，当前 Alpha 的 3-5 个家庭反馈数据需要被系统化分析，为 V0.6 的产品决策提供依据。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|------|----------|--------|------|
| 1 | **最小账号系统** | §22.1, §6.1 | P0 | 手机号 + 短信验证码登录。不追求邮箱/微信 OAuth/密码等多种方式。一个能用的方式就够了。 |
| 2 | **Alpha 家庭迁移** | 运营 | P0 | 将现有 3-5 个 `localStorage` 家庭迁移到账号系统。提供迁移页面：输入邀请码 → 绑定手机号 → 数据关联。 |
| 3 | **Session/token 认证** | §23.1 | P0 | JWT or session cookie。替换当前"前端传 parent_id"的信任模式。保护所有 `/api/students/` 和 `/api/alpha/` 端点。 |
| 4 | **Alpha 数据看板 v2** | 运营 | P1 | 基于 P1-2 deferred item，修复 admin query。增加：按日期范围过滤、按 event type 过滤、导出 CSV。 |
| 5 | **Alpha 反馈分析** | 运营 | P1 | 手动分析当前 3-5 个家庭的数据：哪个模块使用最多？reaction 分布？二稿完成率？AI feedback 失败率？产出分析报告作为 V0.6 输入。 |
| 6 | **隐藏阅读峡谷入口** | §16 | P2 | 在 dashboard PlanetMap 中移除"阅读峡谷"链接，直到 V0.7 上线。死胡同链接伤害儿童体验。 |

### 不做

- 微信登录、邮箱登录、Apple ID 登录等（V1.0+）
- 密码找回流程（手机验证码已覆盖）
- 多设备同步（自动，token 机制自然支持）
- 用户设置/个人资料页（V0.7+）

### 验收标准

- [ ] 新 Alpha 家庭通过手机号注册并创建孩子
- [ ] 现有 Alpha 家庭成功迁移，不丢失历史数据
- [ ] 清除浏览器数据后可以通过手机号恢复
- [ ] API 端点验证：未登录请求返回 401
- [ ] 后端测试 60+，前端测试 80+
- [ ] Admin 数据看板支持日期和事件类型过滤

### 对 Alpha 家庭的影响

- **Breaking change**: 现有家庭需要完成一次性迁移（输入手机号绑定）
- **Positive**: 迁移后不再担心浏览器数据丢失
- **Risk**: 如果有家庭联系不上，需要手动通过 Railway DB 绑定

## Phase 2: V0.6 — 写作城堡深度升级 (~4-5 周)

**主题**: 从"AI 点评作文"升级为"AI 陪孩子构思作文"

### 为什么这是第二优先

Multi-perspective review 的结论：Pre-writing flow 是 WenLingo 最强的产品差异化能力。PRD §15.3-15.5 详细设计了选材追问和提纲生成的完整流程，但从未实现。当前作文训练从"空白文本框"开始——这对孩子是最难的时刻。

这个 Phase 也引入写作城堡的三种模式（PRD §6 写作类型并未在 PRD 中定义三种模式，但 brainstorm item 6 提出了 `课内同步作文` / `AI出题作文` / `随笔写` 的划分，这是合理的产品演进）。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|------|----------|--------|------|
| 1 | **审题小助手** | §15.3 | P0 | 孩子输入作文题目 → AI 拆解题意：写什么类型？重点是什么？容易忽略什么？1 分钟交互，不超过 3 轮。 |
| 2 | **选材问答** | §15.4 | P0 | AI 根据题目追问 3-5 个问题（什么时候？有谁？最难忘的画面？感受？）。每个问题一个输入框。孩子回答收集为素材卡片。 |
| 3 | **素材卡片** | §8.1 素材宝盒 | P0 | 选材问答的产出可视化为卡片。孩子可以拖拽排序、删除、添加新卡片。这是写作前的"素材桌"。 |
| 4 | **提纲生成** | §15.5 | P0 | AI 根据素材卡片生成提纲建议。结构：开头/中间一/中间二/结尾。孩子可以修改提纲文本。确认后进入写作。 |
| 5 | **写作城堡模式选择** | §15.2 | P1 | 进入作文城堡时提供三种模式入口：① 课内同步作文（输入老师布置的题目要求）② AI 出题作文（系统推荐题目）③ 随笔写（自由写作，轻量反馈） |
| 6 | **课内同步作文导入** | §15.2 | P1 | 支持粘贴/输入老师的作文题目和要求。AI 识别题目类型（写人/写事/写景等），匹配 PRD §15.2 的作文类型。 |
| 7 | **难度适配 v1** | §12.2 | P1 | 根据 `grade_label` 调整：AI 追问的复杂度、提纲建议的详细度、点评语言的难度。三年级用更短句子，六年级可以用更抽象的概念。 |

### 不做

- 手写识别 / OCR 导入题目（PRD §8.2）
- 语音输入
- AI 出题的完整题库（V0.6 只需 10-20 个推荐题目）
- 提纲模板的可视化编辑器（文本编辑即可）

### 验收标准

- [ ] 孩子可以从题目输入走到提纲确认，全程在 5 分钟内完成
- [ ] 选材问答产出至少 3 张素材卡片
- [ ] 提纲被孩子修改后，修改内容保留到写作阶段
- [ ] 三种城堡模式入口可见且可切换
- [ ] 课内同步作文可以输入老师题目要求
- [ ] 不同年级看到不同深度的追问和提纲
- [ ] 现有作文初稿→点评→二稿→对比流程不被破坏

### 数据观察目标

- 课前构思流程完成率（从题目到提纲确认）
- 有素材卡片 vs 无素材卡片的作文长度和质量差异
- 课内同步 vs AI 出题 vs 随笔写的使用分布
- 提纲修改率（孩子是否真的修改 AI 提纲）

## Phase 3: V0.7 — 句子工坊扩展 + 阅读峡谷 v1 + 游戏化升级 (~4-5 周)

**主题**: 补齐句子训练多样性、让阅读峡谷不再是死胡同、让游戏化从"数字变化"变成"世界感"

### 为什么这是第三优先

PRD §14 定义了 4 种句子训练类型，当前只实现了 1 种。PRD §16 设计了完整的阅读峡谷（10-20 篇文章、5 种题型、AI 反馈、写作迁移），当前是占位页。PRD §17 设计了怪物系统、徽章系统、称号系统，当前只有 XP + 等级数字。

这三个模块同时上线，是因为它们共同构成"每日训练习惯"的产品基础：句子工坊 = 短平快每日打卡，阅读峡谷 = 输入积累，游戏化 = 持续动力。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|------|----------|--------|------|
| 1 | **句子工坊：4 种训练类型** | §14.2 | P0 | 在现有"加细节"基础上增加：缩句训练、仿写句子、比喻/拟人训练。每种类型有独立的 UI 和 AI prompt。 |
| 2 | **句子工坊：每日 3 题** | brainstorm #9 | P0 | 进入句子工坊看到今日 3 道题。完成度可视化。来源：系统推荐 + 上次薄弱点。 |
| 3 | **句子工坊：闯关模式** | brainstorm #9 | P1 | 完成 3 题 → 解锁下一关。每关难度递增。关卡之间有简短结算。 |
| 4 | **阅读峡谷 v1** | §16 | P0 | 内置 10 篇短文（覆盖 PRD §16.2 的 6 种文章类型）。每篇 5 道题（对应 PRD §16.3 的 5 种题型）。AI 批改 + 反馈。 |
| 5 | **阅读→写作迁移** | §16.5 | P1 | 每篇阅读结束后，AI 给一个与文章写法相关的微写作任务（1-3 句话）。如"这篇文章用了时间顺序写景，请写 3 句话描写校园早晨"。 |
| 6 | **怪物系统可视化** | §17.3 | P1 | 在 AI 反馈中，每个被识别的问题显示为对应怪物的图标+名称。战斗结算中显示"击退 XX 怪 -70%"。 |
| 7 | **称号系统** | §17.4 | P1 | 根据等级和主要训练类型显示称号（PRD §17.4 的 6 个称号）。Dashboard 角色卡显示。 |
| 8 | **徽章系统** | §17.6, §22.11-12 | P2 | 实现 PRD 的 8 个徽章。在 GameEvent 中追踪进度。Dashboard "最近奖励"区域显示已解锁徽章。 |
| 9 | **Dashboard 视觉升级** | §25 | P1 | Planet Map 变成真正的插图地图（3 个可点击建筑）。角色卡显示称号+等级。今日任务显示奖励预览。 |

### 不做

- 完整技能树（PRD §8.2）
- 词语森林、素材湖泊等更多地图形（V1.0+）
- 金币/商城/宠物养成系统
- 排行榜/社区分享
- 阅读文章难度自动分级算法（V0.7 手动标注年级）

### 验收标准

- [ ] 句子工坊支持 4 种训练类型，每种有独立 AI prompt
- [ ] 阅读峡谷 10 篇文章可用，AI 批改 5 种题型
- [ ] 阅读→写作迁移产出可用的微写作任务
- [ ] 怪物在 AI 反馈中可见（图标+名称）
- [ ] Dashboard 显示称号和最近徽章
- [ ] Planet Map 是插图地图而非文字链接列表

### 数据观察目标

- 4 种句子训练类型的使用分布
- 每日 3 题完成率 vs 旧版单次训练完成率
- 阅读峡谷文章完成率和题目正确率
- 阅读→写作迁移任务的完成率
- 徽章解锁进度分布

## Phase 4: V0.8 — 家长端升级 + 成长记录 + 数据闭环 (~3-4 周)

**主题**: 让家长真正看到孩子的成长轨迹，让数据飞轮完整运转

### 为什么这是第四优先

PRD §18 定义了完整的家长周报（本周概况 + 能力变化 + 最佳修改案例 + 薄弱点 + 下周建议）。当前 parent summary 是静态快照。PRD §9 定义了孩子端的"成长记录"页面（能力变化 + 徽章进度 + 训练历史 + 最佳句子），当前不存在。

这个 Phase 也让数据飞轮（PRD §26）从"单向反馈"变成"闭环推荐"：系统根据历史数据生成下周任务建议，而非每次随机推荐。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|------|----------|--------|------|
| 1 | **家长周报** | §18 | P0 | 自动汇总本周数据 → 生成周报。包含：练习概况（次数/类型）、能力变化（delta + 趋势方向）、最佳修改案例（初稿→二稿对比）、1-2 个薄弱点、下周建议。 |
| 2 | **孩子成长记录页** | §9 成长记录 | P0 | `/children/:id/growth` 页面。能力变化折线图（6 维度）、训练历史时间线（最近 20 条）、已解锁徽章墙、最佳句子收藏。 |
| 3 | **数据飞轮：智能推荐 v1** | §26 | P1 | 基于能力画像的薄弱点 + 最近训练历史，生成下周推荐任务。替换当前的固定推荐逻辑。推荐至少包含：1 个薄弱点专项 + 1 个保持项 + 1 个挑战项。 |
| 4 | **家长通知** | 运营 | P2 | 孩子完成作文训练后，家长收到 App 内通知（下次打开时可见）。不做 Push/短信。 |
| 5 | **家长端写作样本展示** | §18.3 | P1 | 周报和家长 summary 中可以展示孩子写作的 before/after 片段（经过隐私处理，仅展示改写对比，不展示完整作文）。 |

### 不做

- Push 通知 / 短信通知 / 邮件通知
- 家长之间的孩子比较/排名
- 可导出的 PDF 报告（V1.0+）
- 老师端

### 验收标准

- [ ] 家长周报自动生成（每周一），包含全部 5 个模块
- [ ] 孩子成长记录页展示 6 维度能力趋势
- [ ] 智能推荐产出与孩子薄弱点匹配的任务
- [ ] 家长端可以看到至少 1 个 before/after 写作对比
- [ ] 家长周报查看率 ≥ 60%

## Phase 5: V0.9 → V1.0 — 毕业与发布 (~3-4 周)

**主题**: Alpha 毕业，产品化收尾，V1.0 正式发布

### V1.0 的定义

V1.0 不是一个功能爆炸的版本，而是一个**完整的、可信赖的、可以开始收费的最小产品**。

V1.0 = PRD V0.1 所有 P0 功能 + Alpha 验证过的改进 + 可以支持 50+ 付费家庭的基础设施。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|------|----------|--------|------|
| 1 | **付费体系** | 新增 | P0 | 简单的订阅制：免费试用 2 周 → 月度/季度订阅。接入微信支付。不做复杂定价实验。 |
| 2 | **发布说明页** | brainstorm #4 | P1 | `/updates` 页面。展示版本更新记录。静态 Markdown 渲染。 |
| 3 | **基础设施加固** | 运营 | P0 | 数据库备份策略、API rate limiting、LLM 成本追踪、错误监控 (Sentry or similar)、E2E 测试关键路径 |
| 4 | **Alpha 毕业迁移** | 运营 | P0 | 现有 Alpha 家庭自动进入付费试用期。试用结束后引导付费。提供 Alpha 参与者特别定价。 |
| 5 | **内容补充** | §16.2 | P1 | 阅读文章从 10 篇扩展到 20-30 篇。AI 推荐作文题目从 10-20 个扩展到 30-50 个。 |
| 6 | **句子工坊扩展** | brainstorm #9 | P2 | 在 V0.7 的 4 种类型基础上增加：动作描写句、心理描写句、病句修改。共 7 种类型。 |
| 7 | **V1.0 质量审计** | 运营 | P0 | 完整的 manual QA pass、Safari/iPad 兼容测试、中文内容审查、AI 反馈质量抽样评分。 |

### 不做

- 移动 App
- 老师端 / 班级管理
- 大规模阅读库（50+ 篇）
- 自适应测评算法
- OCR 手写识别
- 语音输入

### V1.0 验收标准

- [ ] 新用户可以：注册 → 创建孩子 → 完成诊断 → 句子训练 → 作文构思+写作+修改 → 阅读训练 → 查看成长记录
- [ ] 家长可以：查看周报 → 看到 before/after 对比 → 看到能力趋势 → 收到通知
- [ ] 付费流程：试用 → 到期提醒 → 付费 → 持续使用
- [ ] 后端测试 100+，前端测试 120+，E2E 测试 5+ 关键路径
- [ ] 数据库每日自动备份
- [ ] LLM 失败率 < 5%，平均响应 < 15s
- [ ] 50 个家庭并发使用时无明显性能下降

## 关键风险与缓解

| 风险 | 影响阶段 | 缓解措施 |
|------|----------|---------|
| Alpha 家庭在迁移中流失 (V0.5) | V0.5 | 提前 1 周通知；提供 1-on-1 迁移帮助；保留旧 localStorage 作为 fallback |
| 课前构思流程太长，孩子放弃 | V0.6 | 选题材问答可跳过；提纲可跳过；每步有明确进度指示；Alpha 观察数据决定是否简化 |
| LLM 成本随功能增长失控 | V0.6-V0.7 | V0.5 加入 cost tracking；每个新 LLM call 评估必要性和替代方案 |
| 阅读内容质量不足 | V0.7 | 手动精选 10 篇经典短文作为种子；AI 批改用固定 prompt 模板保证稳定性 |
| 付费转化率低 | V1.0 | Alpha 阶段持续收集家长价值感知数据；V0.8 周报是付费转化的关键触点 |
| 功能蔓延导致 V1.0 延迟 | 全阶段 | 每个 Phase 有明确的"不做"列表；V1.0 定义为"最小完整产品"而非"功能完整产品" |

- 词语森林 / 素材湖泊 / 修辞秘境 / 表达神殿 等更多地图形
- PDF 报告导出
- 多家长协作（父母双方管理同一孩子）
- 国际化 / 英文版
- 复杂定价实验（先用单一订阅方案验证）
