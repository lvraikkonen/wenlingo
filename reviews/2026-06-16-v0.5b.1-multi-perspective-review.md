## 2. 学习设计师视角

### V0.5b.1 对学习体验的影响

V0.5b.1 没有新增学习功能（这是正确的——hardening 版本不应引入学习设计变更）。但两个改动间接改善了学习体验：

1. **Loading 状态改善** — "正在出题..." → "AI 教练正在思考..." → "快好了！" 的三阶段文案让孩子知道系统在工作，减少了 "卡住了" 的焦虑感。这对低年级孩子尤其重要。
2. **Assessment path 保持可见** (`60b1c54`) — Dashboard 上 "入门小试炼" 作为推荐保持可见，避免孩子迷失 "从哪里开始"。

### 学习设计缺口（与 6/12 评审一致，无变化）

| 缺口 | 6/12 状态 | 6/16 状态 | 计划 |
|---|---|---|---|
| 3 种 challenge type 覆盖面有限 | 存在 | 不变 | V0.7 扩展到 6 种 |
| 没有难度递进（fallback 不区分年级） | 存在 | 不变 | V0.7 按年级分段 fallback |
| Challenge 选择是轮转而非自适应 | 存在 | 不变 | V0.8 引入能力画像推荐 |
| 缺少 "跳过此题" | 存在 | 不变 | V0.6+ 考虑 |

### 学习设计师建议（与 6/12 一致）

V0.5b.1 没有改变学习设计方面的任何判断。原 6/12 的建议全部保留：

1. V0.7 增加 2-3 种新 challenge type（缩句、仿写优先）
2. Fallback 模板按年级分段（至少区分 3-4 年级和 5-6 年级）
3. V0.8 之前在 challenge 选择上保持轮转（简单可靠）
4. 考虑添加 "跳过此题" 选项

**新增观察：** QA checklist 显示 daily limit 触发后 child 看到正确的 rest message（"今天的句子挑战已经完成很多啦，休息一下，明天继续闯关！"）。这个文案是好的学习设计——不惩罚、不压迫、鼓励明天再来。建议 V0.7 给 rest message 也按年级分段（低年级更鼓励、高年级可以说 "今天练得不错"）。

## 3. 孩子用户体验视角

### V0.5b.1 的孩子 UX 改善

6/12 评审中孩子 UX 视角指出的问题及 V0.5b.1 的解决情况：

| 6/12 问题 | V0.5b.1 解决 | 评估 |
|---|---|---|
| Loading 只有一行文字，没有过渡动画 | 3 阶段 progress text | ✅ 改善显著——从 "一行文字" 升级为 "有节奏的等待" |
| 提交后等待 AI 反馈只有 spinner | Loading 文案现在覆盖生成和反馈两个阶段 | ✅ 反馈阶段也有 "AI 教练正在看你的句子" |
| 没有进度条、没有趣味性等待动画 | 尚未解决 | ⚠️ 文字改善是好的第一步，但缺乏视觉趣味 |
| 反馈展示中 `encouragement` 和 `highlight` 视觉区分不够 | 未改变 | ⚠️ 仍然是文字区分 |
| `example_upgrade` 容易被理解为 "标准答案" | `example_upgrade` 加了 "这是一个参考" 标签 | ✅ 明确标注为参考例句 |
| 战斗结算只有数字，没有打怪动画 | 未改变 | ⚠️ 延后到 V0.7 |
| 阅读峡谷是死胡同链接 | 标记为 "即将开放" | ✅ 不再是死胡同——孩子看到 "即将开放" 知道这里以后可以玩 |

### 孩子 UX 当前状态

```text
进入体验: 🟢 友好——"句子工坊" + "把一句话升级成小画面"
等待体验: 🟡 改善但仍然朴素——3 阶段文字 vs 理想中的动画
挑战展示: 🟢 清晰——年级 + 能力目标 + 源句 + 引导
反馈展示: 🟡 example_upgrade 标注改善了一个关键问题，但视觉区分仍不足
结算体验: 🟡 只有 XP 数字，缺少庆祝感
```

### 孩子 UX 建议（更新）

1. **V0.5c**：给反馈区块增加简单的视觉层级——`encouragement` 用温暖色背景、`highlight` 用勾号图标、`suggestion` 用灯泡图标。不需要动画，纯 CSS 就能显著改善。
2. **V0.6**：写作城堡的 loading 状态从一开始就用 AIInteractionState 状态机，不要重复句子工坊 "先文字后动画" 的老路。
3. **V0.7**：完整打怪动画 + 战斗结算。
4. **当前不做**：loading 动画（需要设计资源，V0.5c 不应该被 UX polish 阻塞）。

## 4. 家长用户体验视角

### V0.5b.1 对家长体验的影响

V0.5b.1 没有直接改动家长端功能。但以下间接改善影响家长体验：

1. **孩子端 polish 提升** → 孩子更愿意使用 → 家长看到更多练习数据
2. **阅读峡谷不再是死胡同** → 家长不会担心 "这个按钮怎么点不了"
3. **Daily limit 验证通过** → 家长不用担心孩子过度使用

### 家长 UX 当前状态（与 6/12 一致）

```text
登录流程: 🟢 流畅——Magic Code 邮件 + Resend
孩子列表: 🟢 可以看到孩子、进入 dashboard
家长摘要: 🟡 仍然是轻量级计数——本周完成 N 次、主要练习类型
能力趋势: ❌ 没有——看不到进步方向
before/after: ❌ 没有——这是 PRD §18.3 的核心价值
下一步建议: ❌ 没有——家长不知道该让孩子多练什么
```

### 家长 UX 建议（与 6/12 一致，无变化）

1. **V0.5c**：parent summary 至少增加 "本周练习类型分布" 饼图或条形图
2. **V0.8**：完整家长周报（PRD §18 的 5 模块）
3. **当前阶段**：parent summary 保持克制是正确的——过度承诺但交付不足比循序渐进更伤害信任

**新增观察：** 随着 Alpha 家庭从 3-5 扩大到 5-10，家长之间的口碑传播会成为新的用户获取渠道。建议在 V0.5c 给 parent summary 加一个 minimally 的改善（至少显示 "孩子本周完成了 X 次练习，主要练习了 Y" 的计数），让家长在和朋友聊到时有一个 "你看，这是我孩子的练习情况" 的可分享感。

2. **`admin_alpha.py` 拆分** — V0.5c 建议做。当前文件 ~570 行，包含 overview、invites、accounts、ai_usage 四个逻辑分组。
3. **前端 AIInteractionState** — V0.5c 在 sentence workshop 试点，V0.6 推广。
4. **localStorage identity cleanup Step 3** — V0.5c 完全移除 `alphaParent.ts` 读写函数。

### 工程经理建议（更新）

1. **V0.5c 在实现 ModelRouter 的同时拆分 `run_validated_llm_task()`**——这两个改动有天然的代码交集（都在 `ai_tasks.py`），一起做比分开做效率高。
2. **V0.5c 第一件事：建立 ModelRouter 的 config schema 和测试**——在写任何路由逻辑之前先定义好配置格式。YAML/TOML/JSON 都可以，但必须能回答 "哪个 task 用哪个 model"。
3. **V0.5c 增加 E2E 测试**——sentence challenge 完整流程 + Magic Code 登录流程。V0.5b.1 的 manual QA 虽然完整，但每次手动跑 smoke checklist 不可持续。E2E 测试应该成为 V0.5c 的 acceptance criteria 之一。
4. **V0.5c 后运行 `git diff --stat v0.5b.1..HEAD`** 确认 scope 没有膨胀。

### 是否需要 V0.5b.1 Post-Implementation Review？

**不需要单独的 V0.5b.1 post-implementation review。**

原因：
- V0.5b.1 是 1-2 天的 hardening 版本，不是功能版本。变更范围小（8 个 commit），每个变更的意图和效果都清晰可追溯。
- V0.5b 的 post-implementation review（6/12）已经覆盖了 V0.5b.1 需要解决的所有问题。V0.5b.1 是那份 review 的 action items 的执行。
- 本多角度评审已经覆盖了 post-implementation review 会问的问题（design goals 完成度、hotfix 分析、架构评审）。
- 创建一份 500 行的 post-implementation review 来检查 8 个 commit 是 over-engineering——违反 Review Principle #7。

**替代方案：这份多角度评审 + V0.5b.1 QA checklist 的 "Go" decision = 足够的 V0.5b.1 闭合记录。**
