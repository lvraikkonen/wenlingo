# WenLingo V0.5b Post-Implementation Review

Date: 2026-06-12
Reviewer: gstack (Claude Code)
Status: Comprehensive product + architecture + QA review

## Executive Summary

V0.5b **substantially achieves its design goals**. The AI sentence training thin slice is functional end-to-end: AI generates challenges, children complete them, feedback appears, XP settles, and Admin sees aggregate usage. The Prompt Registry, LLMCallLog metadata, daily limits, Resend email, and Dev Echo guard are all implemented.

However, the review identifies **four categories of gap** that should be addressed before expanding Alpha:

1. **LLM cost observability** — logging works, but zero defaults create a misleading "free" display
2. **AI interaction latency** — batch-only requests with text loading states feel slow
3. **Model routing** — no task→model mapping exists; all tasks use one model
4. **Configuration hygiene** — `LLM_DAILY_LIMIT_ENABLED` was missed in Dev, blocking daily limit verification during initial QA (now resolved)

**Readiness assessment:**

```text
功能完成度（Functional completeness）: 85%
产品稳定度（Product stability）:     75–80%
扩大 Alpha readiness:             Conditional
```

V0.5b can be feature-closed, but **V0.5b.1 must not be skipped**. The gaps in cost display, loading UX, and config hygiene are individually small but collectively they make the product feel unfinished for real families.

**Recommendation: V0.5b.1 Hardening** (1–2 days) → then V0.5c AI Platform Foundation (1–2 weeks).

#### 认证架构深度评估：localStorage `wenlingo_alpha_parent_id` 问题

当前 WenLingo 有两层身份机制：

**Layer 1（正确的认证层）— `wenlingo_parent_session` cookie:**

```text
httponly cookie → server-side token hash lookup → ParentSession table → ParentAccount
```

| 属性 | 值 | 评估 |
|---|---|---|
| httponly | true | JS 不可读，免疫 XSS 窃取 |
| secure | true (Railway HTTPS) | 仅 HTTPS 传输 |
| samesite | lax | CSRF 风险降低（配合 Origin/Referer guard + JSON-only 形成完整防线） |
| 服务端存储 | ParentSession.token_hash (SHA256+pepper) | 可单独撤销（set revoked_at） |
| 过期控制 | expires_at + revoked_at | 即时失效，无需 token blacklist |

这个层已经是 **product-grade** 的。它不是 JWT，但**比 JWT 更适合 WenLingo**：server-side session 可以即时撤销，JWT 则需要短期过期 + refresh token + token blacklist 才能达到同样效果。对于家长可控、孩子使用的教育产品，即时撤销能力比无状态扩展更重要。

**Layer 2（需要清理的遗留层）— `wenlingo_alpha_parent_id` in localStorage:**

```typescript
// apps/web/src/lib/alphaParent.ts
export const ALPHA_PARENT_STORAGE_KEY = "wenlingo_alpha_parent_id";
```

这是 pre-auth 时代遗留的客户端路由提示，**不是认证机制**。问题：

1. **信息冗余** — `/api/auth/session` 已经返回 `parent_id`，不需要 localStorage 再存
2. **会过期** — account 禁用后 localStorage 值不会自动更新
3. **会冲突** — 与真实 session 不一致时用户困惑（hotfix QA-2026-06-12-02 的根因）
4. **非 httponly** — localStorage 对页面 JS 可读（虽不是 secret，但暴露内部 ID）
5. **跨浏览器不共享** — 不是真正的多设备同步

**建议：3-step 渐进清理，不要粗暴删除**

```text
Step 1（V0.5b.1）— 立即停止新增写入：
  所有新登录/注册/绑定流程不再写 wenlingo_alpha_parent_id。
  登录成功后只做：GET /api/auth/session → parent_id → React state → route。

Step 2（V0.5b.1）— 读取逻辑降级为 migration-only：
  getStoredAlphaParentId() 只在 legacy bind/migration flow 中使用。
  /parent/children、/parent/.../summary、/children/{id}/dashboard、
  /children/{id}/sentence 等页面不再从 localStorage 拿 parent_id。

Step 3（V0.5c）— 正式移除：
  现有 Alpha 家庭都完成账号绑定后：
  - alphaParent.ts 标记 deprecated
  - 删除大部分读写函数
  - 仅保留 clearLegacyAlphaParentId() 或完全删除 localStorage identity
```

**结论：不要换 JWT，不要重做 auth。当前 server-side session 方案是正确的。需要做的是清理前端 localStorage 遗留身份提示。**

1. **Add `pricing_configured` indicator in Admin** — If `LLM_INPUT_COST_PER_1K_TOKENS` and `LLM_OUTPUT_COST_PER_1K_TOKENS` are both 0, display "未配置价格" instead of `$0.0000`. Never show a misleading zero cost that looks like "free".

## 五、下一阶段建议

### Option Analysis

| Option | Scope | When appropriate |
|---|---|---|
| V0.5b.1 Hardening | Loading UX, cost display, config hygiene | Remaining polish after hotfix |
| V0.5c AI Platform | ModelRouter, task→model, provider fallback, per-task timeout | After hardening |
| V0.5c AI UX | SSE, streaming, AIInteractionState | After platform foundation |
| V0.6 Writing Castle | Pre-writing flow | After AI platform is multi-model ready |

### Recommendation: V0.5b.1 → V0.5c AI Platform Foundation

**Rationale:**

1. **V0.5b.1 first (1-2 days)**: The hotfix is already deployed and verified. Remaining work is lightweight: loading UX improvements, cost display fix, localStorage identity cleanup (Step 1+2), and the React hydration error fix.

2. **V0.5c AI Platform Foundation next (1-2 weeks)**: Before building more AI-powered features (Writing Castle), the AI platform needs multi-model capability. Without ModelRouter, all tasks share one model — which means either overpaying for simple tasks or underpowering complex ones. This is the right architectural sequencing.

3. **V0.6 Writing Castle after V0.5c**: Only after the AI platform can route tasks to appropriate models should we build essay-heavy features that need different model capabilities.

**Do NOT do V0.5c AI Interaction UX (streaming) before platform foundation** — streaming is a UX optimization; model routing is an architectural necessity. Streaming built on a single-model platform would need rework when multi-model arrives.

### V0.5b.1 Scope (Recommended)

1. **Loading state improvement** — 3-stage progress text + animated/playful loading component
2. **Cost display fix** — If `LLM_INPUT_COST_PER_1K_TOKENS` and `LLM_OUTPUT_COST_PER_1K_TOKENS` are both 0, Admin displays "未配置价格" instead of `$0.0000`; add `pricing_configured` indicator
3. **Config hygiene** — Ensure `LLM_DAILY_LIMIT_ENABLED=true` in Dev; verify daily limit end-to-end
4. **React hydration error fix** — QA-2026-06-11-01
5. **localStorage identity cleanup Step 1+2** — Stop writing `wenlingo_alpha_parent_id` on new logins; all pages use `/api/auth/session` for `parent_id`; `getStoredAlphaParentId()` restricted to legacy migration flow only
6. **Update `docs/env-vars.md`** — Add LLM cost config, daily limit enabled flag, and common Dev misses

### V0.5c AI Platform Foundation Scope (Recommended)

1. **ModelRouter** — task→model mapping with configurable policy
2. **Task-level model config** — sentence challenge → cheap model, essay feedback → strong model
