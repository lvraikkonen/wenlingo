## 问题 1：P2 是否应该升级为 P0/P1？

### 原始 P2 描述

> "固定叙事模板（起因/经过/结果/感受）不支持非叙事类作文类型。当前 V0.6a 实现方向符合预期，但应作为产品限制在后续规划中跟进。"

### 基于真实教材数据的重新评估

7 篇课内同步作文的适配情况：

| 适配程度 | 数量 | 题目 |
|---|---|---|
| 很适配 | 1 | 我学会了____ |
| 部分适配 | 1 | 故事新编（可映射但缺关键步骤） |
| 勉强适配 | 1 | 游____（勉强可用，缺游记特有引导） |
| 不太适配 | 2 | 我的乐园、我的动物朋友 |
| 完全不适配 | 2 | 我的奇思妙想、我的"自画像" |

**适配率：1/7（14%）或乐观估计 3/7（43%，算上"部分适配"+"勉强适配"）**

### 结论：P2 → P1

**P1 理由**：

1. **覆盖范围**：当前模板只能服务 14-43% 的课内作文。如果 WenLingo 的 writing castle classroom path 定位是"帮助孩子完成课内同步作文"，那么 57-86% 的课内题目没有得到充分支持。这不是 edge case，是核心场景缺失。

2. **产品定位影响**：V0.6a 的 classroom path 标签是"课内同步作文"。当家长/孩子输入一个课内题目（如"我的奇思妙想"），系统给出的提纲模板完全不匹配题目类型——这会削弱"课内同步"这个定位的可信度。

3. **skip 是安全网，不是解决方案**：V0.6a 允许跳过提纲直接写初稿，所以目前不被阻塞。但 skip 解决的是"孩子不想用提纲"的问题，不是"提纲模板不对"的问题。如果一个孩子想用提纲但模板不对，skip 不是正确答案。

**为什么不是 P0**：

- V0.6a 的"审题三卡"和"选材三问"仍然通用——它们不依赖于叙事模板，对所有题目类型都有帮助。
- skip 路径保证了核心闭环不被阻塞。
- V0.6a 本身是"课前构思 v1"——先验证审题+选材的价值，再在下个版本做题型适配，这个节奏是合理的。
- P1 bug（提纲保存失败）仍然是更高优先级的阻塞问题。

**建议**：P2 升级为 P1，但不是 V0.6a hotfix。应作为 V0.6b 的 P0 需求——在 V0.6b 启动前完成题型适配设计。

## 问题 2：当前 material questions 是否过度假设"回忆真实事件"？

### 分析

当前 V0.6a 的选材三问：

```text
Q1: 你想写哪一件真实发生的事？（事件回忆）
Q2: 这件事里哪个画面最清楚？（细节回忆）
Q3: 当时你有什么心情或收获？（感受回忆）
```

这三个问题全部假设"孩子在回忆一件真实发生的事"。对于：
- 《我的乐园》：适用（回忆去过的地方）
- 《我学会了____》：适用（回忆学东西的经历）
- 《我的奇思妙想》：不适用——孩子不是在"回忆"，而是在"创造"
- 《故事新编》：不适用——孩子不是在"回忆自己的事"，而是在"改编已有故事"
- 《我的动物朋友》：部分适用——如果养过动物适用，如果没养过需要"创设情境"

### "AI 不编造"原则升级

当前 V0.6a spec 的原则：

> Anything that can become作文内容 must come from child input or explicit child confirmation. AI may organize, label, and ask; it may not create the lived content.

这个原则的核心是"AI 不替孩子决定内容"，但表述集中在"lived content"（真实经历）。升级后的表述：

> **AI 不得替孩子决定作文内容。所有可进入作文的内容，必须来自以下四个来源之一：**
> 1. **孩子的真实经历**（如《我学会了骑车》）
> 2. **孩子自己想象出来的设定**（如《我的奇思妙想》中的发明）
> 3. **老师题目中给出的要求**（如《故事新编》中"选一个老故事改编"）
> 4. **孩子明确确认过的选择**（如《我的动物朋友》中创设的情境）
>
> AI 可以追问、整理、建议框架；AI 不得替孩子选择事件、发明设定、创作情节、或填写未经确认的内容。

### 对 material questions 的影响

V0.6b 的选材问题需要按 content_source 分类：

| 内容来源 | 问题方向 | 示例 |
|---|---|---|
| 真实经历 | 帮助回忆 | "你去过哪些地方，哪一个让你最开心？" |
| 想象创造 | 帮助选择 | "你想发明什么东西？它能做什么神奇的事？" |
| 题目要求 | 帮助理解 | "老故事里哪些人物和设定你想保留？" |
| 创设情境 | 帮助想象 | "假如你要请邻居帮忙照顾你的动物，你会怎么介绍它？" |

**结论**：是的，当前 material questions 过度假设"回忆真实事件"。需要扩展，但不是 V0.6a hotfix——当前 skip 路径可以绕过。这应该是 V0.6b design 的一部分。

## 问题 3：是否需要在 V0.6b 引入 topic_type / scaffold_template 概念？

### 回答：是，且应该在 V0.6b spec 的第一部分。

理由：

1. **7 篇课内作文 → 7 种不同的提纲结构**。如果不用模板化方法，就只能让 AI 自由发挥——但这与"AI 输出结构化、可校验"的原则冲突。

2. **模板化 ≠ 过度工程**。四年级下册的 7 种题目类型覆盖了小学中高年级的主要作文类型。做好这 7 种，就覆盖了 80%+ 的课内作文场景。这不是"每种题目一个模板"的无限枚举，而是"每种作文类型一个模板"的有限集合。

3. **模板化有利于 AI 质量**。当前 V0.6a 让 AI 自由生成提纲，虽然 AI 遵循了 prompt 约束，但提纲质量的一致性无法保证。pre-defined template → AI 在模板框架内填充，质量更可控。

4. **模板化不影响 skip 路径**。即使引入 topic_type，孩子仍然可以跳过提纲直接写初稿。模板是"有比没有好"的脚手架，不是必选路径。

### 具体建议

`topic_type` 枚举（第一版 8 种）：

```python
class TopicType(str, Enum):
    LEARNED_SKILL = "learned_skill"
    MY_PARADISE = "my_paradise"
    INVENTION_IDEA = "invention_idea"
    TRAVEL_WRITING = "travel_writing"
    SELF_PORTRAIT = "self_portrait"
    STORY_REWRITE = "story_rewrite"
    ANIMAL_FRIEND = "animal_friend"
    GENERIC_NARRATIVE = "generic_narrative"  # 兜底
```

每个 `topic_type` 绑定一个 `ScaffoldTemplate`：

```python
class ScaffoldTemplate:
    topic_type: TopicType
    # 审题三卡的关键词提示（如游记强调"顺序"，写人强调"特点+事例"）
    topic_analysis_hints: dict
    # 选材问题的引导方向（回忆/想象/理解/创设）
    question_direction: Literal["recall", "imagine", "understand", "create_scenario"]
    # 素材卡槽位定义
    material_card_slots: list[MaterialCardSlotDef]
    # 提纲段落定义
    outline_sections: list[OutlineSectionDef]
    # 是否适用当前 V0.6a 通用模板
    falls_back_to_generic: bool = False
```

这不需要在 V0.6b 一次性做完所有 8 种。建议分两批：
- **V0.6b**: learned_skill（优化当前）、my_paradise、invention_idea、self_portrait、generic_narrative（兜底）
- **V0.6c**: travel_writing、story_rewrite、animal_friend

## 问题 4：素材卡是否应该从固定 3 槽改为 template-specific？

### 回答：是。这直接来自题型分类数据。

当前固定 3 槽：
```text
事件 | 细节 | 心情收获
```

按题目需要的素材卡类型：

| 题目 | 需要的素材卡 | 当前 3 槽覆盖 |
|---|---|---|
| 我的乐园 | 地点样子 / 在这里做什么 / 最快乐的时刻 / 为什么是乐园 | 勉强（"细节"可以做样子，"事件"可以做做什么） |
| 我的奇思妙想 | 样子 / 功能 / 用处 / 为什么想发明 | ❌ 完全不对——不需要"事件"，需要"功能""用处" |
| 游____ | 游览路线 / 重点景物 / 细节描写 / 游览感受 | ⚠️ 缺"游览路线"和"重点景物选择" |
| 我的"自画像" | 外貌 / 性格 / 爱好特长 / 最能体现特点的事例 | ❌ 不对——需要"性格"+"事例"配对，不是事件流水 |
| 故事新编 | 原故事基础 / 保留设定 / 改变情节 / 新结局 / 新寓意 | ❌ 不对——核心是"保留 vs 改变"，不是事件叙述 |
| 我的动物朋友 | 情境 / 外形 / 习性 / 故事或感情 | ⚠️ 部分可映射但缺"情境" |
| 我学会了____ | 学什么 / 困难 / 关键画面 / 学会后的心情 | ✅ 当前模板最适配的题目 |

**结论**：固定 3 槽只能覆盖 1-3/7 篇。template-specific 素材卡是 P1 需求。

素材卡的实现建议：
- 每个 `ScaffoldTemplate` 定义 3-5 个 slot
- slot 有 `category`（显示标签）和 `hint`（引导语，如"写一句就可以"）
- 空 slot 的 placeholder 行为保留（不编造内容）
- 孩子仍可删除不需要的卡

## 问题 5：V0.6b 原计划（AI 出题作文）是否应该让位于题型适配？

### 原 V0.6b 计划（来自 spec §19 V0.6b Deferrals）：

> - Full AI topic作文 path.
> - Full free-writing path with distinct scaffolding.
> - Topic-type-specific outline templates.
> - Strong grade-level adaptation beyond current grade_label context.
> - Rich parent weekly report integration.
> - Topic bank with 10-20 recommendations.

### 重新排序建议

基于真实教材数据的分析，建议 V0.6b 优先级重排：

**V0.6b 应该做的（P0-P1）**：

| 优先级 | 交付项 | 理由 |
|---|---|---|
| P0 | Topic-type-specific outline templates（题型适配 v1） | 当前覆盖 14%，刚需 |
| P0 | Template-specific material card slots | 当前 3 槽覆盖 1-3/7 篇 |
| P0 | Content-source-aware material questions | 当前问题全部假设"回忆真实事件" |
| P1 | Updated "AI 不编造" principle → "AI 不替孩子决定内容" | 为想象类作文打开空间 |
| P1 | topic_type detection（从题目文本自动识别题型）或 manual selection | 减少家长/孩子的认知负担 |
| P1 | 5 种模板（learned_skill、my_paradise、invention_idea、self_portrait、generic） | 覆盖 7 篇中的 5 篇 |

**V0.6c 应该做的（从 V0.6b 移出）**：

| 交付项 | 原计划 | 新计划 | 理由 |
|---|---|---|---|
| AI 出题作文 | V0.6b P0 | V0.6c P0 | 课内同步作文的题型适配优先级更高 |
| 题目推荐库（10-20 题） | V0.6b | V0.6c | 需要 AI 出题作文先上线 |
| 剩余 2-3 种模板（travel、story_rewrite、animal_friend） | — | V0.6c P1 | 分批交付 |
| Grade-level adaptation | V0.6b | V0.6c P2 | 先做题型适配，再做难度适配 |

**为什么题型适配应该优先于 AI 出题**：

1. **课内同步作文是 classroom path 的核心承诺**。如果"课内同步"只覆盖 14% 的题目，这个 path 的产品价值大打折扣。先让 classroom path 真正覆盖 80%+ 的课内题目，再扩展 AI 出题这个新入口。
2. **题型适配的 ROI 更高**：家长已经知道课内作文题目是什么（老师布置的），不需要 AI 出题。AI 出题解决的是"不知道写什么"的问题——这是另一个产品场景。
3. **题型适配为 AI 出题铺路**：一旦有了 topic_type 系统，AI 出题时可以根据题型生成更匹配的题目灵感。

### 建议的 V0.6b 新范围

```text
V0.6b: 课内同步作文题型适配 v1
├── P0: topic_type + scaffold_template 设计
├── P0: 5 种模板（覆盖 5/7 课内题目）
├── P0: Template-specific 素材卡 slot
├── P0: Content-source-aware 选材问题
├── P1: "AI 不替孩子决定内容"原则升级
├── P1: topic_type 自动识别或手动选择
├── P1: Progress SSE（prewriting 进度流） + latency instrumentation
├── P2: 提纲确认/编辑保存 bug fix（如 V0.6a 未修）
├── P2: Token Streaming for essay_feedback / revision_comparison（V0.6c 或 V0.7）
└── 保持: 已有闭环回归绿色
```

## 补充：AI 延迟与 Streaming 策略

_此节基于 QA P3/P4 发现 + ChatGPT 分析 + 产品判断_

### 延迟问题的本质

V0.6a 的 AI 延迟不是"单次调用太慢"，而是"等待点太多"：

```text
审题 → 等 AI (1)
选材问题 → 等 AI (2)
素材卡 → 等 AI (3)
提纲 → 等 AI (4)
初稿反馈 → 等 AI (5)
二稿对比 → 等 AI (6)
```

这 6 次等待，每次 3-15 秒，累计可达 30-90 秒。4 步 prewriting 占其中 4 次。

### 关键区分：Progress SSE vs Token Streaming

| | Progress SSE | Token Streaming |
|---|---|---|
| 推送内容 | 任务状态（started/validating/completed） | LLM 输出逐字/逐段 |
| 适用任务 | Prewriting JSON tasks | Essay feedback / revision comparison |
| 风险 | 低—不展示未验证内容 | 高—半截 JSON 未通过 validation |
| 用户价值 | 让等待"有进度感" | 让长内容"边生成边看" |

### 不同任务的 Streaming 价值

| 任务 | 输出特点 | Streaming 价值 | 建议 |
|---|---|---|---|
| 审题三卡 | 短 JSON | 低 | Progress SSE |
| 选材三问 | 很短 JSON | 很低 | Progress SSE |
| 素材卡生成 | 中短 JSON，需 source 校验 | 低-中 | Progress SSE，不流半成品 |
| 提纲生成 | 中短 JSON，需 source 校验 | 低-中 | Progress SSE，不流半成品 |
| 作文初稿反馈 | 长内容、多个反馈块 | **高** | 首批 Token Streaming |
| 二稿对比 | 长内容、结构化反馈 | **高** | 第二批 Token Streaming |

### Prewriting 不适合 Token Streaming 的原因

1. 素材卡和提纲涉及"可能进入作文的内容"
2. 半截 JSON 未通过 Pydantic validation + source reference check
3. 可能包含 AI 编造的人物、地点、动作
4. Validation fail 后要不要撤回孩子已看到的内容？
5. Fallback 发生时，前面 stream 的内容算不算用户可见输出？

### 建议路线

```text
V0.6a.1:
  修复 P1 提纲保存 bug

V0.6b.0（spike）:
  1. Latency instrumentation: 记录各 task 的 p50/p90/p95
  2. 判断最大瓶颈是"题型不适配"还是"等待太慢"

V0.6b.1:
  1. 题型适配 v1（P0）
  2. Staged loading 文案优化（短期方案，不改架构）
  3. Progress SSE spike（prewriting 任务状态推送）

V0.6c:
  1. essay_feedback Token Streaming
  2. LLMCallLog streaming 字段设计 + daily limit 规则

V0.7:
  1. revision_comparison Token Streaming
  2. sentence_feedback Token Streaming
```

### LLMCallLog Streaming 最小设计

```text
streaming_enabled: bool
stream_started_at / first_content_at / stream_finished_at
client_disconnected_at
final_status (success / fallback_success / partial_failed)
visible_output_started: bool
partial_output_discarded: bool
usage_available: bool
input_tokens / output_tokens / estimated_cost
```

Daily limit 规则（5 种场景）需在实现 streaming 前由产品确认。

### 与题型适配的关系

题型适配（问题 1-5）和 AI 延迟（P3/P4）是 V0.6b 的两条并行主线：

- **题型适配**解决"脚手架对不对"的问题——直接影响学习质量
- **延迟优化**解决"等待难不难受"的问题——直接影响使用体验

两者不冲突。建议 V0.6b 同时推进：题型适配是 P0 功能，Progress SSE 是 P1 体验优化。Token Streaming 延后到 V0.6c。

## "AI 不编造"原则升级

### 原始原则（V0.6a spec §5）

> Anything that can become作文内容 must come from child input or explicit child confirmation. AI may organize, label, and ask; it may not create the lived content.

### 升级后原则

> **AI 不得替孩子决定作文内容。**
>
> 所有可进入作文的内容，必须来自以下四个来源：
> 1. **孩子真实经历** — 孩子回忆并确认的事件、细节、感受（如《我学会了骑车》）
> 2. **孩子自己想象出来的设定** — 孩子主动创造的内容（如《我的奇思妙想》中发明的东西、功能和用处）
> 3. **老师题目中给出的要求** — 题目自带的内容约束（如《故事新编》中"选一个老故事"）
> 4. **孩子明确确认过的选择** — 系统提供选项或框架，孩子确认或修改的内容（如《我的动物朋友》中创设的情境）
>
> AI 的行为边界：
> - ✅ 可以追问（"你想发明的东西长什么样？"）
> - ✅ 可以整理（把孩子说的内容整理成卡片）
> - ✅ 可以建议框架（"写人可以先写外貌，再写性格"）
> - ✅ 可以指出空缺（"你还没说这个东西能帮人做什么"）
> - ❌ 不可以替孩子选择事件、发明设定、创作情节
> - ❌ 不可以填写未经孩子确认的内容到素材卡或提纲
> - ❌ 不可以把空缺的卡槽自动填满
> - ❌ 不可以因为"不是真实经历"而拒绝想象类作文的内容
>
> **关键变化**：从 "AI 不编造孩子的真实经历" → "AI 不替孩子决定作文内容"。
> 这个变化的核心是：想象类和情境创设类作文的内容来源不是"回忆"，而是"创造和选择"。
> AI 同样不能替孩子创造或选择——但 AI 必须为孩子的创造和选择提供空间。

### 对实现的影响

1. **合约不变**：`source_answer_ids`、`source_card_ids` 的引用链仍然有效。想象类作文的 source 来自"孩子输入的想象内容"而非"孩子回忆的真实事件"——但对系统来说，都是来自 `material_answers` 的文本。
2. **Fallback 不变**：空槽位仍然是 placeholder，不编造内容。
3. **Prompt 需要更新**：从 "Do not invent people, events, dialogue, feelings, or lessons" 升级为 "Do not decide content for the child. Only organize and suggest structure from child-provided or child-confirmed material, whether from real experience or imagination."
4. **选材问题需要区分方向**：回忆型问题 vs 想象型问题 vs 理解型问题。
