## Blockers

### B1 — Assessment essays leak into child + parent archive after migration ✅ RESOLVED 2026-07-02

> **Status: RESOLVED.** Fixed at the query layer by Codex and verified by gstack.
> See **Resolution** at the end of this entry.

**Severity:** P2 (UX correctness; not data-corrupting)

**Root cause (two parts):**

1. The migration backfills `essay.last_version_submitted_at` for *any* essay
   that has a version, including entry-assessment essays. Assessment essays
   are created at `apps/api/app/services/assessment.py:122` with a `first_draft`
   version and `status = "assessment_completed"`
   (`ASSESSMENT_ESSAY_STATUS`). The backfill at
   `apps/api/app/db/migrations/versions/20260630_v06d_essay_archive_revision_attempts.py:85-99`
   runs unconditionally on essay type.
2. The archive list queries filter only on `hidden_by == ""` and
   `last_version_submitted_at IS NOT NULL`
   (`apps/api/app/api/routes/essay_archive.py:79-88`, `110-117`). There is no
   assessment-status filter, and `derive_archive_status`
   (`apps/api/app/services/essay_archive.py:100`) has no assessment branch.
   Only `can_continue_revision` checks assessment status.

**Inconsistency that proves it is a bug, not intent:** runtime-created
assessment essays never set `last_version_submitted_at`
(`assessment.py` does not set it), so they stay out of the archive. Pre-existing
assessment essays get the column backfilled by the migration and leak in. Same
essay type, different visibility depending on when it was created.

**User impact:** a pre-existing student sees their entry-assessment writing in
the 写作记录 archive drawer as `status="needs_revision"` / "建议继续修改" with
`can_continue_revision=false`. Clicking it hits
`page.tsx:361` and shows "这篇作文现在还不能继续修改。". Same leak in the parent
archive and parent summary. Confusing, non-actionable item.

**No test guards it:** `rg assessment` against
`tests/test_essay_archive_api.py` and `tests/test_essay_archive_services.py`
returns nothing.

**Minimal fix** — `apps/api/app/api/routes/essay_archive.py`, exclude
assessment-status essays from both list queries:

```python
from app.services.essay_archive import ASSESSMENT_STATUSES
# ...
.where(
    Essay.student_id == student.id,
    Essay.hidden_by == "",            # parent path drops this when include_hidden
    _submitted_filter(),
    ~Essay.status.startswith("assessment_"),
)
```

Apply to both `child_essay_archive` (line 79) and `parent_essay_archive`
(line 110). A query-level filter is the correct fix because runtime-created
assessment essays already have NULL `last_version_submitted_at`, so this makes
backfilled and new rows consistent without touching the migration.

**Regression test to add** — `tests/test_essay_archive_api.py`: an assessment
essay with `last_version_submitted_at` set must not appear in the child archive
list, and must not appear in the parent archive list.

#### Resolution (2026-07-02)

Fixed by Codex as a minimal query-layer change, exactly as specified.

- `apps/api/app/api/routes/essay_archive.py`: added
  `~Essay.status.startswith("assessment_")` to both `child_essay_archive`
  (line 84) and `parent_essay_archive` (line 113, applied before the
  `include_hidden` branch). 6 lines of route code.
- `apps/api/tests/test_essay_archive_api.py`: added
  `test_archive_lists_exclude_assessment_essays_even_when_backfilled`. Creates
  a regular submitted essay plus an `assessment_completed` essay with a newer
  `last_version_submitted_at` (reproducing the migration backfill), and asserts
  the assessment essay is absent from the child list, the parent list, and the
  parent list with `include_hidden=true`.
- Migration untouched. `derive_archive_status` untouched. No idempotency code
  touched.

**Verification (gstack):**

1. Diff scope confirmed: only `essay_archive.py` (+6) and the test (+44); no
   migration, no service change.
2. Test reproduces the backfill: `_add_essay_with_versions` sets
   `last_version_submitted_at` (line 49) and the test passes
   `status="assessment_completed"` (line 170), so the assessment essay is
   genuinely in the backfilled state and only the new filter excludes it.
3. Acceptance suites green with the fix:
   `test_essay_archive_api.py` + `test_essay_archive_services.py` +
   `test_alpha_api.py` → **53 passed**.
4. Test confirmed to bite: stashing the route fix only (keeping the test) makes
   the new test **fail** — `At index 0 diff: 'assessment-backfilled' !=
   'regular-submitted'` (the assessment essay leaks to position 0 because its
   timestamp is newer). Restoring the fix → pass.

Note: the fix is still **uncommitted** in the working tree at the time of this
update; it must be committed before `/ship`.

## Informational (not blockers, tracked separately)

- **F4 (deferred):** post-LLM completion logic is duplicated ~85 lines each in
  submit (`essays.py:633-730`) and retry (`essays.py:844-925`) and has already
  drifted — retry omits the `essay_revision_feedback_completed` event and
  hardcodes `completed_task_count: 0`. Extract a shared
  `_complete_revision_attempt` helper in a later version. Do not block V0.6d.
- **F5 (deferred):** three event types are whitelisted but never emitted —
  `essay_multi_round_revision_submitted`, `essay_revision_attempt_retried`,
  `essay_revision_comparison_failed`. Dead telemetry config until wired. The
  four visibility events (`drawer_opened`, `item_selected`, `hidden_by_child`,
  `restored_by_parent`) are emitted. Also: the global sweeper
  `mark_stale_pending_attempts_failed` scans all essays on every submit
  (`essays.py:520`); acceptable at current volume, scope to the current essay
  later.
- **Minor UX:** the pending-`comparison` response is surfaced via
  `setError(result.message)` (`page.tsx:305`), so the saving copy may render as
  red error text. Not a data issue; consider a dedicated "saving" state in a
  later pass.
