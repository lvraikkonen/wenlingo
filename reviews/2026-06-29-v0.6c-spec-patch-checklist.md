## Context / why

V0.6c = 4 new scaffold families (`place_scenery / animal_object_observation /
practical_writing / story_adaptation`) + AI-topic thin slice (`writing_topic_idea_generation`).
Both reviews agree the direction and scope split are healthy. The blocker to "spec freeze"
is not scope creep — it is **underspecified contracts**: places where Codex would have to
invent behavior, risking semantic drift caught only at QA. This checklist closes those gaps.

## Verdict

**Concept: PASS (both). Spec freeze: NOT YET.** Apply the patch set below, then enter
implementation plan / TDD. The two reviews are **highly complementary** — Review B goes
deeper on per-family contracts; Review A uniquely catches a version-gate regression that
would silently disable Review B's own source-policy fix.

## The one refinement to Review B

Review B #2 says "V0.6b ScaffoldTemplate defines `material_questions`" and asks to add
static per-family question lists. **That is imprecise.** Verified in code: the V0.6b
template dict holds only `display_name_*, material_slots, outline_sections, source_policy`.
`material_questions` is an **AI task** (`prompts/writing_castle.py:43`) that derives
questions from `payload.scaffold.material_slots` ("Ask about the first three material_slots",
line 55-56), with **topic_type-specific prompt clauses** (e.g. person_portrait → first
person at line 58-62; expository → no external facts at line 31-36). Deterministic
fallback is `fallback_material_questions(scaffold)` (`writing_castle_ai.py:212`).

So the real gap is **not a missing template field** — it is that the 4 new families need
**`material_questions` (and `material_card_generation`) prompt clauses per topic_type**,
plus the slots/sections those prompts anchor to. Adding a static `material_questions`
field to templates would invent a structure V0.6b doesn't have. Frame the patch that way.

## Consolidated spec-patch checklist (for Codex)

### P0 — must close before implementation planning

1. **`schema_version` stays `v0.6b.1`; only `scaffold_template_version` gets the `.v0.6c`
   suffix.** (Review A P0-1 — **protects P0-3 below**.) `schema_version` gates source-ref
   validation (`ai_tasks.py:344`) and 6+ resume/normalize/accept checks
   (`writing_castle_state.py:153/155/167/168/313`, `writing_castle.py:149/269/413/414`,
   `alpha.py:490/500/501/585/586`). Bumping it disables `_validate_v06b_material_card_source_refs`
   for all V0.6c essays and breaks in-flight V0.6b resume. Decouple the suffix at
   `writing_castle_scaffold.py:283`; existing 4 families keep `.v0.6b.1`.

2. **Add complete `outline_sections` for all 4 new families.** (Review B #1 — real gap both
   reviews' specs miss.) The `outline_generation` prompt anchors sections to
   `payload.scaffold.outline_sections[*].id` (`writing_castle.py:110-112`) — without them
   Codex invents section ids and the prompt has no anchor. Use Review B's proposed section
   sets as the starting draft; each section needs `id/heading/label/content_kind`.

3. **Slot-level source policy for `practical_writing` and `story_adaptation`** (Review B #3,
   merging Review A's content_kind note). `topic_requirement` may carry format/audience/
   original-basis hints but must NOT carry child-specific content. Concretely:
   `practical_writing.main_message/specific_details` and
   `story_adaptation.new_event/new_ending/new_meaning` require `child_confirmed` /
   `real_experience` / `observation` / `imagined_setting`. This is enforced by the existing
   source-ref validators (`ai_tasks.py:306-348`) — which is exactly why P0-1 must hold.

4. **Unsupported-detector migration** (Review A P0-2 ≡ Review B #4). Remove the
   `practical_writing` (`写信/书信/我想对您说/倡议书`) and `story_adaptation`
   (`故事新编/续写`) rules from `UNSUPPORTED_RULES` (`writing_castle_scaffold.py:42-48`);
   keep `story_summary`, `reading_response_recommendation`, `central_idea_reflection`.
   Add negative tests: `detect("写信")`, `detect("故事新编")`, `detect("续写故事")` → `None`;
   `detect("缩写")`, `detect("推荐一本书")`, `detect("围绕中心意思写")` still flagged.

5. **`topic_origin` as a distinct field; do NOT overload `selection_source`.** (Review B #5,
   verified real.) `selection_source` (`ai_suggested/manual/fallback`) already renders in
   parent summary as "选择方式" (`summary/page.tsx:230-235`). AI-topic is a different
   provenance signal. Add `topic_origin: "teacher_provided" | "ai_topic_idea" | "direct_draft"`
   (+ optional `selected_topic_idea` block). Raise **minimum** parent-visible origin
   ("题目来源：AI 出题灵感，孩子选择" + "AI 未生成正文") to **P0**; keep copy polish P1.
   (Resolves the Product-Goal-vs-§9 tension Review B flags.)

6. **Executable AI-idea validation heuristics** (Review B #6). Augment the spec's semantic
   rejections with structural guards: exactly 3 ideas; title ≤30 CJK / ≤60 chars; no
   newlines; no completed-story patterns (`我那天…最后…`, `我明白了…`); title must be
   assignment-shaped not story-shaped. Append `NO_GHOSTWRITE` (`writing_castle.py:9-12`)
   to the new prompt — existing pattern.

7. **AI-topic prompt + per-family question/card clauses.** (Refined Review B #2.) The
   `material_questions` prompt needs topic_type clauses for new families, especially:
   `story_adaptation` → elicit original basis from child, never fill from common knowledge;
   `practical_writing` → format-aware. Same lever as the existing person_portrait/expository
   clauses (`writing_castle.py:31-36, 58-62`).

### P1 — should clarify before/during implementation

8. **`practical_writing`: make `diary/letter/proposal` true variants, not aliases.**
   (Review B per-family risk — highest-risk family.) Format differs structurally; one
   default template yields "格式不像". `heartfelt_letter` (我想对您说) can alias `letter`.

9. **`animal_object_observation`: give `observation_diary` a variant outline** emphasizing
   time/sequence/change/discovery, so it isn't swallowed by the generic introduce-template.
   (Review B.)

10. **`story_adaptation` ghostwrite guard in spec text:** AI may ask/confirm the original
    basis; must not fill missing original-story detail from common knowledge or decide the
    new event/ending before child confirmation. (Review B — second-highest risk.)

11. **`place_scenery`: allow `topic_requirement` for subject/assignment constraints**
    (推荐一个好地方 / 游____) but not for specific scenes/feelings. (Review B.)

12. **AI-topic API contract** (Review B #5): name the generate-ideas endpoint, the
    select-and-create-essay endpoint, confirm **no Essay before selection**, and that the
    selected idea attaches an **immutable** scaffold snapshot. Add `writing_topic_idea_generation`
    `TaskConfig` (real fields: `primary/fallback_timeout_seconds`, `max_total_latency_seconds`,
    `daily_limit`, `allowed_prompt_keys`, `default_prompt_key` — **no** `retry_count`;
    Review A P1-2).

13. **Mode shell is 2-mode today** (`WritingCastleMode = "classroom" | "direct"`; "AI 出题
    作文 · 稍后开放" is a disabled label). AI-topic is net-new UI incl. interest input
    (interest exists nowhere in the app); confirm interest is transient (Essay created only
    on selection; `interest_input_present` boolean suffices). (Review A P1-3.)

14. **`content_kind` per new slot** (Review A P1-1): drives source validation; specify at
    least for `practical_writing` format slots and `animal_object_observation` factual slots.
