## 版本履行总结：我们实际做了什么 vs 旧路线图的预期

旧路线图（2026-06-01）规划 V0.5 是"手机号 + 短信验证码登录"的单一大版本。实际执行中，V0.5 被拆分为三个子版本：

| 版本 | 实际交付 | 与旧路线图的差异 |
|---|---|---|
| V0.5a | ParentAccount、ParentSession、Magic Code 登录、Alpha 邀请管理、Resend/Dev Echo guard | 登录方式是 Magic Code 邮件而非短信验证码——这个决策是正确的（邮件比短信更可靠、更便宜、更适合 Alpha） |
| V0.5a.1/.2 | Dev hardening、QQ Mail SMTP 支持、QA 闭合 | 旧路线图未预期的 hardening 阶段 |
| V0.5b | Prompt Registry、LLMCallLog 元数据、Daily limit、AI 句子挑战 thin slice（3 种类型）、Admin AI usage | 旧路线图未预期的 AI 基础设施版本——句子挑战 thin slice 是 V0.5b 最大的新增价值 |

**关键变化：实际进度比旧路线图多了一个 AI 基础设施 + 句子训练 thin slice，但登录方案从 SMS 变为 Magic Code 邮件。**

这个变化对后续路线图的影响：
- ✅ AI 基础设施已经部分就绪（Prompt Registry、LLMCallLog、daily limits），V0.5c 不需要从零开始
- ✅ 用户体系已经是 product-grade 的 server-side session，不需要重构
- ⚠️ 但 ModelRouter 还没有，所有 AI 任务共享单一模型——这成为 V0.5c 的核心任务
- ⚠️ 句子挑战只有 3 种类型（vs PRD 的 4 种），V0.7 需要补齐

## Phase 4: V0.5c — AI 平台基础（预计 1-2 周）

**主题**: 建立多模型能力，让 AI 平台可以按任务选择最合适的模型

### 为什么这是 V0.6 之前必须做的

当前所有 AI 任务共用一个模型（`LLM_MODEL`）。这导致：
- 句子挑战生成（简单、短输出）和作文反馈（复杂、长输出）用同一个模型
- 要么为简单任务多付钱，要么用便宜模型导致作文反馈质量下降
- 没有 provider fallback，单一 provider 故障 = 所有 AI 功能不可用

V0.6 的 Writing Castle 会引入 4 种新的 AI 任务（审题分析、选材追问、提纲生成、素材卡片分析），每种对模型的 latency/cost/quality 需求不同。没有 ModelRouter 就直接上 V0.6，会累积技术债务。

### 交付清单

| # | 交付 | 优先级 | 说明 |
|---|---|---|---|
| 1 | **ModelRouter** | P0 | task → model mapping 配置层。支持 `sentence_challenge_generation → cheap_model`、`essay_feedback → strong_model` 等映射 |
| 2 | **Task-level model config** | P0 | 每个 task_name 可独立配置 model、timeout、retry |
| 3 | **Provider fallback** | P0 | 主 provider 失败时自动切换到备用 provider |
| 4 | **Per-task timeout/retry** | P0 | 挑战生成 10s timeout，作文反馈 30s timeout，2 次重试 |
| 5 | **Cost registry** | P1 | model-level pricing config，替代 hardcoded 0.0 |
| 6 | **Admin model usage dashboard** | P1 | 按 model 拆分 cost 视图 |
| 7 | **Prompt registry cleanup** | P1 | 迁移 `material_questions`、`outline_generation`；移除 `LEGACY_DEFAULT_PROMPT_VERSION` |
| 8 | **localStorage identity cleanup Step 3** | P2 | 完全移除 `alphaParent.ts` 读写函数 |
| 9 | **`run_validated_llm_task()` 拆分** | P1 | Daily limit check 和 cost/logging 提取为独立 middleware |
| 10 | **admin_alpha 路由拆分** | P2 | 拆分为 overview、invites、accounts、ai_usage 子模块 |
| 11 | **AIInteractionState** | P1 | 前端引入 `idle → generating → validating → fallback → completed → failed` 状态机，sentence workshop 试点 |
| 12 | **E2E 测试** | P1 | 至少 2 个 Playwright/Cypress 测试：sentence challenge 完整流程 + Magic Code 登录流程 |

### 不做
- Streaming / SSE（V0.6+）
- 新 AI 任务类型（属 V0.6）
- 前端框架升级

### 验收标准
- [ ] 不同 task_name 可以使用不同模型（配置验证）
- [ ] Provider 故障时自动 fallback 到备用 provider
- [ ] Admin 可以看到 per-model cost breakdown
- [ ] Prompt Registry 中无遗留 `LEGACY_RESPONSE_CONTRACTS`
- [ ] `alphaParent.ts` 完全移除（或仅保留 `clearLegacyAlphaParentId()`）
- [ ] 2 个 E2E 测试通过
- [ ] 所有已有后端测试继续通过

### 对 Alpha 家庭的影响
- 无 breaking change
- AI 响应速度可能改善（小任务用更快的模型）
- Cost 显示变为可观测（从 "barely observable" 升级为 "cost controllable"）

## Phase 5: V0.6 — 写作城堡完整课前构思（预计 3-4 周）

**主题**: 从"AI 点评作文"升级为"AI 陪孩子从头构思一篇作文"

### 为什么这是 V0.5c 之后的第一优先级

PRD §15.3-15.5 的课前构思流程是 WenLingo 最强的产品差异化能力。当前作文训练从"空白文本框"开始——这对孩子是最难的时刻。课前构思解决了"不知道写什么"的核心痛点。

V0.6 也是 Writing Castle 三种模式的首次完整呈现。

### 交付清单

| # | 功能 | 对应 PRD | 优先级 | 说明 |
|---|---|---|---|---|
| 1 | **审题小助手** | §15.3 | P0 | 孩子输入作文题目 → AI 拆解题意。1 分钟交互，≤3 轮 |
| 2 | **选材问答** | §15.4 | P0 | AI 追问 3-5 个问题 → 孩子回答 → 收集为素材卡片 |
| 3 | **素材卡片** | §8.1 | P0 | 选材问答产出可视化卡片，可排序/删除/添加 |
| 4 | **提纲生成** | §15.5 | P0 | AI 根据素材卡片生成提纲 → 孩子可修改 → 确认后进入写作 |
| 5 | **三种城堡模式** | §15.2 | P0 | ① 课内同步作文 ② AI 出题作文 ③ 随笔写 |
| 6 | **课内作文导入** | §15.2 | P1 | 粘贴老师题目要求 → AI 识别题目类型 |
| 7 | **难度适配 v1** | §12.2 | P1 | 按 grade_label 调整追问深度和提纲详细度 |
| 8 | **已有作文流程保护** | §15.6-15.9 | P0 | 初稿→点评→二稿→对比流程不被破坏 |

### 不做
- OCR 手写识别
- 语音输入
- AI 出题的完整题库（V0.6 只需 10-20 个推荐题目）
- 提纲模板的可视化编辑器

### 验收标准
- [ ] 孩子从题目输入到提纲确认全程 ≤5 分钟
- [ ] 选材问答产出 ≥3 张素材卡片
- [ ] 孩子修改提纲后，修改内容保留到写作阶段
- [ ] 三种城堡模式入口可见且可切换
- [ ] 课内同步作文可以输入/粘贴老师题目要求
- [ ] 不同年级看到不同深度的追问和建议
- [ ] 现有作文 feedback→revision→compare 流程不被破坏

### 数据观察目标
- 课前构思流程完成率（题目→提纲确认）
- 有素材卡片 vs 无素材卡片的作文质量差异
- 三种模式使用分布
- 提纲修改率

## Phase 8: V0.9 → V1.0 — 毕业与发布（预计 3-4 周）

**主题**: Alpha 毕业，产品化收尾，V1.0 正式发布

### V1.0 的定义

V1.0 = PRD V0.1 所有 P0 功能 + Alpha 验证过的改进 + 可以支持 50+ 付费家庭的基础设施。

**不是**功能完整产品，而是**最小完整产品**：一个孩子可以持续使用、家长可以看到价值、系统可以稳定运行的产品。

### 交付清单

|---|---|---|---|
| 1 | **付费体系** | P0 | 免费试用 2 周 → 月度/季度订阅。微信支付。不做复杂定价实验 |
| 2 | **基础设施加固** | P0 | DB 自动备份、API rate limiting、错误监控（Sentry）、LLM 失败率 <5% |
| 3 | **Alpha 毕业迁移** | P0 | 现有家庭自动进入试用期 → 付费引导。Alpha 参与者特别定价 |
| 4 | **内容补充** | P1 | 阅读文章 10→20-30 篇。AI 推荐题目 10-20→30-50 |

| 8 | **E2E 测试扩展到 5+ 关键路径** | P0 | sentence、essay、reading、login、payment |

### 不做（明确推迟到 V1.0 后）
- 移动 App（iOS/Android）
- 老师端 / 班级管理

## 关键风险与缓解（修订版）

| 风险 | 影响阶段 | 缓解措施 |
|---|---|---|
| V0.5b.1 被跳过，产品 polish 不足 | V0.5c+ | V0.5b.1 范围锁定为≤2 天，不允许 scope creep；CEO/产品 owner 必须明确 sign off |
| ModelRouter 设计过度，延迟 V0.6 | V0.5c | ModelRouter V0.5c 只做 config-based task→model mapping，不做动态路由、不做 A-B testing、不做自动模型选择 |
| 课前构思流程太长，孩子放弃 | V0.6 | 选材问答可跳过；提纲可跳过；每步有进度指示；Alpha 数据决定是否简化 |
| LLM 成本随 4 个新 AI 任务（V0.6）增长 | V0.6 | V0.5c 的 ModelRouter + cost registry 让成本可控；小任务用便宜模型 |
| 阅读内容质量不足 | V0.7 | 手动精选 10 篇经典短文作为种子；AI 批改用固定 prompt 模板保证稳定性 |
| 付费转化率低 | V1.0 | Alpha 阶段持续收集家长价值感知数据；V0.8 完整周报是付费转化的关键触点 |
| 功能蔓延导致 V1.0 延迟 | 全阶段 | 每个 Phase 有明确的"不做"列表；V1.0 定义为"最小完整产品" |
