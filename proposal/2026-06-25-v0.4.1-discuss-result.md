# WenLingo V0.4.1a Minimum Viable Alpha Entry — Implementation Task



## Context

V0.4 Minimal Assessment Entry has been implemented and QAed.

V0.4 successfully created the first real learning loop:

```text
new/default child
→ 3–5 minute entry assessment
→ fixed sentence upgrade
→ short writing task
→ real SentenceTraining artifact
→ real Essay / EssayVersion artifact
→ AbilityHistory updates
→ first ability sketch
→ Dashboard recommendation changes from assessment to personalized tasks
```

However, V0.4 still cannot be used by real families because there is no real family entry flow:

```text
no child creation UI/API
no clear parent-facing vs child-facing usage model
current flow still behaves like a demo tool
```

The V0.4.1 proposal was reviewed by Claude Code + gstack. The review approved the direction but warned that the proposal is too large for a single enablement release.

Therefore, implement only **V0.4.1a — Minimum Viable Alpha Entry**.

Do not implement the full V0.4.1 proposal yet.

## Goal

Allow a real invited parent-like user to create a child profile, enter the child dashboard, let the child complete the existing V0.4 assessment, and let the parent see a minimal growth summary.

This is for:

```text
3–5 invited families
manual monitoring
no public launch
no payment
no leaderboard
no full auth
no school deployment
```

## Product Scope

1. Manual Alpha entry link

If any of these already exist partially and can be wired with almost no scope increase, ask before expanding scope.

## Important Product Decisions

### 1. Use Manual Alpha Link

Do not build invite codes yet.

Use a simple manual Alpha link such as:

```text
/alpha/start
```

or:

```text
/alpha/family
```

The developer will manually send this link to 3–5 trusted families.

### 2. Use Real ParentUser

Do not create a separate `AlphaFamily` model unless the existing codebase makes `ParentUser` impossible.

Preferred behavior:

```text
Alpha notice accepted
→ create or reuse a ParentUser row
→ create children under ParentUser.parent_id
```

This is preferred because the existing data model already links children to parents.

If the current codebase has a different concrete model name, inspect the code and use the existing parent model consistently.

### 3. Preserve Demo Flow

Do not break the existing seeded demo family behavior.

The gstack review specifically warns that navigation split has regression risk. Keep existing `FamilyTopbar` unchanged for demo paths if possible.

Add Alpha-specific navigation separately, for example:

```text
AlphaParentNav
AlphaChildNav
```

or conditional rendering only for the Alpha path.

## Backend Requirements

### Child Creation API

Add or expose an API that creates a child under a parent.

Minimum request:

```json
{
  "nickname": "小星",
  "grade": 4
}
```

Behavior:

- create `StudentProfile`
- create default `AbilityProfile`
- associate child with `ParentUser`
- return child id and dashboard URL
- do not require real name, school, phone, address, birthdate, or photo

Validation:

- nickname required
- grade required
- grade should support elementary range, at least 3–6
- reject empty nickname
- reject overlong nickname
- allow normal Chinese names/nicknames and spaces safely

### Parent Creation / Reuse

For V0.4.1a, implement the smallest working parent identity.

Acceptable:

- create a generic Alpha parent row after Alpha notice acceptance; or
- create a parent row from a display name field; or
- reuse a manually created parent if the codebase already has a simple demo login mechanism.

But do not require full auth.

Important:

- children must be associated with a real parent row, not orphaned
- the flow should not require seed_demo_data

### Parent Children API

Provide an API to list children for the Alpha parent.

The parent landing page should show all children at a glance.

For each child card, show at minimum:

```text
nickname
grade
assessment status
last activity if easy
button: 进入孩子空间
button: 查看成长摘要
```

### Minimal Parent Summary API

Add a read API that returns a minimal summary based on real data.

Use existing data:

```text
Assessment
SentenceTraining
Essay / EssayVersion
AbilityHistory
GameEvent
AbilityProfile
```

Minimum response should support:

```text
assessment completed or not
recent training counts
ability changes from AbilityHistory
one recent highlight if available
next suggestion
```

Example summary:

```text
孩子最近完成了：
- 入门小试炼 1 次
- 句子训练 N 次
- 小写作 N 次

能力变化：
- 表达力 +X
- 观察力 +Y

最近亮点：
孩子完成了第一次能力草图。

下一步建议：
继续练习“把句子写具体”。
```

For a newly created child with no training data, return a friendly empty state:

```text
还没有训练记录。完成入门小试炼后，这里会出现第一份成长摘要。
```
