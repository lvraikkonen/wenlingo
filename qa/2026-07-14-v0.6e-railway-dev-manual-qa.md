## Pause Note: `/alpha/start` Slow Load

- User paused QA after opening `https://wenlingo.com/alpha/start`.
- Chrome DevTools showed `GET https://wenlingo.com/api/auth/session` returning `500 Internal Server Error`.
- Chrome DevTools also showed `Remote Address: 127.0.0.1:10810`, which strongly suggests the browser request is going through a local proxy.
- Local shell environment also had `HTTP_PROXY`, `HTTPS_PROXY`, and `ALL_PROXY` set to `http://127.0.0.1:10810`; a proxied curl failed immediately because that local proxy port was unavailable from this session.
- Code inspection: `/alpha/start` calls `/api/auth/session` on first load. The API route should normally return `{"authenticated": false}` when no valid session cookie is present, so a 500 or long wait should be investigated before continuing QA.
- User disabled the local browser proxy and still saw a 500.
- Railway `wenlingo-web` logs showed a Next.js proxy failure:
  `Failed to proxy https://wenlingo-api-production.up.railway.app/api/essays/.../material-questions Error: socket hang up` / `ECONNRESET`.
- Interpretation: the visible 500 is likely emitted by the web rewrite/proxy while forwarding `/api/*` to `API_PROXY_TARGET`. A normal FastAPI 500 should have a traceback in `wenlingo-api` logs; an `ECONNRESET` suggests the API connection was closed/reset or the API service was restarting/unhealthy.
- User restarted the `wenlingo-api` Railway service and reported that the site recovered. QA resumed after this restart.

- Local fix: `apps/web/src/lib/api.ts` now raises `StreamResponseError` when an SSE `error` frame is received.
- Regression coverage:
  - `apps/web/tests/api.test.ts` verifies backend SSE error frames reject with the backend error code/final status.
  - `apps/web/tests/writing_castle_prewriting.test.tsx` verifies first-draft streaming failure before preview falls back to JSON feedback.
- Verification: `corepack pnpm --dir apps/web test -- api.test.ts writing_castle_prewriting.test.tsx` passed: 20 files, 241 tests. `git diff --check` passed.
- Deployed/retested on Railway Dev: partial fix only. Chrome network showed:
