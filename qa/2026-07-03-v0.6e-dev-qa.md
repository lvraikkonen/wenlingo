## Observations

- Direct draft streaming: with streaming flags enabled, the direct draft flow posts to `/essays/stream-feedback`, reaches `作文点评`, and shows `修改小任务`.
- Writing Castle first-draft streaming: with streaming flags enabled, the first-draft flow posts to `/first-draft/stream-feedback`, replaces preview state with canonical feedback, reaches `作文点评`, and shows `修改小任务`.
- Material-card job: with progress-job flags enabled, the flow posts to `/material-cards/jobs`, receives a material-card job response, and advances only after material cards are available.
- Outline job: with progress-job flags enabled, the flow posts to `/outline/jobs`, receives an outline job response, and advances to `第 4 步 / 共 4 步：搭一个提纲`.
- Feature-flag-off fallback: with default flags disabled, direct draft uses the JSON `/api/students/{student_id}/essays` route and reaches feedback.
- Admin AI usage row: backend/admin API and web admin tests verify the V0.6e usage columns, including `Usage available`, `First visible`, and `Fallback rate`.

## Known Issues Discovered

- Fixed during this QA: streaming `done` events returned `fetch_url` at the top level while the frontend reducer expects `result.fetch_url`. The backend now emits `done.result.fetch_url`.
- Fixed during this QA: `fetch_url` pointed at `/api/essays/{essay_id}` without a canonical GET result route. The backend now returns first-draft feedback from that opaque URL.
- Fixed during this QA: a stale backend resilience test expected `初稿/二稿` copy after the implementation had moved to round-neutral `上一稿/这一稿` wording.
- Noted limitation: the V0.6e Playwright spec uses environment-gated tests because frontend `NEXT_PUBLIC_*` flags are fixed when the dev server starts. Run both default and flag-on commands above for complete coverage.
