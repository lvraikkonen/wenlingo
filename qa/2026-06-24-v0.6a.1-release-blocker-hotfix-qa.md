## Root Cause

Confirmed root cause: child-edited placeholder outline sections were sent as non-placeholder sections with no `source_card_ids`; strict backend outline source validation rejected the save. V0.6a.1 keeps generated outline validation strict and allows only child-authored outline edits to save without source ids at the `PATCH /outline` boundary.

## Minimal Failing Request

- Endpoint: `PATCH /api/essays/{essay_id}/outline`
- Status before fix: `400`
- Response body before fix: `{"detail":"story-specific outline sections require source_card_ids"}`
- Synthetic sanitized payload shape:

```json
{
  "sections": [
```

Latency/fallback interpretation:

- `writing_topic_analysis`, `material_questions`, `material_card_generation`,
  and `outline_generation` are configured in ModelRouter with registered prompt
  keys, primary HTTP model routing, fallback HTTP model routing, and local
  deterministic fallback.
- The observed `deterministic_fallback_used` rows mean both provider attempts
  failed to produce a validated output and the local deterministic fallback was
  used. The current Admin AI usage aggregate does not expose the persisted
  `fallback_reason` or per-attempt summaries, so the aggregate alone cannot
  distinguish timeout, malformed JSON, schema validation failure, task
  validation failure, or provider HTTP/API error.
- Because `essay_feedback` and `essay_revision_comparison` returned
  `primary_success` from the HTTP provider in the same Railway Dev run, this is
  not evidence of a global provider credential outage. The pattern points to
  prewriting task-specific provider output/latency/validation behavior and
  should be followed up with privacy-safe `LLMCallLog.fallback_reason` and
  `attempt_summaries` aggregation before V0.6b latency optimization.
