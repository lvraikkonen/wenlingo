# V0.5c.2 Alpha Auth Runtime Hardening QA Checklist

Date: 2026-06-19
Status: Draft

Do not record raw Admin tokens, Magic Codes, full emails, full phone numbers,
session cookies, token hashes, or child writing content.

## Runtime Demo Removal

- [ ] `POST /api/auth/demo-login` returns 404.
- [ ] Web home page links to `/alpha/start` and does not show seeded demo children.
- [ ] Unauthenticated direct access to a child dashboard does not render seeded demo data.
- [ ] Unauthenticated direct access to child task pages does not render seeded demo data.
- [ ] `FamilyTopbar` does not show seeded demo children after auth failure.

## Family Boundary

- [ ] Authenticated parent can open their own child dashboard.
- [ ] Authenticated parent cannot open another family's child dashboard.
- [ ] Authenticated parent cannot create or complete another family's child task.

## Admin Session Operations

- [ ] Admin account list shows active session count.
- [ ] Admin can open active session details for an account.
- [ ] Session detail response does not expose token hash.
- [ ] Admin can revoke one active session.
- [ ] Admin sees confirmation text before revoke-all: `这会让该家长账号的所有设备重新登录。`
- [ ] Admin can revoke all active sessions for an account.

## Cleanup Command

Run `cd apps/api` before cleanup commands. Before using `--execute`, verify the
configured database target is the intended disposable, local, or staging DB.

- [ ] Dry-run shows scanned, eligible, deleted, reason counts, and cutoff times.
- [ ] Dry-run does not delete rows.
- [ ] Execute deletes eligible expired/revoked rows.
- [ ] Execute is safe to run twice.
- [ ] Output does not include token hashes or raw session cookies.
