## Findings

- [P1] Confirming or editing a generated outline fails on production. After
      editing the `结果` outline section and clicking `确认提纲，开始写`, the UI
      stayed on step 4 and showed `这一步没有保存成功，可以重试，也可以先继续写。`.
      The skip action `我想直接开始写` did continue to the first-draft editor, but
      the normal confirm/edit path is part of the V0.6a acceptance criteria.
- [P2] The classroom outline/material organization is still the traditional
      narrative template `起因 -> 经过 -> 结果 -> 感受`. It does not yet adapt the
      material questions, material cards, or outline structure to different
      school作文 requirements or non-narrative topic types. This matches the
      current V0.6a implementation direction but should be treated as a product
      limitation for follow-up planning.
- [P3] AI interaction latency is visibly high during Writing Castle generation
      and feedback. Future work should move AI-facing interactions to streaming
      UX, likely SSE, for sentence practice, Writing Castle prewriting, essay
      feedback, and revision comparison.
- [P4] Streaming AI output has observability implications. Token/cost tracking
      should be reviewed before SSE rollout so `LLMCallLog` can still capture
      final status, fallback status, latency, token usage, and cost for
      streamed responses. If a provider only returns usage at stream completion,
      logging should finalize after the terminal stream event; if usage is not
      returned, define a consistent estimator or mark usage as unavailable.
- [P5] The first custom-domain run failed because Railway API origin allowlists
      only contained the old Railway web domain. This was fixed during QA by
      updating `AUTH_ALLOWED_ORIGINS` and `CORS_ALLOW_ORIGINS` and redeploying.
