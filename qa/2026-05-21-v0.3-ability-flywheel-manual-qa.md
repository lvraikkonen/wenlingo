## Case 1: Sentence training creates AbilityHistory

Status: fail.

Action:

- Submitted `POST /api/students/s1/sentences`
- Source: `公园很美。`
- Upgraded: `清晨的公园里，荷叶上的水珠一闪一闪，像小灯泡。`
- Focus: `加细节`

Observed:

- `SentenceTraining` row was created:
  - `id=2279b691-c552-4b39-a3de-f9927215c27c`
  - `source_type` should have been `sentence`
- `AbilityProfile` did not change after the sentence step.
- `AbilityHistory` query for the training source ID returned no rows.
- Real provider `ability_delta` used non-canonical Chinese keys:
  - `细节描写: 2`
  - `比喻运用: 1`

Expected:

- At least one `AbilityHistory` row linked to `source_type=sentence` and `source_id=SentenceTraining.id`.
- `AbilityProfile` should update atomically with the sentence training result.

Assessment:

- The route uses `feedback.ability_delta or SENTENCE_ABILITY_DELTA_FALLBACK`.
- Because the real provider returned a non-empty dict, fallback did not trigger.
- `apply_ability_delta` filtered all non-canonical ability names, so no history was written.
- This means V0.3 is still not reliable with real LLM output for sentence ability deltas.

## Case 6: Invalid / empty deltas do not create history

Status: pass by focused automated test; real-provider sentence path exposes a related product risk.

Evidence:

- `tests/test_learning_state_services.py::test_apply_ability_delta_ignores_empty_zero_negative_invalid_and_unchanged_deltas`
- Focused suite result: `31 passed`.

Assessment:

- Service-level filtering is correct for invalid keys.
- Route-level fallback is not robust enough for real LLM output that returns a non-empty but entirely invalid delta map.
- Acceptance should distinguish "invalid deltas do not create history" from "sentence route still creates growth events when the LLM does not follow canonical keys."

## Data Flow Verdict

Observed successful chain for essay:

```text
essay draft / essay revision
-> computed ability_delta
-> AbilityHistory
-> AbilityProfile
-> Dashboard recommendation / ability bars
-> Report training evidence
```

Observed broken chain for real-provider sentence training:

```text
sentence training
-> real LLM ability_delta with non-canonical keys
-> apply_ability_delta filters all keys
-> no AbilityHistory
-> no AbilityProfile change
-> Dashboard and Report cannot reflect the sentence growth event
```

## Review Notes

- `AbilityHistory` exists as a real SQLModel table and SQLite table.
- `apply_ability_delta` is the shared service boundary for observed ability updates.
- Sentence, essay draft, essay revision, and reading routes call `apply_ability_delta`.
- Recommendation no longer accepts or depends on `has_completed_assessment`.
- No V0.3 UI scope creep was observed in `apps/web/src`; current working tree only showed an unrelated `apps/web/next-env.d.ts` modification before this QA document was added.

## Verdict

Fail until the sentence route handles real-provider non-canonical `ability_delta` safely.

Recommended follow-up:

- Validate or normalize `SentenceFeedback.ability_delta` before deciding whether to use fallback.
- Treat "non-empty but no valid canonical ability keys" the same as empty/missing for the sentence fallback, or tighten the LLM contract/schema to reject unknown keys and trigger the existing fallback path.
- Add an integration test with a provider response like `{"细节描写": 2}` to prove sentence training still creates `expression` / `observation` history.
- Decide whether V0.3 reports are expected to read `AbilityHistory`; if yes, update `build_stage_report_content` to include recent growth rows as evidence.
