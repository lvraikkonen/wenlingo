# WenLingo V0.5b.1 Alpha Polish Release Gate Design

Date: 2026-06-13
Status: Approved for implementation planning
Owner role: gstack product / UX / architecture / QA review

## Goal

V0.5b.1 turns V0.5b from "functionally complete on Dev" into "ready to expand Alpha to more real families." It closes the product polish, observability, identity consistency, and QA gaps found in the V0.5b reviews without adding new learning features or starting the V0.5c AI platform work.

V0.5b.1 is a release gate. It passes only when a reviewer can say:

1. A child can enter Sentence Workshop, wait for AI, submit, receive feedback, and recover from daily limits without the experience feeling broken or frozen.
2. A parent can log in from a fresh browser without legacy localStorage identity causing confusion.
3. Admin can distinguish "known zero cost" from "pricing not configured," and can verify daily limit hits.
4. Reading Canyon no longer behaves like an active child-facing destination before V0.7.
5. A child who skips the initial assessment still sees a clear path back to it.
6. Dev has a completed smoke checklist proving the above on the deployed Railway URL.
7. Browser console is free of the known React hydration error during the smoke path.

## Scope

### In Scope

- Sentence workshop loading and feedback presentation polish.
- Admin AI usage cost display and pricing configured indicator.
- Daily limit config documentation plus Dev end-to-end verification.
- React hydration error #418 investigation and fix.
- `wenlingo_alpha_parent_id` cleanup Step 1 and Step 2:
  - stop new writes;
  - demote reads to legacy migration only.
- Hide or disable Reading Canyon entry from child-facing navigation and dashboard until V0.7.
- Preserve and surface the initial assessment path when a child enters practice first.
- Env/config docs update for LLM pricing and daily limit switches.
- A V0.5b.1 release checklist under `qa/`.

### Out Of Scope

- ModelRouter, provider fallback, per-task model config, or cost registry implementation.
- New sentence challenge types.
- Writing Castle or pre-writing work.
- Reading Canyon v1.
- Full Admin v2 or broad route/module refactors.
- Replacing the server-side parent session architecture.
- Frontend framework upgrades.

## Product Decisions

### 1. V0.5b.1 Is An Alpha Expansion Gate

This is not a cosmetic polish pass. The release should be held until the scoped gates are implemented, verified, and recorded in QA. The goal is to make the current product feel serious enough for more real Alpha families, not to expand the product surface.

### 2. Initial Assessment Uses Light Blocking

If a child has not completed the initial assessment, the app should strongly recommend it but not hard-block exploration.

Preferred behavior:

- Dashboard keeps "入门小试炼" as the primary recommendation.
- Sentence Workshop and Writing Castle show a compact recommendation card before the main task.
- The card offers:
  - primary action: "先去小试炼";
  - secondary action: "今天先练句子" or "今天先写作文".
- The recommendation disappears after assessment completion.

This solves the handoff confusion observed during child testing without turning the product into a rigid setup wizard.

### 3. Reading Canyon Is Visible Only As Future World-Building

Until V0.7, Reading Canyon should not appear as a normal active destination. The preferred V0.5b.1 treatment is a disabled map item:

```text
阅读峡谷 · 即将开放
```

It should not link to `/children/{studentId}/reading` from child-facing dashboard or navigation. The placeholder route may remain for old links and regression coverage.

### 4. Cost Unknown Must Not Look Free

Admin AI usage should continue showing tokens and model/task rows, but cost should only be formatted as money when pricing is configured. If pricing env vars are zero or unset, Admin should show "未配置价格" rather than `0`, `$0.0000`, or an equivalent misleading free-cost display.

## Release Gates

### Gate 1: Sentence Workshop AI Waiting Experience

The current single loading line becomes a small child-friendly AI waiting component for both challenge generation and feedback submission.

Requirements:

- Staged copy for challenge generation, for example:
  - "正在出题..."
  - "AI 教练正在想一个适合你的句子..."
  - "快好了！"
- Separate staged copy for feedback submission, for example:
  - "AI 教练正在读你的句子..."
  - "正在找出你写得好的地方..."
  - "马上给你一个小建议。"
- A simple animation that does not resize or shift the layout.
- Mobile-safe text wrapping.
- The form remains understandable while disabled or waiting.
- `example_upgrade` is labeled as a reference, not a correction, for example:

```text
这是一个参考写法，你的写法也很棒。
```

Acceptance:

- On slow AI responses, the child can tell the system is still working.
- Feedback still follows the positive order:

```text
encouragement -> highlight -> suggestion -> reference example
```

### Gate 2: Cost Display Is Honest

Backend/Admin aggregate should expose whether pricing is configured.

Preferred backend signal:

```text
pricing_configured = llm_input_cost_per_1k_tokens > 0
                  or llm_output_cost_per_1k_tokens > 0
```

Requirements:

- Admin AI usage response includes `pricing_configured` at the response or row level.
- Admin Cost column shows "未配置价格" when pricing is not configured.
- Admin Cost column shows a formatted cost only when pricing is configured.
- Token counts remain visible either way.

Acceptance:

- Ops can distinguish unknown cost from genuinely low cost.
- This remains a narrow V0.5b.1 honesty fix, not the V0.5c model-level cost registry.

### Gate 3: Daily Limit Is Verified On Dev

`LLM_DAILY_LIMIT_ENABLED=true` must be active and verified on Railway Dev.

Requirements:

- Dev env/config docs state that `LLM_DAILY_LIMIT_ENABLED=true` is required for limit QA.
- QA forces or naturally reaches the sentence challenge generation and/or feedback limit.
- During Dev smoke, QA should temporarily set the sentence challenge generation or feedback daily limit to a low value such as `1` or `2` for the masked QA student/environment, then restore normal Alpha configuration after verification. This avoids excessive manual clicks and unnecessary real LLM calls.
- After the limit is reached:
  - no provider call is made for the limited task;
  - the child sees the rest message;
  - `ai_daily_limit_reached` ProductEvent is recorded;
  - Admin `Limits` count increments.

Acceptance:

- The guardrail is proven in the deployed environment, not only in tests.

### Gate 4: Hydration Error Closed

The known React hydration error #418 must be investigated and fixed on the smoke path.

Smoke path:

```text
/alpha/start
-> parent children
-> child dashboard
-> sentence workshop
-> Admin AI usage
```

Acceptance:

- Browser console shows no recurring hydration error during the smoke path.
- The QA checklist records console status.

### Gate 5: Legacy localStorage Identity Demoted

The server-side parent session remains the source of truth.

Requirements:

- Successful login, existing-account login, create-family, and current-browser switching flows stop writing `wenlingo_alpha_parent_id`.
- `getStoredAlphaParentId()` remains only for the legacy migration flow on `/alpha/start`.
- `clearStoredAlphaParentId()` remains for logout/reset cleanup.
- `FamilyTopbar` and authenticated child/parent runtime pages do not decide Alpha mode from `wenlingo_alpha_parent_id`.
- Authenticated context should come from session-backed APIs such as `/api/auth/session` and `/api/alpha/my-children`.
- Event tracking should not require storing parent identity in localStorage. If needed, it should be replaced with a server-session-aware event path or demoted.

Acceptance:

- Fresh-browser existing-account login does not create a new `wenlingo_alpha_parent_id`.
- Stale `wenlingo_alpha_parent_id` cannot override the real session.
- Legacy unbound Alpha browsers still have a migration path.

### Gate 6: Reading Canyon Is Not A Dead-End Destination

Requirements:

- Dashboard map and child-facing navigation should not link to Reading Canyon as an active place.
- Preferred treatment is a disabled item labeled "阅读峡谷 · 即将开放".
- The existing placeholder route may remain reachable for old links.

Acceptance:

- Children are not invited into a dead-end module during expanded Alpha.

### Gate 7: Release QA Artifact Exists

Create a V0.5b.1 QA checklist under `qa/`, for example:

```text
qa/2026-06-13-v0.5b.1-alpha-polish-release-checklist.md
```

Required sections:

- Environment and deployed commit.
- Masked test accounts/families.
- Parent login and fresh-browser handoff.
- New child assessment prompt persistence.
- Sentence workshop challenge generation/loading/submission.
- Daily limit path.
- Admin AI usage/cost.
- Reading Canyon non-active entry.
- Browser console status.
- Final go/no-go decision.

Acceptance:

- Release readiness is auditable, not just asserted.

### Gate 8: Initial Assessment Cannot Be Lost

If the child has not completed the initial assessment, the path back to it must remain clear even when the child enters practice first.

Requirements:

- Backend provides a clear signal such as `assessment_completed` and, if useful, `assessment_recommended`.
- Dashboard keeps assessment as the primary recommendation until completion.
- Sentence Workshop and Writing Castle show the light-blocking assessment recommendation card before their main task.
- The card lets the child go to assessment or continue practice.
- The card disappears after assessment completion.

Acceptance:

- New child from parent handoff can go directly to Sentence Workshop and still see a clear "先去小试炼" path.
- Choosing "今天先练句子" continues the current sentence flow.
- Returning to Dashboard still shows assessment until the child completes it.

## Architecture And Data Flow

### Assessment Visibility

Current backend behavior already checks whether an `Assessment` exists and returns `assessment` as the main task for a default ability profile. V0.5b.1 should make that condition explicit for frontend pages.

Recommended API shape:

```json
{
  "assessment_completed": false,
  "assessment_recommended": true
}
```

`assessment_completed` should be based on whether an `Assessment` exists for the student. `assessment_recommended` may combine completion state with the existing default ability profile rule.

Frontend learning pages should use this backend-derived signal rather than inferring assessment state only from ability values.

### localStorage Identity Cleanup

Current server-side session is correct and should remain unchanged. V0.5b.1 removes localStorage parent identity from normal authenticated routing, while preserving legacy migration.

Implementation should be incremental:

1. Stop all new writes to `wenlingo_alpha_parent_id` after successful real-auth flows.
2. Update authenticated pages and topbar to use session-backed parent/children data.
3. Keep `/alpha/start` legacy migration behavior for browsers that already have the key.
4. Keep logout/reset cleanup.

### Admin Cost Signal

V0.5b.1 adds a configuration signal at the aggregate boundary. It should not change the stored `LLMCallLog` schema unless needed by implementation.

Future V0.5c model-level pricing should be able to replace or extend this signal without rewriting Admin from scratch.

### Daily Limit Verification

No major architecture change is expected. V0.5b.1 verifies existing limit behavior in Dev and documents the required environment switch.

### V0.5c Compatibility

V0.5b.1 should avoid changes that make V0.5c harder:

- Do not add ad hoc per-task model env vars.
- Do not create a partial ModelRouter.
- Keep usage/cost response fields compatible with future per-provider and per-model breakdowns.
- Keep loading polish local enough that V0.5c can later introduce a shared AI interaction state.

## Testing And QA Design

### Backend Tests

Add or update focused tests for:

- Dashboard or student status response includes assessment completion/recommendation signals for:
  - a new child with no assessment;
  - a child after assessment creation.
- Admin AI usage response reports `pricing_configured=false` when token prices are unset or zero.
- Admin AI usage response reports `pricing_configured=true` and preserves estimated cost when token prices are configured.
- Daily limit behavior still proves limited fallback does not call the provider.

### Frontend Tests

Add or update focused tests for:

- Dashboard shows assessment as primary recommendation for an unassessed/default-profile child.
- Sentence page shows the assessment recommendation card for an unassessed child.
- The card allows "today continue practice" without breaking the current sentence flow.
- The card is absent after assessment completion.
- Sentence loading component renders waiting copy for generation and submission.
- Admin AI usage renders "未配置价格" when pricing is not configured.
- Planet map renders Reading Canyon as disabled or omits the active link.
- Fresh existing-account login does not write `wenlingo_alpha_parent_id`.

### Manual Dev Smoke

Required Dev smoke path:

1. Open `https://wenlingo-web-production.up.railway.app/alpha/start`.
2. Complete existing-account login from a fresh browser.
3. Verify no new `wenlingo_alpha_parent_id` is written.
4. Create or use a child with no assessment.
5. Verify Dashboard keeps assessment primary.
6. Enter Sentence Workshop directly.
7. Verify assessment recommendation card appears and can be bypassed.
8. Verify challenge loading, submission loading, feedback, reference example label, and settlement.
9. Temporarily set sentence challenge generation or feedback daily limit to `1` or `2` for the masked QA student/environment.
10. Trigger the daily limit with the minimum needed challenge generation or feedback attempts.
11. Verify child rest message and Admin limit count.
12. Restore normal Alpha daily limit configuration.
13. Verify Admin AI usage cost display.
14. Verify Reading Canyon is not active in dashboard/map navigation.
15. Verify browser console has no recurring hydration error.

## Handoff To Codex

### Goal

Implement V0.5b.1 as an Alpha expansion release gate: improve the child AI waiting experience, make Admin cost observability honest, verify daily limits on Dev, close the hydration issue, demote legacy localStorage parent identity, prevent Reading Canyon from acting as a dead-end destination, and preserve the initial assessment path for children who enter practice first.

### Non-Negotiables

- Preserve positive child-facing feedback.
- Do not block children hard from practicing before assessment.
- Do not replace the server-side parent session architecture.
- Do not implement V0.5c platform features in this release.
- Keep legacy localStorage migration possible for old unbound Alpha browsers.
- Do not display unknown AI cost as zero.
- Produce a QA checklist before calling the release ready.

### Acceptance Criteria

- All eight release gates in this spec pass.
- Relevant backend and frontend tests pass.
- Manual Dev smoke checklist is completed under `qa/`.
- Console hydration error is absent during the smoke path.
- New login/create flows do not write `wenlingo_alpha_parent_id`.
- Admin cost display distinguishes unconfigured pricing from real cost.
- Daily limit behavior is verified on Dev.

### Do Not Do

- Do not add new challenge types.
- Do not add ModelRouter or provider fallback.
- Do not build Reading Canyon v1.
- Do not start Writing Castle pre-writing.
- Do not refactor Admin broadly beyond scoped needs.

### Review Required After Implementation

gstack should review:

- Child UX: loading, assessment recommendation, and feedback tone.
- Parent/session UX: fresh-browser login and no stale localStorage confusion.
- Admin UX: pricing configured display and daily limit counts.
- QA evidence: release checklist, console status, and smoke path.
- Architecture: no accidental V0.5c partial implementation or auth rewrite.

## V0.5c Boundary For Later

V0.5c remains deferred until V0.5b.1 is implemented and reviewed.

V0.5c purpose:

```text
Task-specific quality, latency, and cost control before V0.6 Writing Castle expands AI usage.
```

Likely V0.5c scope, not designed here:

- ModelRouter: task to model/provider mapping.
- Per-task timeout and retry policy.
- Provider fallback.
- Model-level pricing registry.
- Admin usage breakdown by provider/model/task with reliable cost.
- Prompt registry cleanup for `material_questions` and `outline_generation`.
- `run_validated_llm_task()` decomposition into clearer steps.
- Shared frontend AI interaction state, likely piloted from Sentence Workshop.
- At least two E2E flows: Magic Code login and sentence challenge completion.

V0.5b.1 must not:

- Add multiple model routing env vars.
- Introduce a full pricing registry.
- Split all Admin routes.
- Rewrite the LLM provider abstraction.
- Convert Sentence Workshop to a global AI state machine.
- Add new AI task types.

Before starting detailed V0.5c design, review:

- Whether V0.5b.1 daily limit and cost QA showed real provider/token behavior.
- Whether loading polish was enough or a shared AI state machine is needed.
- Whether `run_validated_llm_task()` changes are urgent or can be incremental.
- Whether expanded Alpha produced new AI latency/cost issues.
