## Goal

Move V0.6a from No-Go to Go for limited Alpha by fixing the Writing Castle classroom prewriting outline edit/confirm save blocker, adding regression coverage, and completing focused QA blind spots.

V0.6a.1 is a release blocker hotfix. It does not introduce V0.6b topic-type adaptation, new scaffold templates, AI topic generation, streaming, or a UI redesign.

## Problem Summary

Manual QA on `https://wenlingo.com` found that the classroom Writing Castle flow can proceed when the child skips the outline step, but fails when the child edits a generated outline section and clicks `确认提纲，开始写`. The UI remains on step 4 and shows the generic save failure message.

The normal confirm/edit path is part of the V0.6a learning design because it is the moment where the child takes ownership of the writing plan. Skipping outline is a safety valve, not an acceptable replacement for a broken confirm path.

## Expected Root Cause

The relevant save path is:

- Frontend caller: `apps/web/src/components/writing-castle/ClassroomPrewritingWizard.tsx`
- Outline editor: `apps/web/src/components/writing-castle/OutlineStep.tsx`
- API client: `apps/web/src/lib/api.ts::saveOutline`
- Backend endpoint: `PATCH /api/essays/{essay_id}/outline`
- Backend handler: `apps/api/app/api/routes/writing_castle.py::save_outline`
- State validator: `apps/api/app/services/writing_castle_state.py::validate_outline_sources`

Current behavior appears to be:

1. AI outline generation may return some placeholder outline sections with empty `note`, empty `source_card_ids`, and `placeholder: true`.
2. When the child edits a section, `OutlineStep` marks that section as `child_edited: true` and `placeholder: false`.
3. The frontend sends the edited section to `PATCH /outline`.
4. Backend validation treats any non-placeholder section with a non-empty `note` and no `source_card_ids` as story-specific outline content without traceable sources.
5. The route rejects the request, producing the production save failure.

Existing tests did not catch this because the API happy path confirms the generated outline without editing it, and the E2E smoke clicks confirm without editing a previously source-less placeholder section.

Implementation must still capture the minimal failing request payload and response status/body before applying the fix, so the final implementation summary can confirm or correct this root cause.

## Save Contract

V0.6a.1 defines the outline save contract as:

1. `PATCH /api/essays/{essay_id}/outline` accepts child-edited outline sections and persists the child's text.
2. AI-generated outline content remains source-validated. This hotfix must not allow AI/fallback output to add story content without valid `source_card_ids`.
3. Child-authored outline edits are a valid content source. If a section has `child_edited: true`, backend save normalization may preserve the edit even when no source card exists.
4. When possible, backend save normalization should attach conservative source references:
   - keep existing `source_card_ids` first;
   - otherwise inherit from the previously saved section with the same id only when the child edit appears to modify that section;
   - if no safe inherited source exists, keep `source_card_ids` empty and rely on `child_edited: true` as the explicit source marker;
   - do not attach unrelated retained material cards just to satisfy validation.
5. A child-edited outline section may be saved with empty `source_card_ids`, because the content came directly from the child rather than the AI.
6. The save response must return the normalized persisted outline, and the frontend must use that returned outline for the draft reference area.

This contract preserves the V0.6a principle that AI must not invent作文内容 while recognizing that the child's direct edit is itself a legitimate source of writing intent.

## Backend Design

The backend fix should be narrowly scoped to outline confirmation.

Add a route-level normalization helper for `save_outline` that prepares child-edited sections before calling shared persistence logic. The helper should:

- operate only for `PATCH /outline`, not for AI outline generation;
- detect sections with `child_edited: true` and non-empty `note`;
- normalize those sections to `placeholder: false`;
- preserve existing metadata and order;
- attach source card ids only when they already exist or can be safely inherited from the previously saved section with the same id;
- avoid attaching unrelated retained material cards just to satisfy validation;
- allow child-edited sections without source card ids when no safe inherited source exists;
- reject unknown `source_card_ids` as before.

`merge_outline_sections` and `validate_outline_sources` should remain strict for generated or non-child-edited content. If a small state-level adjustment is needed, it must be explicit that the relaxed rule applies only to `child_edited: true` outline save payloads.

A client must not be able to bypass AI-generated outline source validation by simply setting `child_edited: true` on generated or unchanged story content. The relaxation applies only at the outline save boundary for child-authored edits. It must not apply to AI generation, fallback generation, or shared generated-outline validation.

No prompt, Prompt Registry entry, AI task contract, schema migration, or broad state-machine refactor is part of this hotfix.

## Frontend Design

The frontend fix should be minimal.

`OutlineStep` may continue to mark edited sections as `child_edited: true`. It should not try to invent source card ids in browser state.

`ClassroomPrewritingWizard` should update local outline state from the successful API response before entering the draft step:

- call `saveOutline(essay.id, { sections, skipped })`;
- on success, set `essay` from `saved.essay`;
- set `sections` from `saved.essay.outline.sections`;
- then enter the draft editor.

This ensures that the draft reference area displays the persisted, normalized outline and that refresh/re-entry behavior matches saved state.

No UI redesign, new step, new loading pattern, or V0.6b topic-type UI is included.

## Test Design

Use TDD for the blocker.

### API Regression Test

Add a failing test in `apps/api/tests/test_writing_castle_api.py` that:

1. Creates a classroom Writing Castle essay.
2. Saves enough material input to produce at least one retained material card.
3. Generates outline sections.
4. Edits one previously placeholder/source-less section, such as `result`.
5. Sends `PATCH /api/essays/{essay_id}/outline` with `skipped: false`.
6. Asserts status `200`.
7. Asserts essay status is `outline_ready`.
8. Asserts the edited note is persisted in the response and database.
9. Asserts outline status is `confirmed`.

This test should fail before the fix and pass after it.

### State-Level Tests

Add or update tests in `apps/api/tests/test_writing_castle_state.py` to protect the source boundary:

- non-child-edited story outline notes without sources are still rejected;
- child-edited outline notes without sources are allowed only through the explicit save-normalization path or an explicit state helper;
- unknown source card ids are still rejected.
- AI-generated, fallback-generated, or unchanged story outline content cannot bypass source validation by setting `child_edited: true`; the relaxation is scoped only to `PATCH /outline` save normalization for child-authored edits.

### Frontend Unit/Component Test

Add or update `apps/web/tests/writing_castle_prewriting.test.tsx` so the classroom wizard:

- reaches outline step;
- edits one outline textarea;
- clicks `确认提纲，开始写`;
- verifies `saveOutline` receives a child-edited section;
- enters the first draft editor;
- displays the edited outline content in the reference area.

### Playwright E2E

Add or update `apps/web/e2e/v06a-writing-castle.spec.ts` to cover:

- generate outline;
- edit one section;
- confirm outline;
- enter draft editor;
- verify edited outline content appears in the draft reference area;
- verify the edited outline survives refresh or returning to the essay when supported by the current route behavior.

The existing direct-write E2E regression must stay green.

## Latency Baseline

V0.6a.1 records a baseline but does not optimize latency.

Use Admin AI usage, `LLMCallLog`, or an equivalent privacy-safe aggregate to record available latency for:

- `writing_topic_analysis`
- `material_questions`
- `material_card_generation`
- `outline_generation`
- `essay_feedback`
- `revision_comparison`, if a comparison is available in the QA run

The baseline should include task name, call count, average latency when available, final status/fallback status, and date/environment. Latency is not a Go blocker unless it causes task failure or extreme timeout during QA.

## Acceptance Criteria

- Editing one outline section and clicking confirm successfully moves the child to the draft editor.
- Edited outline content appears in the draft reference area.
- Edited outline content survives refresh or returning to the essay.
- API regression test reproduces and protects the outline edit/confirm path.
- Playwright E2E covers outline edit + confirm + draft reference persistence.
- Direct-write essay flow remains green.
- Parent process summary renders correctly.
- Auth boundary and root route QA blind spots are checked.
- Latency baseline is recorded.
- `child_edited: true` cannot bypass source validation in AI generation, fallback generation, or shared generated-outline validation.
- No V0.6b functionality is introduced.

## Go / No-Go Recommendation Rule

Recommend Go for limited Alpha only when:

- local API, frontend, and focused Playwright checks pass;
- Railway Dev happy path with outline edit + confirm passes;
- skip behavior, auth boundary, root route, direct-write flow, and parent summary are verified;
- QA document records the latency baseline and remaining risks;
- no out-of-scope V0.6b behavior was added.

Recommend No-Go if outline edit/confirm still fails, edited content does not persist, auth/family boundary checks fail, direct-write flow regresses, or parent summary breaks.
