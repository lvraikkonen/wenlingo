# WenLingo V0.5b AI Infrastructure + Sentence Training Design

Date: 2026-06-08
Status: Revised after user review
Source review: `reviews/2026-06-08-v0.5a-series-post-implementation-review.md`

## Goal

V0.5b establishes the AI infrastructure needed before larger LLM-powered product work, then ships a thin vertical slice of AI-generated sentence training by extending the existing sentence workshop.

The intended learning loop is:

```text
AI generates a sentence challenge
-> child rewrites the sentence
-> AI gives structured feedback
-> ability and XP update
-> parent summary records lightweight progress
-> admin can see aggregate AI usage and cost
```

This version keeps the current Alpha identity/session foundation intact. It does not begin Writing Castle or a full sentence curriculum.

## Product Decisions

- V0.5b extends the existing sentence workshop instead of creating a parallel training engine.
- AI challenge generation uses fixed task templates plus AI-generated challenge content.
- If AI challenge generation fails, the backend uses local fallback challenge templates.
- The thin slice includes three challenge types:
  - `expand_sentence`: 扩句
  - `action_expression`: 加动作/神态
  - `feeling`: 加心理感受
- Generated challenges are persisted immediately.
- The challenge state machine is intentionally small: `generated` -> `completed`.
- Generated challenge completion uses a short child-facing feedback contract rather than the older free-input sentence feedback shape.
- Parent summary records training progress but does not display child sentence text.

## Email And Dev Echo Preflight

V0.5b includes real email delivery hardening before inviting any external Alpha families.

Settings:

```text
MAGIC_CODE_EMAIL_PROVIDER=resend
MAGIC_CODE_FROM_EMAIL=login@your-domain.com
RESEND_API_KEY=...
RESEND_TIMEOUT_SECONDS=10
ENVIRONMENT=development|staging|production
```

Email sender behavior:

- Add `ResendEmailSender` or a generic `HttpsEmailSender` with a Resend-backed implementation.
- `get_email_sender()` returns Resend when `MAGIC_CODE_EMAIL_PROVIDER=resend`.
- Missing Resend config fails closed with the existing email-provider-unavailable behavior.
- Resend sends the Magic Code email over HTTPS using configured sender, recipient, subject, and text/html body.
- SMTP support may remain, but Resend is the V0.5b Railway Dev path.

Domain readiness:

- Domain verified: use `MAGIC_CODE_FROM_EMAIL` under the verified domain and verify real email delivery in Railway Dev.
- Domain pending: Dev Echo may remain available for internal QA only, but external Alpha invites stay blocked.

Dev Echo startup guard:

```text
if ENVIRONMENT in ("staging", "production") and MAGIC_CODE_DEV_ECHO=true:
    fail fast on startup
```

The guard must use explicit `ENVIRONMENT`, not `DATABASE_URL` heuristics, so Railway Dev and other non-production deployments are not accidentally blocked.

## Backend Design

### SentenceTraining Model

`SentenceTraining` remains the canonical table for sentence practice. V0.5b extends it so one row can represent both a generated challenge and the later completed answer.

New fields:

- `status`: `generated` or `completed`
- `challenge_prompt`: child-facing task instruction
- `hint`: short child-facing hint
- `target_skill`: stable challenge type key
- `completed_at`: timestamp set when the child completes the challenge

Existing fields keep their meaning with small extensions:

- `source_sentence`: stores the AI-generated or fallback source sentence.
- `upgraded_sentence`: empty or nullable while generated, filled on completion.
- `focus`: stores the Chinese display focus already used by current sentence feedback.
- `ai_feedback`: empty while generated, filled on completion.

Generated-but-not-completed rows remain useful for future funnel analysis. V0.5b does not add `skipped`, `abandoned`, or `expired`; those can be derived later by age if needed.

### API Endpoints

New endpoint:

```text
POST /api/students/{student_id}/sentence-challenges
```

Behavior:

- Requires the same auth-mode state-change guard as other student learning writes.
- Verifies the student belongs to the authenticated family.
- Selects one of the three supported challenge types.
- Calls `sentence_challenge_generation` through the LLM task runner.
- Validates the AI output against a strict schema.
- Enforces the sentence challenge generation daily LLM limit.
- Falls back to a local template if the AI call or validation fails.
- Creates a `SentenceTraining` row with `status="generated"`.
- Returns the challenge id, source sentence, challenge prompt, hint, focus, target skill, difficulty label, and grade label.

New endpoint:

```text
POST /api/students/{student_id}/sentences/{training_id}/complete
```

Behavior:

- Requires the same auth-mode state-change guard.
- Verifies the student and training row belong to the authenticated family.
- Rejects already-completed challenges with `409`.
- Accepts the child's upgraded sentence.
- Validates `upgraded_sentence` as required, sentence-level input of 5-120 Chinese characters.
- Calls the short `sentence_challenge_feedback` flow for generated challenges.
- Enforces the sentence challenge feedback daily LLM limit.
- Updates the same `SentenceTraining` row with the answer, feedback, `completed_at`, and `status="completed"`.
- Applies deterministic ability delta and XP settlement by `target_skill`, rather than relying on the short child-facing feedback schema for ability data.
- Records a product event for completion.
- Returns the updated training row, AI feedback, settlement, and next task.

Existing endpoint:

```text
POST /api/students/{student_id}/sentences
```

The current free-input sentence practice endpoint remains compatible. It should gain the same prompt registry and logging improvements, but its external behavior should not change. It can continue using the older `sentence_upgrade_feedback` contract.

### AI Challenge Generation

The AI challenge generator must not generate child answers or full model rewrites. It returns a strict JSON object:

```json
{
  "source_sentence": "小猫跑了。",
  "challenge_prompt": "请把句子写具体，加上动作和样子。",
  "hint": "可以写小猫怎么跑、跑到哪里、看起来怎么样。",
  "target_skill": "action_expression",
  "focus": "动作描写",
  "difficulty_label": "四年级基础",
  "grade_label": "四年级"
}
```

Field constraints:

- `source_sentence`
  - 5-25 Chinese characters.
  - Must be child-safe, daily-life, school-life, family-life, or nature-observation content.
  - Must not include horror, violence, adult content, medical advice, politics, discrimination, dangerous behavior, or sensitive personal data.
- `challenge_prompt`
  - 10-60 Chinese characters.
  - Gives only the task.
  - Must not provide an answer.
  - Must not ask the child to write a long paragraph.
- `hint`
  - 10-80 Chinese characters.
  - Gives an observation angle only.
  - Must not provide a full standard answer.
- `target_skill`
  - One of `expand_sentence`, `action_expression`, `feeling`.
- `focus`
  - One of `扩句`, `动作描写`, `心理感受`.
- `difficulty_label`
  - One of `四年级基础`, `四年级进阶`.
- `grade_label`
  - `四年级`.

Fallback templates provide safe local challenges for each supported type. A fallback challenge still creates a normal `SentenceTraining` row so the child experience does not fail just because the model did.

### AI Challenge Feedback

Generated challenge completion uses a short feedback contract designed for quick child-facing iteration:

```json
{
  "encouragement": "你写得很有画面感！",
  "highlight": "你加上了“飞快地冲过去”，动作更清楚了。",
  "suggestion": "还可以加一点表情或心情。",
  "example_upgrade": "小狗瞪大眼睛，飞快地冲过草地，好像发现了什么宝贝。"
}
```

Field constraints:

- `encouragement`
  - 8-30 Chinese characters.
  - Must be positive and encouraging.
- `highlight`
  - 10-60 Chinese characters.
  - Points out one concrete strength in the child's answer.
  - May quote a short fragment from the child's answer, up to 20 Chinese characters.
- `suggestion`
  - 10-60 Chinese characters.
  - Gives one next-step suggestion only.
  - Must not stack multiple criticisms.
- `example_upgrade`
  - 10-80 Chinese characters.
  - Provides one upgraded example.
  - Must not become a full essay paragraph.

Ability deltas and settlement metadata for generated challenges come from deterministic backend rules based on `target_skill`. The short AI feedback contract is for child guidance, not for scoring.

## LLM Infrastructure

### LLMCallLog

Add fields:

- `prompt_key`
- `prompt_tokens`
- `completion_tokens`
- `total_tokens`
- `estimated_cost`
- `latency_ms`

`prompt_version` remains, but it should come from Prompt Registry instead of scattered defaults at individual call sites.

Cost estimation is configuration-based:

```text
LLM_INPUT_COST_PER_1K_TOKENS=0
LLM_OUTPUT_COST_PER_1K_TOKENS=0
```

Defaults are zero so unknown model pricing does not produce misleading numbers. The HTTP provider reads OpenAI-compatible `usage` when available. Mock responses and non-calling fallback paths may log zero tokens and zero cost.

Logging rules:

- Log successful LLM calls.
- Log validation failures and provider failures.
- Log daily-limit fallbacks.
- Keep `input_summary` privacy-safe and do not store full child writing text there.
- Keep Admin cost views aggregate-only; do not expose raw responses in Admin.

### LLM Usage Guardrail

V0.5b must include guardrails that limit how many real LLM calls a student can trigger per day for the new sentence challenge loop.

Settings:

```text
SENTENCE_CHALLENGE_DAILY_LIMIT_PER_STUDENT=10
SENTENCE_FEEDBACK_DAILY_LIMIT_PER_STUDENT=10
LLM_DAILY_LIMIT_TIMEZONE=Asia/Shanghai
```

Challenge generation rules:

- Each student can trigger at most 10 real AI challenge generation calls per day.
- Local fallback challenge generation does not consume LLM quota.
- If the provider is called and then fails, record the failed LLM call in `LLMCallLog`.
- Only actual provider calls count as LLM usage.
- When the limit is reached, do not call the provider; return a controlled response that lets the frontend show:

```text
今天的句子挑战已经完成很多啦，休息一下，明天继续闯关！
```

Challenge feedback rules:

- Each student can trigger at most 10 real AI challenge feedback calls per day.
- Local fallback feedback does not consume LLM quota.
- If the provider call fails after it was started, record the failed call.
- Failed provider calls count toward operational usage, but do not need to count as successful feedback completions.
- The training can still complete with fallback feedback unless request validation or auth fails.

ProductEvent on limit:

```text
event_type = ai_daily_limit_reached
payload = {
  "target_type": "student",
  "target_id": "<student_id>",
  "task_type": "sentence_challenge_generation" | "sentence_feedback",
  "limit_type": "daily_per_student",
  "status": "blocked"
}
```

Use `target_id` in payload rather than duplicating `student_id`, matching the existing safe payload convention.

Daily limit date boundary:

```text
LLM_DAILY_LIMIT_TIMEZONE=Asia/Shanghai
```

Daily limits use the configured deployment/user-facing product timezone. The V0.5b default is `Asia/Shanghai` for Chinese Alpha families, so the child's "today" matches the product experience rather than raw UTC database time.

### Prompt Registry

Add a code-level registry under:

```text
apps/api/app/prompts/
  registry.py
  system.py
  sentence_feedback.py
  essay_feedback.py
  revision_feedback.py
  sentence_challenge.py
```

Registry records should expose:

- `prompt_key`
- `version`
- system prompt or system prompt key
- response contract
- optional task-specific template helpers

V0.5b migrates only the real tasks used by current learning flows:

- `sentence_upgrade_feedback`
- `essay_feedback`
- `essay_revision_comparison`
- `sentence_challenge_generation`
- `sentence_challenge_feedback`

Existing reserved pre-writing tasks such as `material_questions` and `outline_generation` can remain compatible without being part of this migration.

## Frontend Design

### Child Sentence Workshop

The sentence workshop defaults to AI-generated challenge mode.

Initial state:

- Request a challenge for the current child.
- Show the challenge type/goal, source sentence, and hint.
- Provide a single answer box for the child's upgraded sentence.

Completion state:

- Show the short AI challenge feedback structure: encouragement, highlight, suggestion, and example upgrade.
- Show feedback reaction.
- Show XP/settlement panel.
- Provide "再挑战一题".
- Provide "自己带句子来练".
- Keep navigation back to dashboard and parent report.

Free-input mode:

- Lets the child enter both source and upgraded sentence.
- Uses the existing endpoint.
- Remains a secondary mode rather than the default.

### Admin Lite

Admin stays a single lightweight tool, but the page is grouped to avoid piling new controls into one long surface.

Groups:

- Alpha 总览
- 邀请管理
- 账号管理
- AI 使用量

Tabs or clear sections are both acceptable. The implementation should choose whichever fits the current Admin component with the least churn.

AI 使用量 displays aggregate rows by date, task type, and model:

- call count
- prompt tokens
- completion tokens
- total tokens
- estimated cost
- failure count
- daily limit hit count

Invite management:

- Default-hide or fold `revoked` invites.
- Add a control to show revoked invites.
- Do not delete invites.
- Do not add expiration in V0.5b.

## Parent Summary

Parent summary lightly incorporates completed sentence training.

Expected behavior:

- Count completed sentence training sessions.
- Optionally show the latest completed training type or status.
- Do not show source sentence, child rewritten sentence, or raw AI response.
- Do not add a new parent summary LLM call in V0.5b.

This keeps the parent informed about practice momentum without increasing the privacy surface.

Example product copy:

```text
本周完成 3 次句子挑战，主要练习了“动作描写”和“扩句”。
```

## Product Events

V0.5b should keep ProductEvent payloads privacy-safe.

Events to support or reuse:

- `sentence_challenge_generated`
- `sentence_challenge_completed`
- `sentence_challenge_feedback_failed`
- `ai_daily_limit_reached`

Payloads should use safe keys such as:

- `target_type`
- `target_id`
- `task_type`
- `status`
- `target_skill`
- `error_category`
- `limit_type`

No child writing text, raw prompt, raw response, email, phone, or invite code value should be stored in ProductEvent payloads.

## Error Handling

- AI generation failure: use local fallback challenge, log failure, and keep the child flow available.
- AI feedback failure: use short fallback feedback; completion still succeeds unless the request itself is invalid.
- Daily limit reached: do not call the provider, record `ai_daily_limit_reached`, and return a controlled response for the frontend rest message.
- Invalid or missing training row: return 404.
- Cross-family training access: return 404.
- Already-completed challenge: return 409.
- Invalid answer length or empty answer: return validation error.
- Admin usage summary should return empty aggregates when there are no logs.

## Security and Privacy

- Existing auth/session guards continue to protect learning endpoints.
- New state-changing endpoints must use the same JSON-only and Origin/Referer guard path as existing Alpha learning writes.
- Prompt Registry stores templates and contracts only, not student inputs.
- `LLMCallLog.input_summary` remains summary-only.
- Admin AI usage is aggregate-only and must not expose raw responses or child writing text.
- `MAGIC_CODE_DEV_ECHO=true` remains allowed only for internal QA in `ENVIRONMENT=development`.
- Startup must fail fast when `ENVIRONMENT` is `staging` or `production` and `MAGIC_CODE_DEV_ECHO=true`.
- External Alpha invitations require verified Resend email delivery.
- `docs/alpha-deploy.md` must clearly say Dev Echo is not real email delivery and is not suitable for broader external Alpha invitation.

## Acceptance Criteria

- Every real LLM task in scope records `prompt_key` and `prompt_version`.
- LLM logs record tokens, latency, and estimated cost when provider data/config is available.
- Prompt Registry owns the in-scope prompt keys and versions.
- Resend email sender can deliver real Magic Code email from a verified domain.
- Dev Echo startup guard fails fast in staging/production.
- Daily per-student limits prevent unbounded sentence challenge generation and feedback calls.
- Sentence workshop defaults to AI-generated challenges.
- Generated challenges are persisted before completion.
- Completed challenges update the same `SentenceTraining` row, show short child-facing feedback, and settle XP once.
- The old free-input sentence training path remains usable.
- Admin can view aggregate AI usage/cost and daily limit hits.
- Admin invite management no longer shows revoked invites by default.
- Parent summary lightly reflects completed sentence training without showing child text.
- `docs/alpha-deploy.md` documents Resend, Dev Echo meaning, guard behavior, and email readiness gates.
- Existing invite, assessment, essay, revision, reaction, summary, admin, and demo flows continue to pass relevant tests.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| AI generation quality is uneven | Fixed challenge types, strict schema, and local fallback templates |
| LLM cost or usage grows unexpectedly | Token/cost logging, Admin aggregate usage view, and daily per-student LLM limits |
| Email provider setup is delayed by domain verification | Dev Echo remains development-only for internal QA; external Alpha stays blocked until real delivery is verified |
| Prompt Registry grows too abstract | Code-level registry only; no DB, UI, or A/B framework |
| Admin page becomes cluttered | Same-page grouping, not Admin v2 |
| Generated-but-uncompleted rows accumulate | Accept for Alpha; use status and timestamps for future cleanup or derived abandonment |
| Dev Echo is mistaken for production auth | Explicit `ENVIRONMENT` guard fails startup in staging/production, plus deployment docs |
