# WenLingo V0.5b AI Infrastructure + Sentence Training Design

Date: 2026-06-08
Status: Draft for user review
Source review: `reviews/2026-06-08-v0.5a-series-post-implementation-review.md`

## Goal

V0.5b establishes the AI infrastructure needed before larger LLM-powered product work, then ships a thin vertical slice of AI-generated sentence training by extending the existing sentence workshop.

The intended learning loop is:

```text
AI generates a sentence challenge
-> child rewrites the sentence
-> AI gives structured feedback
-> ability and XP update
-> parent summary records lightweight progress
-> admin can see aggregate AI usage and cost
```

This version keeps the current Alpha identity/session foundation intact. It does not begin Writing Castle or a full sentence curriculum.

## Scope

### In Scope

- Extend `LLMCallLog` with prompt key, token usage, latency, and estimated cost fields.
- Add code-level Prompt Registry for real production LLM tasks used by the current product.
- Extend existing `SentenceTraining` so generated sentence challenges are stored before completion.
- Add an AI challenge generation endpoint and a challenge completion endpoint.
- Keep the existing free-input sentence endpoint compatible.
- Make the child sentence workshop default to AI-generated challenges.
- Keep a "bring your own sentence" mode for the existing free-input flow.
- Add Admin Lite grouping and a minimal AI usage/cost view.
- Default-hide or fold revoked invites in Admin, with a control to show them.
- Lightly include completed sentence training in parent summary.
- Update `docs/alpha-deploy.md` to explain `MAGIC_CODE_DEV_ECHO=true`, its intended internal-use boundary, and its risk.

### Out of Scope

- HTTPS email provider integration.
- Production startup guard for `MAGIC_CODE_DEV_ECHO=true`.
- Writing Castle or pre-writing flow.
- Admin prompt editor.
- Prompt A/B testing.
- Full Admin v2.
- Invite expiration or hard deletion.
- A complete sentence-training curriculum or large题库.

Email delivery and production-grade Dev Echo protection are deferred to a dedicated future version. During V0.5b, the Alpha cohort remains a small trusted internal group that can use Dev Echo code `123456`.

## Product Decisions

- V0.5b extends the existing sentence workshop instead of creating a parallel training engine.
- AI challenge generation uses fixed task templates plus AI-generated challenge content.
- If AI challenge generation fails, the backend uses local fallback challenge templates.
- The thin slice includes three challenge types:
  - `expand_sentence`: 扩句
  - `action_expression`: 加动作/神态
  - `feeling`: 加心理感受
- Generated challenges are persisted immediately.
- The challenge state machine is intentionally small: `generated` -> `completed`.
- Parent summary records training progress but does not display child sentence text.

## Backend Design

### SentenceTraining Model

`SentenceTraining` remains the canonical table for sentence practice. V0.5b extends it so one row can represent both a generated challenge and the later completed answer.

New fields:

- `status`: `generated` or `completed`
- `challenge_prompt`: child-facing task instruction
- `hint`: short child-facing hint
- `target_skill`: stable challenge type key
- `completed_at`: timestamp set when the child completes the challenge

Existing fields keep their meaning with small extensions:

- `source_sentence`: stores the AI-generated or fallback source sentence.
- `upgraded_sentence`: empty or nullable while generated, filled on completion.
- `focus`: stores the Chinese display focus already used by current sentence feedback.
- `ai_feedback`: empty while generated, filled on completion.

Generated-but-not-completed rows remain useful for future funnel analysis. V0.5b does not add `skipped`, `abandoned`, or `expired`; those can be derived later by age if needed.

### API Endpoints

New endpoint:

```text
POST /api/students/{student_id}/sentence-challenges
```

Behavior:

- Requires the same auth-mode state-change guard as other student learning writes.
- Verifies the student belongs to the authenticated family.
- Selects one of the three supported challenge types.
- Calls `sentence_challenge_generation` through the LLM task runner.
- Validates the AI output against a strict schema.
- Falls back to a local template if the AI call or validation fails.
- Creates a `SentenceTraining` row with `status="generated"`.
- Returns the challenge id, source sentence, challenge prompt, hint, focus, and target skill.

New endpoint:

```text
POST /api/students/{student_id}/sentences/{training_id}/complete
```

Behavior:

- Requires the same auth-mode state-change guard.
- Verifies the student and training row belong to the authenticated family.
- Rejects already-completed challenges with `409`.
- Accepts the child's upgraded sentence.
- Calls the existing sentence feedback flow.
- Updates the same `SentenceTraining` row with the answer, feedback, `completed_at`, and `status="completed"`.
- Applies ability delta and XP settlement using the existing sentence training behavior.
- Records a product event for completion.
- Returns the updated training row, AI feedback, settlement, and next task.

Existing endpoint:

```text
POST /api/students/{student_id}/sentences
```

The current free-input sentence practice endpoint remains compatible. It should gain the same prompt registry and logging improvements, but its external behavior should not change except where needed for the new model defaults.

### AI Challenge Generation

The AI challenge generator must not generate child answers or full model rewrites. It only returns:

- `source_sentence`
- `challenge_prompt`
- `hint`
- `target_skill`
- `focus`

Fallback templates provide safe local challenges for each supported type. A fallback challenge still creates a normal `SentenceTraining` row so the child experience does not fail just because the model did.

## LLM Infrastructure

### LLMCallLog

Add fields:

- `prompt_key`
- `prompt_tokens`
- `completion_tokens`
- `total_tokens`
- `estimated_cost`
- `latency_ms`

`prompt_version` remains, but it should come from Prompt Registry instead of scattered defaults at individual call sites.

Cost estimation is configuration-based:

```text
LLM_INPUT_COST_PER_1K_TOKENS=0
LLM_OUTPUT_COST_PER_1K_TOKENS=0
```

Defaults are zero so unknown model pricing does not produce misleading numbers. The HTTP provider reads OpenAI-compatible `usage` when available. Mock responses and non-calling fallback paths may log zero tokens and zero cost.

Logging rules:

- Log successful LLM calls.
- Log validation failures and provider failures.
- Log daily-limit fallbacks.
- Keep `input_summary` privacy-safe and do not store full child writing text there.
- Keep Admin cost views aggregate-only; do not expose raw responses in Admin.

### Prompt Registry

Add a code-level registry under:

```text
apps/api/app/prompts/
  registry.py
  system.py
  sentence_feedback.py
  essay_feedback.py
  revision_feedback.py
  sentence_challenge.py
```

Registry records should expose:

- `prompt_key`
- `version`
- system prompt or system prompt key
- response contract
- optional task-specific template helpers

V0.5b migrates only the real tasks used by current learning flows:

- `sentence_upgrade_feedback`
- `essay_feedback`
- `essay_revision_comparison`
- `sentence_challenge_generation`

Existing reserved pre-writing tasks such as `material_questions` and `outline_generation` can remain compatible without being part of this migration.

## Frontend Design

### Child Sentence Workshop

The sentence workshop defaults to AI-generated challenge mode.

Initial state:

- Request a challenge for the current child.
- Show the challenge type/goal, source sentence, and hint.
- Provide a single answer box for the child's upgraded sentence.

Completion state:

- Show existing AI coach feedback structure.
- Show feedback reaction.
- Show XP/settlement panel.
- Provide "再挑战一题".
- Provide "自己带句子来练".
- Keep navigation back to dashboard and parent report.

Free-input mode:

- Lets the child enter both source and upgraded sentence.
- Uses the existing endpoint.
- Remains a secondary mode rather than the default.

### Admin Lite

Admin stays a single lightweight tool, but the page is grouped to avoid piling new controls into one long surface.

Groups:

- Alpha 总览
- 邀请管理
- 账号管理
- AI 使用量

Tabs or clear sections are both acceptable. The implementation should choose whichever fits the current Admin component with the least churn.

AI 使用量 displays aggregate rows by date, task type, and model:

- call count
- prompt tokens
- completion tokens
- total tokens
- estimated cost
- failure count

Invite management:

- Default-hide or fold `revoked` invites.
- Add a control to show revoked invites.
- Do not delete invites.
- Do not add expiration in V0.5b.

## Parent Summary

Parent summary lightly incorporates completed sentence training.

Expected behavior:

- Count completed sentence training sessions.
- Optionally show the latest completed training type or status.
- Do not show source sentence, child rewritten sentence, or raw AI response.

This keeps the parent informed about practice momentum without increasing the privacy surface.

## Product Events

V0.5b should keep ProductEvent payloads privacy-safe.

Events to support or reuse:

- challenge generated
- sentence training completed
- AI feedback failed

Payloads should use safe keys such as:

- `target_type`
- `target_id`
- `task_type`
- `status`
- `target_skill`
- `error_category`

No child writing text, raw prompt, raw response, email, phone, or invite code value should be stored in ProductEvent payloads.

## Error Handling

- AI generation failure: use local fallback challenge, log failure, and keep the child flow available.
- AI feedback failure: use existing fallback feedback; completion still succeeds unless the request itself is invalid.
- Invalid or missing training row: return 404.
- Cross-family training access: return 404.
- Already-completed challenge: return 409.
- Invalid answer length or empty answer: return validation error.
- Admin usage summary should return empty aggregates when there are no logs.

## Security and Privacy

- Existing auth/session guards continue to protect learning endpoints.
- New state-changing endpoints must use the same JSON-only and Origin/Referer guard path as existing Alpha learning writes.
- Prompt Registry stores templates and contracts only, not student inputs.
- `LLMCallLog.input_summary` remains summary-only.
- Admin AI usage is aggregate-only and must not expose raw responses or child writing text.
- `MAGIC_CODE_DEV_ECHO=true` remains allowed for the small trusted internal Alpha cohort in V0.5b.
- `docs/alpha-deploy.md` must clearly say Dev Echo is not real email delivery and is not suitable for broader external Alpha invitation.

## Acceptance Criteria

- Every real LLM task in scope records `prompt_key` and `prompt_version`.
- LLM logs record tokens, latency, and estimated cost when provider data/config is available.
- Prompt Registry owns the in-scope prompt keys and versions.
- Sentence workshop defaults to AI-generated challenges.
- Generated challenges are persisted before completion.
- Completed challenges update the same `SentenceTraining` row and settle XP once.
- The old free-input sentence training path remains usable.
- Admin can view aggregate AI usage/cost.
- Admin invite management no longer shows revoked invites by default.
- Parent summary lightly reflects completed sentence training without showing child text.
- `docs/alpha-deploy.md` documents Dev Echo meaning and risk.
- Existing invite, assessment, essay, revision, reaction, summary, admin, and demo flows continue to pass relevant tests.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| AI generation quality is uneven | Fixed challenge types, strict schema, and local fallback templates |
| LLM cost remains unclear | Token/cost logging and Admin aggregate usage view before expanding AI features |
| Prompt Registry grows too abstract | Code-level registry only; no DB, UI, or A/B framework |
| Admin page becomes cluttered | Same-page grouping, not Admin v2 |
| Generated-but-uncompleted rows accumulate | Accept for Alpha; use status and timestamps for future cleanup or derived abandonment |
| Dev Echo is mistaken for production auth | Document meaning, internal-only boundary, and future email provider gate in `alpha-deploy.md` |
