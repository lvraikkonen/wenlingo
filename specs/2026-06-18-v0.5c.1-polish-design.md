Status: Approved by Claus

## Goal

V0.5c.1 is the cleanup and external-Alpha unblocker after V0.5c AI Platform Foundation.

The release goal is:

```text
Clear V0.5c platform debt and remove the browser/session/navigation blockers
before inviting broader external Alpha families.
```

V0.5c core Dev QA passed after hotfix `eac30c1`, and QA document commit `f536e57`
recorded the manual verification. The remaining work is not a new learning feature
release. It makes the current Alpha product reliable enough for privacy-stricter
browsers, concurrent usage, and family navigation.

## Non-Goals

V0.5c.1 must not include:

- New AI learning task types.
- V0.6 Writing Castle prompt content.
- Streaming or SSE.
- Dynamic model selection, A/B testing, or automatic model routing.
- Plugin systems or policy engines.
- Admin charts, exports, filters, scheduled reports, or daily digests.
- Frontend framework upgrades or broad visual redesign.
- New gamification systems.

## Release Boundary

V0.5c.1 uses the complete cleanup option, but with clear gates.

### P0: Must Ship Before Broader External Alpha

P0 items address issues observed in QA or risks left by V0.5c implementation.

1. Same-origin API proxy for browser API traffic.
2. Frontend auth failure UX that distinguishes Magic Code failure, missing session,
   and unlinked-account states.
3. Atomic daily-limit reservation or counter semantics.
4. Page-level navigation polish for the core child, parent, and Admin paths.

### P1: Complete In V0.5c.1 Unless It Breaks The P0 Gate

These are V0.5c roadmap polish items. They should be completed in V0.5c.1, but
each item must stay small and behaviorally scoped.

1. Admin model usage dashboard polish beyond the minimal P0 table.
2. Prompt Registry naming cleanup and legacy fallback cleanup.
3. Sentence Workshop `AIInteractionState`.
4. Behavior-preserving split of `admin_alpha.py`.
5. Parent summary one-line copy improvement.
6. localStorage identity cleanup Step 3.
7. `qa/smoke-checklist-template.md`.

If a P1 item exceeds a half-day estimate and does not unblock external Alpha, split
it or explicitly defer it rather than delaying P0 release validation.

### P2: Documentation And Verification Cleanup

1. Update the roadmap to mark V0.5c core complete and V0.5c.1 planned.
2. Update deployment docs for the same-origin API proxy and cookie settings.

   navigation.
4. Confirm no V0.6 prompts, new AI tasks, dynamic routing, or Admin advanced

## Architecture

V0.5c.1 keeps the existing Next.js web app and FastAPI API split. The visible
browser origin changes: external Alpha browser traffic should call API routes under
the web origin.

```text
Browser
-> https://wenlingo-web.../api/*
-> Next.js rewrite/proxy
-> Railway API service /api/*
```

The API service remains the owner of auth, sessions, AI execution, daily limits,
and persistence. The web service only proxies browser API calls and renders the
current product flows.

### Same-Origin API Proxy

Current V0.5c Railway Dev uses separate browser-visible hosts:

```text
wenlingo-web-production.up.railway.app
wenlingo-api-production.up.railway.app
```

That shape can fail in Chrome Incognito, Safari, and mobile browsers because the
session cookie set by the API host may be treated as a third-party or cross-site
cookie. V0.5c.1 should make browser API traffic same-origin by default.

Design requirements:

- Add an explicit web proxy/rewrite for `/api/*`.
- Make the frontend API client default to same-origin API calls.
- Keep an override for local development or controlled direct-API testing.
- Update deployment docs so external Alpha uses same-origin proxy as the
  recommended topology.
- Use `AUTH_SESSION_COOKIE_SAMESITE=lax` for same-origin deployment unless a
  direct cross-site fallback is intentionally being tested.
- Do not depend on custom domains as the only fix. Custom domains may help, but
  same-origin proxy is the strongest Alpha path.

Implementation requirements:

- Frontend browser API base defaults to relative `/api` calls, not the API
  service's absolute public URL.
- The proxy target comes only from server-side environment, for example
  `API_PROXY_TARGET`. It must not come from request parameters, to avoid an open
  proxy or SSRF surface.
- The proxy forwards method, path, query string, body, content type, and necessary
  authorization/cookie headers.
- The proxy preserves API `Set-Cookie` responses.
- Same-origin Alpha session cookies are `HttpOnly`, `Secure`, `SameSite=Lax`,
  `Path=/`, and omit `Domain` so the browser stores them on the web origin.
- Direct API testing may still use cross-site cookie settings, but external Alpha
  should not depend on direct browser calls to the API service.
- If `NEXT_PUBLIC_API_BASE_URL` remains supported, the external Alpha value should
  be empty or `/api`, not the API service's absolute URL.

### Auth Failure UX

The Alpha start page must not silently reset to the default create-family form when
Magic Code verification succeeds but the session is unavailable afterward.

Auth UX states:

- Magic Code invalid or expired: stay in the code-entry state and show a code
  error.
- Session unavailable after verification: show a clear login/session message and
  offer retry, rather than switching to create-family mode.
- Existing account with no linked Alpha family: keep the current unlinked-account
  message and creation path.
- Disabled account: keep the current disabled-account message.

This UX is still needed after the proxy fix because it gives operators a clear
signal if cookie or deployment settings regress later.

Alpha start should model auth as explicit UI states:

```text
enter_email
enter_code
verifying_code
code_error
session_unavailable
unlinked_account
disabled_account
authenticated_redirecting
```

State behavior:

- Magic Code verification failure keeps the user in `enter_code` or `code_error`.
- Magic Code verification success followed by missing session enters
  `session_unavailable`, and does not switch back to create-family mode.
- Existing account with no linked family enters `unlinked_account`, where the
  create-family path remains visible.
- Disabled account enters `disabled_account`, and cannot continue into family
  creation.
- Valid linked account enters `authenticated_redirecting`.

### Atomic Daily Limit

V0.5c currently checks successful `LLMCallLog` rows before writing the task log.
That check-then-write pattern is not safe under concurrent requests. V0.5c.1 moves
daily-limit enforcement to a database-backed reservation or counter.

Target flow:

```text
resolve task config
-> atomically reserve one slot for student_id + task_name + product_day
-> if no slot is available: skip provider call and return daily_limit_reached
-> if a user-visible output is produced: consume the reservation
-> if the task fails before user-visible output: release or mark the reservation failed
-> write LLMCallLog for observability
```

Requirements:

- `LLMCallLog` remains the Admin and QA observability record.
- Daily-limit accounting no longer relies only on counting previous log rows.
- The product day is based on `settings.llm_daily_limit_timezone`.
- Switching provider or model cannot bypass the task limit.
- Failed provider tasks do not consume product daily limit.
- A `daily_limit_reached` result creates no provider call.
- If two concurrent requests race for the final slot, at most one receives a
  user-visible AI output.

Preferred implementation is a small `DailyTaskLimitCounter` or
`AIDailyTaskUsage` table:

```text
student_id
task_name
product_day
limit_value
reserved_count
consumed_count
failed_count
released_count
reservation_expires_at
updated_at
```

Reserve flow:

```text
if reserved_count + consumed_count < limit:
  reserved_count += 1
else:
  return daily_limit_reached
```

Success flow:

```text
reserved_count -= 1
consumed_count += 1
```

Failure before user-visible output:

```text
reserved_count -= 1
failed_count += 1
```

The design allows an equivalent row-lock or conditional-update implementation, but
the implementation plan should start from the counter table unless there is a
clearer local pattern. Add stale reservation handling through
`reservation_expires_at` or a cleanup step so an interrupted request cannot
permanently consume a child's daily slot.

### Navigation Polish

Navigation polish is a reachability improvement, not a redesign.

Rules:

- Dashboard remains the child hub.
- Parent children page remains the parent hub.
- Every child task page has visible links back to Dashboard and the parent hub.
- Completed task states include next-step links so the user does not need browser
  Back/Forward.
- Reading Canyon remains a construction state, but it must provide a clear route
  back to Dashboard and parent hub.
- Parent summary and parent report link back to the child Dashboard and child list.
- Admin Alpha can remain a single page, but its main sections must be scannable and
  reachable without relying on browser history.

The scope is limited to existing pages:

| Page | Required links or controls |
|---|---|
| `/alpha/start` | existing-account/create-family mode controls, retry after session failure |
| `/parent/children` | child dashboard, create child |
| `/parent/children/new` | parent children list, created child dashboard after success |
| `/children/[studentId]` | parent children list, sentence, essay, assessment, reading construction state |
| `/children/[studentId]/assessment` | child dashboard, parent children list, next step after completion |
| `/children/[studentId]/sentence` | child dashboard, parent children list, summary/report after completion |
| `/children/[studentId]/essay` | child dashboard, parent children list |
| `/children/[studentId]/reading` | child dashboard, parent children list |
| `/parent/children/[studentId]/summary` | child dashboard, parent children list |
| `/parent/[studentId]/report` | child dashboard, parent children list |
| `/admin/alpha` | overview, invites, accounts, AI usage anchors or equivalent section controls |

### Sentence Workshop AIInteractionState

Sentence Workshop should use a local interaction state for AI calls:

```text
idle -> generating -> validating -> fallback -> completed -> failed
```

This is local to Sentence Workshop. It must not introduce a global state library
or change all task pages. The goal is consistent loading, fallback, failure, and
next-step UI behavior.

### Prompt Registry Cleanup

Prompt cleanup is restricted to naming and legacy cleanup.

Requirements:

- Define and document prompt key naming conventions.
- Remove legacy prompt fallback constants where they are no longer required.
- Confirm all production AI tasks resolve prompts through the Prompt Registry.
- Reserve V0.6 task names only as disabled placeholders if useful.
- Do not add V0.6 prompt content.

### Admin Cleanup

Admin cleanup has two parts.

Admin model usage polish:

- Make the existing task/model/provider/fallback/cost table easier to read.
- Keep it as a table.
- Do not add charts, filters, export, scheduled reports, or digests.

`admin_alpha.py` split:

- Split into focused route modules for overview, invites, accounts, and AI usage,
  or an equivalent local structure.
- Preserve endpoint paths, response schemas, permissions, and privacy boundaries.
- Add or keep tests that prove behavior is unchanged.

### Parent Summary Copy

Add one lightweight sentence that helps parents understand recent sentence practice,
for example:

```text
本周小Q完成了 X 次练习，主要在练“把句子写具体”。
```

This is not a full weekly report. It should reuse existing persisted counts and
focus labels.

### localStorage Identity Cleanup Step 3

V0.5b.1 stopped new writes and moved runtime pages to session-aware APIs. V0.5c.1
should finish the cleanup:

- Remove `alphaParent.ts` read/write functions if no runtime dependency remains.
- Remove related tests or rewrite them around session behavior.
- Keep legacy migration behavior only if explicitly still needed, with tests.
- Verify fresh login and create-family flows do not write
  `wenlingo_alpha_parent_id`.

## Error Handling

Child-facing AI errors remain encouraging and non-technical.

- Daily limit reached: show the existing rest message.
- Provider failure with deterministic fallback: show normal fallback content.
- Provider/fallback failure without safe output: show child-friendly retry/rest
  message.
- Session unavailable: show clear login/session guidance.
- Admin can see operational details; children and parents cannot see provider names,
  model names, stack traces, prompts, raw child writing, or raw responses.

## Testing Strategy

V0.5c.1 should use TDD whenever practical.

### Backend Tests

Add or update tests for:

- Daily-limit reservation/counter allows one request and blocks the next at limit.
- Concurrent limit=1 semantics: two racing requests cannot both produce
  user-visible output.
- Daily-limit hit creates no provider call.
- Provider failure before output does not consume product daily limit.
- Admin AI usage still counts success, fallback, failures, and limit hits.
- `admin_alpha.py` split preserves endpoint paths and response schemas.

### Frontend Tests

Add or update tests for:

- API client defaults to same-origin calls, with env override still supported.
- Magic Code verification followed by missing session shows a session-specific
  message instead of resetting to create-family mode.
- Core pages expose visible links back to Dashboard and/or parent child list.
- Sentence Workshop state transitions cover loading, fallback, completed, failed,
  and daily-limit states.
- localStorage identity key is not written during fresh login or create-family
  flows.

### E2E And Manual QA

Automated E2E should cover at least:

- Magic Code login.
- Parent children page load after login.
- Sentence challenge complete flow.
- Navigation from sentence completion to Dashboard and parent summary/report.

Manual QA must include:

- Chrome normal login.
- Chrome Incognito login.
- Safari or mobile browser login.
- Refreshing `/parent/children` after login.
- Core page navigation without browser Back/Forward.
- Daily-limit smoke.
- Daily-limit concurrency smoke if practical in Dev.
- Admin privacy boundary check.
- Real email delivery smoke before external family invitations if Dev Echo is
  disabled.

## Acceptance Criteria

- Chrome normal, Chrome Incognito, Safari or mobile browser can complete Magic
  Code login and stay authenticated on `/parent/children`.
- Frontend auth failures show specific session/login messaging.
- Browser API traffic for external Alpha uses the web origin by default.
- Concurrent daily-limit requests cannot both pass a one-call limit for the same
  `student_id + task_name + product_day`.
- Daily-limit hits create no provider call.
- Failed AI tasks do not consume product daily limit.
- Core pages provide visible in-app navigation without relying on browser
  Back/Forward.
- Sentence Workshop uses local `AIInteractionState`.
- Admin AI usage table remains privacy-safe and easier to scan.
- Prompt Registry remains the only legal prompt source for production AI tasks.
- `admin_alpha.py` split preserves all existing behavior.
- `wenlingo_alpha_parent_id` is no longer a runtime identity dependency.
- QA smoke checklist template exists.
- No V0.6 prompt content, new AI task type, dynamic routing, or Admin advanced
  reporting is introduced.
