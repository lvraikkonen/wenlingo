# WenLingo V0.6c Topic Breadth + AI Topic Thin Slice Design

Date: 2026-06-29

Status: Accepted in brainstorming; ready for user review before implementation planning

## 1. Summary

V0.6c is a topic-breadth release for Writing Castle. Its first job is to make
classroom-aligned composition credible across more 3-6 grade assignment types.
Its second job is to unlock the smallest useful AI-generated topic path without
turning this release into a recommendation system or topic-bank project.

The release keeps the V0.6b architecture:

```text
TopicType -> ScaffoldTemplate -> SourceChain -> QA Matrix
```

P0 adds four visible scaffold families:

- `place_scenery`
- `animal_object_observation`
- `practical_writing`
- `story_adaptation`

P0 also adds an AI topic path:

```text
interest + grade_label -> 3 topic ideas -> child selects one -> existing prewriting flow
```

Each AI topic idea must map to a currently supported scaffold. The system must
not generate essay body text or decide the child's specific content.

## 3. Decisions From Brainstorming

- V0.6c is topic-breadth first. AI topic composition is a thin slice.
- `story_adaptation` is P0. `story_summary` remains unsupported and moves to
  V0.7/backlog.
- AI topic generation uses interest + grade context and returns exactly 3 topic
  ideas.
- AI topic generation has no deterministic topic fallback. On failure, the child
  sees a friendly retry or later path.
- Each new scaffold family gets one default template plus key textbook
  variants/aliases.
- `reading_response_recommendation` and `central_idea_reflection` get design
  spike documents only. They are not product-visible in V0.6c.
- Essay archive, multi-round revision, and delete/hide behavior move to V0.6c.1
  and must not expand V0.6c.

## 4. Product Goal

The child should feel:

- "This scaffold understands this kind of assignment."
- "I can choose or confirm my own material."
- "AI can suggest a topic idea, but I still decide what to write."

The parent should see:

- The child worked inside an appropriate scaffold family.
- AI did not write copy-ready essay content.
- AI topic ideas are traceable to a supported topic type.

## 5. Non-Goals

V0.6c does not include:

- Token Streaming, Progress SSE, or LLMCallLog streaming fields.
- Full AI topic bank larger than 20 items.
- AI topic fallback from a hidden fixed bank.
- Profile-based intelligent recommendation.
- Recommendation optimization that narrows the child into an interest bubble.
- `story_summary` / 缩写故事 / 作品梗概 scaffold.
- Product-visible `reading_response_recommendation` or `central_idea_reflection`.
- Essay archive, multi-round revision, continue-editing, or delete/hide actions.
- Parent weekly report redesign.
- Database/admin template editor.

## 7. Scaffold Template Design

The backend remains the source of truth for templates. The frontend renders the
resolved scaffold snapshot and must not hardcode family-specific slot logic.

The JSON container shape does not need to change. New sessions may continue to
use the existing V0.6b.1 material/outline state schema if implementation does
not add fields. Each new template must still use a V0.6c
`scaffold_template_version`, for example:

```text
place_scenery.default.v0.6c
```

### `place_scenery`

Purpose: cover place description, scenery, travel writing, and place
recommendation.

Representative topics:

- 我的乐园
- 游____
- 这儿真美
- ____即景
- 推荐一个好地方

Default slots:

- place_subject: 地点是什么
- observation_order: 观察或游览顺序
- key_scene: 最重要的景物或画面
- sensory_detail: 颜色/声音/气味/动作等细节
- activity_or_experience: 我在那里做什么或经历什么
- feeling_reason: 感受或推荐理由

Key variants/aliases:

- `my_paradise`
- `travel_writing`
- `scene_description`
- `place_recommendation`

Source policy:

- allowed: `real_experience`, `observation`, `child_confirmed`
- required for content: `real_experience`, `observation`, `child_confirmed`

### `animal_object_observation`

Purpose: cover animal, plant, object, and observation diary assignments.

Representative topics:

- 我的植物朋友
- 我的动物朋友
- 我的心爱之物
- 写观察日记

Default slots:

- observation_subject: 观察对象
- appearance_detail: 样子/颜色/形状
- change_or_habit: 变化/习性/特点
- sensory_detail: 看到/听到/摸到/闻到的细节
- relationship_or_story: 我和它的故事或关系
- discovery_feeling: 发现或感受

Key variants/aliases:

- `plant_friend`
- `animal_friend`
- `beloved_object`
- `observation_diary`

Source policy:

- allowed: `observation`, `real_experience`, `child_confirmed`
- required for content: `observation`, `real_experience`, `child_confirmed`

### `practical_writing`

Purpose: cover format-based practical writing while preserving the child's own
message, position, and feelings.

Representative topics:

- 写日记
- 写信
- 我想对您说
- 学写倡议书

Default slots:

- format_type: 文体/格式
- audience_or_date: 对象或日期信息
- main_message: 最想表达的事情
- reason_or_background: 为什么要写
- specific_details: 具体事情或建议
- closing_or_call: 祝福/期待/号召

Key variants/aliases:

- `diary`
- `letter`
- `heartfelt_letter`
- `proposal`

Source policy:

- allowed: `topic_requirement`, `real_experience`, `observation`,
  `child_confirmed`
- required for content: `topic_requirement`, `child_confirmed`

Practical-writing templates may include format hints, but they must not compose
the child's message for them.

### `story_adaptation`

Purpose: cover continuation and adaptation from an existing story or provided
situation.

Representative topics:

- 续写故事
- 故事新编

Default slots:

- original_basis: 原故事或已有情境
- kept_elements: 保留的人物/设定
- change_point: 从哪里开始变化
- new_event: 接下来发生什么
- new_ending: 新结局
- new_meaning: 新故事想表达的意思

Key variants/aliases:

- `story_continuation`
- `story_rewrite`

Source policy:

- allowed: `topic_requirement`, `reading_material`, `imagined_setting`,
  `child_confirmed`
- required for content: `topic_requirement`, `reading_material`,
  `imagined_setting`, `child_confirmed`

`story_summary` remains unsupported in V0.6c. "缩写", "梗概", and similar topics
must continue to surface `unsupported_future_type = "story_summary"`.

## 8. AI Topic Generation

### Task Contract

Add a new prompt key:

```text
writing_topic_idea_generation
```

It must be registered through `register_prompt()` with:

- prompt key
- version
- response contract
- system prompt key

It must be routed through ModelRouter as a normal essay task. The recommended
initial routing is `cheap_fast` primary and `strong_default` fallback with a
short latency budget similar to `sentence_challenge_generation`.

The task input includes:

- `student.grade_label`
- child interest text or selected interest chips
- supported scaffold choices and allowed variants

The output must be exactly 3 topic ideas:

```json
{
  "ideas": [
    {
      "id": "idea-1",
      "title": "",
      "topic_type": "",
      "topic_variant": "",
      "why_it_fits_child_interest": "",
      "practice_focus": "",
      "child_safe_prompt": ""
    }
  ]
}
```

Server-side validation must reject:

- unsupported `topic_type`
- unsupported `topic_variant`
- duplicate idea ids
- empty titles
- titles or prompts that include copy-ready essay paragraphs
- ideas that decide a specific real event, person, feeling, lesson, or ending
  for the child

### User Flow

```text
Writing Castle mode shell
-> AI 出题作文
-> child enters/selects interest + backend reads grade_label
-> AI returns 3 ideas
-> child chooses one
-> backend creates a prewriting Essay
-> backend attaches scaffold snapshot from idea topic_type/topic_variant
-> existing topic analysis / material questions / cards / outline / draft flow
```

Generating topic ideas does not create an `Essay`. The `Essay` is created only
after the child selects one idea.

The selected idea should be traceable in ProductEvent payloads and in the
prewriting state as topic requirement metadata. It is a topic prompt, not essay
body content.

### Failure Behavior

If AI topic generation fails, times out, exceeds daily limit, or returns invalid
ideas:

- show child-friendly retry/later copy;
- keep classroom composition and direct draft available;
- do not provide hidden fallback topics;
- log the failed task in LLMCallLog.

## 9. Data And Observability

ProductEvent should record:

- `ai_topic_ideas_requested`
- `ai_topic_ideas_generated`
- `ai_topic_idea_selected`
- existing `scaffold_selected`

Payloads should include:

- `student_id`
- `essay_id` when created
- `interest_input_present`
- `grade_label`
- `idea_count`
- `selected_idea_id`
- `topic_type`
- `topic_variant`
- `scaffold_template_version`

LLMCallLog already has topic/scaffold metadata. The new AI topic task should use
the same logging path and include prompt key, prompt version, task name, final
status, fallback reason, latency, tokens, and cost where available.

Parent summary should continue to show:

- selected topic type
- selection source
- material sources
- AI body not generated

Parent summary copy for AI topic essays is P1. If implemented, it should
distinguish "AI 出题灵感" from "老师题目". A summary redesign is not part of
V0.6c.

## 10. Error Handling

- Existing direct draft must remain available and must not be scaffold-gated.
- Existing V0.6a/V0.6b open sessions must still resume or fail closed exactly as
  they do now.
- Scaffold changes remain blocked after topic analysis, child answers, material
  cards, or outline sections exist.
- Malformed persisted scaffold snapshots must fail closed with 409.
- Unsupported future types must not be silently coerced into supported families.
- `story_summary`, `reading_response_recommendation`, and
  `central_idea_reflection` remain visible unsupported categories unless a
  child/parent explicitly selects a supported fallback family.

## 13. V0.6c.1 Follow-Up: Essay Archive And Multi-Round Revision

Feedback from a colleague and the user's child showed that children and parents
want to see submitted first drafts, AI suggestions, second drafts, comparison
feedback, and later revision history. They also want continue-editing and delete
or hide operations.

This is important to the WenLingo learning loop because visible revision history
is evidence of growth. However, it should be its own release because it changes
history browsing, version semantics, delete policy, and parent-visible progress
data.

V0.6c records this as V0.6c.1 scope:

- essay archive/list entry;
- essay detail showing first draft, feedback, revision, comparison, and
  settlement;
- multi-round continue-revision policy;
- soft delete or hide policy;
- parent/child permissions and data-retention rules.

V0.6c must not implement these features.
