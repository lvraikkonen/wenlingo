# WenLingo V0.6a Writing Castle Prewriting Design

Date: 2026-06-20

Status: Approved for implementation planning

## 1. Summary

V0.6a upgrades Writing Castle from "AI comments on an existing draft" to
"AI helps a child get ready to write." The release focuses on one complete
path: classroom-aligned composition from a teacher's topic to a child-confirmed
outline, then into the existing draft feedback, revision, comparison, and
settlement loop.

The product success standard is not that AI produces better ideas. The success
standard is that a child who starts with a blank作文框 can move from topic to
first draft with less fear and more ownership.

Core flow:

```text
老师作文题目
-> 审题三卡
-> 孩子确认题目重点
-> 3 个选材问题
-> 3 类素材卡
-> 起因 / 经过 / 结果 / 感受提纲
-> 孩子确认或修改提纲
-> 初稿编辑
-> 现有 AI 点评 / 二稿 / 对比 / 结算
```

## 3. Product Goal

V0.6a validates the learning moment before the first draft:

- A fourth-grade child can understand what the teacher's topic asks.
- The child can recall at least one real event or detail.
- The child can see a small outline and start writing.
- The child remains the author of the material, outline choices, and draft.
- Parents can see that the child practiced prewriting, not that AI wrote for the
  child.

Primary success metric:

- Topic-to-outline completion rate for the classroom-aligned path.

Secondary observation metrics:

- Topic-to-first-draft completion rate.
- Step skip rates.
- Material card count retained by the child.
- Outline edit or confirmation rate.
- Existing draft feedback and revision completion rate after prewriting.

## 4. Non-Goals

V0.6a does not include:

- AI-generated full essays or copy-ready paragraphs.
- OCR handwriting input.
- Voice input.
- Multi-turn open chat.
- Complex drag-and-drop card editing.
- A full topic-type template system.
- A full AI-generated topic bank.
- Complete AI topic作文 mode.
- Complete free-writing mode beyond direct draft entry.
- Parent weekly report redesign.
- New gamification systems.
- New frontend framework or broad visual redesign.

## 5. Core Principle: AI Scaffolds, The Child Decides

V0.6a uses AI as a scaffold, not as the thinker of record.

Allowed AI behaviors:

- Break a teacher topic into short, child-readable prompts.
- Ask limited questions that help the child remember real experiences.
- Organize the child's own answers into editable cards.
- Point out missing pieces without inventing them.
- Suggest a short outline frame from confirmed cards.
- Provide child-friendly fallback hints when AI fails or the child skips.

Disallowed AI behaviors:

- Choosing a fictional event for the child.
- Inventing people, details, emotions, dialogue, or lessons the child did not
  provide.
- Producing full作文正文, full paragraphs, or copy-ready openings/endings.
- Turning a blank answer into a polished material card as if the child supplied
  it.
- Blocking the child from writing because a scaffold step is incomplete.

The rule for implementation and QA:

> Anything that can become作文内容 must come from child input or explicit child
> confirmation. AI may organize, label, and ask; it may not create the lived
> content.

## 6. Writing Castle Mode Shell

The Writing Castle page presents a light mode shell without expanding V0.6a
scope.

Modes:

- Classroom composition: complete V0.6a path and default primary action.
- AI topic作文: not actionable in V0.6a. If shown, it is a disabled `稍后开放`
  tile with no API path and no partial flow.
- Free writing: direct first-draft entry into the existing essay feedback loop.

The shell should make the classroom path feel like the main route. AI topic作文
and free writing should not create separate product expectations in V0.6a.

## 7. Classroom Composition Flow

### 7.1 Start From Teacher Topic

The child or parent enters the teacher's作文题目 or copied requirement text.

The input can include a short teacher requirement, but V0.6a treats it as one
topic text field. It does not need a separate import parser.

On start, the backend creates an `Essay` in `prewriting_started` status. No
`EssayVersion.first_draft` is created yet.

### 7.2 Topic Analysis / 审题三卡

AI returns three short cards:

- `题目在问什么`: one child-readable sentence.
- `一定要写到什么`: two to three must-include points.
- `可以写精彩的地方`: one to two optional focus ideas.

After seeing the cards, the child confirms or edits one sentence:

```text
我觉得这题最重要的是：____
```

The child can skip this confirmation and continue. If skipped, the system stores
the skip state and uses the original topic text for the next step.

Length guardrails:

- Each card should be short enough to scan on one screen.
- The tone is warm and direct, not a teacher lecture.
- No scoring, ranking, or intimidating terminology.

### 7.3 Material Questions / 选材三问

AI asks exactly 3 questions.

Question goals:

- Help the child recall a real event.
- Nudge for visible detail.
- Nudge for feeling or takeaway.

Each question supports:

- A short answer.
- An empty answer.
- A clear skip action.

There is no multi-turn follow-up in V0.6a. If the child gives little information,
the system continues instead of trapping the child in the question step.

### 7.4 Material Cards / 素材卡片

The system organizes child answers into 3 card categories:

- `事件`: what happened or what the composition is mainly about.
- `细节`: action, language, sound, image, or other concrete detail.
- `心情收获`: feeling at the time or what the child later learned.

Card rules:

- Cards are editable.
- Cards are deletable.
- Cards can move up and down.
- Drag-and-drop is out of scope.
- The UI always renders the three category slots: `事件`, `细节`, `心情收获`.
- Empty or weak answers produce empty slots or "you can add one sentence here"
  prompts, not invented content.

The child should be able to keep only the cards they want to write from.

### 7.5 Outline Generation / 提纲

The default outline structure is:

```text
起因 -> 经过 -> 结果 -> 感受
```

AI may suggest which confirmed material card fits each outline slot. If the
child uses the outline, the child must confirm or edit it before moving to
first-draft writing. The child may also skip the outline entirely and write
directly.

Outline constraints:

- Each section is a short phrase or bullet, not a paragraph.
- Each section can reference a material card.
- Empty sections are allowed.
- A child can skip the outline and write directly.
- Confirmed or edited outline content is carried into first-draft editing.

For non-narrative teacher topics, V0.6a still uses this default structure with
gentle copy. A full topic-type template system is deferred.

### 7.6 First Draft Editing

The first-draft editor shows the child-confirmed topic focus, material cards,
and outline as reference. It must not show copy-ready作文正文.

When the child submits a first draft, the existing essay feedback flow begins:

- Create `EssayVersion.first_draft`.
- Run existing `essay_feedback`.
- Set status to `revision_requested`.
- Show existing revision task UI.
- Preserve the existing revision, comparison, and settlement behavior.

## 8. Skip Behavior

Every prewriting step can be skipped.

Skip principles:

- Skipping is not failure.
- The child should never be stuck because one scaffold step is blank.
- Skip actions must be recorded for learning analytics.
- Skipped outputs should render as empty states or short prompts in later steps.

Recorded skip states:

- Topic analysis skipped.
- Topic focus confirmation skipped.
- Material questions skipped per question and for the step.
- Material cards skipped or all deleted.
- Outline skipped.

## 9. Parent Visibility

V0.6a adds a lightweight process summary. It does not redesign the full parent
report.

Parent-visible summary fields:

- Composition topic.
- Whether topic analysis was used.
- Whether the child confirmed or edited the topic focus.
- Number of material questions answered.
- Number of material cards retained.
- Whether the outline was confirmed or edited.
- Whether first draft, revision, comparison, and settlement were completed.

The summary should emphasize process and effort:

- The child practiced审题.
- The child recalled素材.
- The child organized an outline.
- The child revised after feedback.

It should not imply AI wrote the composition.

## 10. Data Model

V0.6a should reuse the existing `Essay` model and avoid a new prewriting table.

Existing fields to use:

- `Essay.status`
- `Essay.material_card`
- `Essay.outline`
- `EssayVersion.first_draft`
- `EssayVersion.revision`

Required essay statuses:

- `prewriting_started`
- `topic_ready`
- `materials_ready`
- `outline_ready`
- `revision_requested`
- `settled`

Status transition rule:

```text
prewriting_started -> topic_ready -> materials_ready -> outline_ready
-> revision_requested -> settled
```

Skip paths move forward by recording an explicit skip state for that step. For
example, a child who skips outline still moves to `outline_ready` before first
draft submission. Status records the furthest safe stage; detailed use/skip/edit
state lives in the JSON payload.

Status constraints:

- Prewriting endpoints may only operate before `revision_requested`.
- First-draft submission moves an essay to `revision_requested`.
- Revision settlement moves an essay to `settled`.
- `settled` essays cannot return to prewriting states.
- Edits to earlier prewriting data are allowed before first-draft submission,
  but they must preserve later child edits unless the endpoint explicitly resets
  that later step.

Both JSON containers must include a schema version:

```text
schema_version: "v0.6a.1"
```

New V0.6a classroom essays must initialize `Essay.material_card` and
`Essay.outline` with this schema version. Empty legacy JSON values are treated
as "no prewriting data" and must not be mutated into partial V0.6a data except
through V0.6a endpoints.

`Essay.material_card` stores:

- Raw question prompts.
- Child answers.
- Per-question skip states.
- Generated or empty card slots.
- Child edits.
- Card order.
- Card deletion state.
- Card source references back to child answers.

`Essay.outline` stores:

- Topic analysis cards.
- Child-confirmed topic focus.
- Topic focus skip state.
- Outline draft.
- Child-confirmed outline.
- Outline skip state.
- Timestamps for confirmation or edit actions.

`EssayVersion.first_draft` remains the boundary for existing essay feedback.
Prewriting does not create essay versions.

### 10.1 Minimum JSON Shape

`Essay.material_card` must normalize to this shape:

```text
{
  schema_version: "v0.6a.1",
  questions: [{ id, text, hint, order }],
  answers: [{ id, question_id, text, skipped, updated_at }],
  cards: [{
    id,
    category,              # event | detail | feeling_takeaway
    text,
    source_answer_ids,
    order,
    deleted,
    child_edited,
    placeholder
  }],
  step_state: {
    questions_status,      # not_started | generated | answered | skipped
    cards_status           # not_started | generated | edited | confirmed | skipped
  }
}
```

`Essay.outline` must normalize to this shape:

```text
{
  schema_version: "v0.6a.1",
  topic_analysis: {
    cards: [{ id, kind, title, body, required_points }],
    status                  # not_started | generated | skipped
  },
  child_topic_focus: {
    text,
    adopted_from_ai,
    skipped,
    updated_at
  },
  sections: [{
    id,
    slot,                   # cause | process | result | reflection
    heading,
    note,
    source_card_ids,
    child_edited,
    placeholder
  }],
  step_state: {
    outline_status          # not_started | generated | edited | confirmed | skipped
  }
}
```

### 10.2 PATCH Ownership

PATCH endpoints must merge their owned fields into the existing JSON document.
No endpoint may replace the whole `material_card` or `outline` object.

Field ownership:

- `topic-analysis` writes `outline.topic_analysis`.
- `topic-focus` writes `outline.child_topic_focus`.
- `material-answers` writes `material_card.answers` and question skip state.
- `material-cards` generation writes generated `material_card.cards` only before
  child card edits or confirmation.
- `material-cards` patch writes card text, deletion state, order, and
  `child_edited`.
- `outline` generation writes generated `outline.sections` only before child
  outline edits or confirmation.
- `outline` patch writes section text, source-card mapping, skip state, and
  `child_edited`.

Implementation tests must prove that updating one step preserves unrelated
fields written by earlier or later steps.

## 11. AI Tasks And Prompt Registry

V0.6a enables four previously reserved AI tasks:

- `writing_topic_analysis`
- `material_questions`
- `material_card_generation`
- `outline_generation`

Each task must use:

- `register_prompt()`
- A stable `prompt_key`
- A prompt `version`
- A `response_contract`
- A task wrapper that calls `get_prompt()`
- Pydantic validation
- Deterministic fallback
- ModelRouter task config
- LLMCallLog recording
- Daily limit behavior
- Cost/fallback observability from V0.5c

No V0.6 prompt may be hardcoded in routes or services outside the prompt
registry.

### 11.1 Contract Direction

The existing `MaterialCard` and `OutlineResult` contract names are too coarse
for the V0.6a product behavior. V0.6a must use clearer contracts for these
outputs:

- `WritingTopicAnalysis`: topic analysis cards.
- `MaterialQuestionsResult`: material questions.
- `MaterialCardsResult`: material card slots sourced from child answers.
- `WritingOutlineResult`: outline sections mapped to confirmed material cards.

Contracts must reject extra fields and must enforce short outputs.

Source references are required:

- Every non-placeholder material card must include at least one
  `source_answer_ids` entry.
- Placeholder material cards may have empty `source_answer_ids`, but must be
  marked `placeholder: true` and must not contain invented story content.
- Every outline section that contains story-specific content must include at
  least one `source_card_ids` entry.
- Placeholder outline sections may have empty `source_card_ids`, but must be
  marked `placeholder: true`.
- IDs returned by AI tasks must be validated against the current essay's saved
  answers or cards. Unknown source IDs fail validation and use fallback.

### 11.2 Deterministic Fallbacks

Fallbacks should preserve the child-agency rule.

Examples:

- Topic analysis fallback: generic three-card scaffold based on the topic text.
- Material questions fallback: fixed three questions for event/detail/feeling.
- Material card fallback: empty event/detail/feeling slots populated only from
  child answers that exist.
- Outline fallback: four empty outline slots with short prompts.

Fallback must not invent story content.

## 12. API Shape

V0.6a exposes separate prewriting actions instead of overloading the existing
draft-feedback endpoint. Endpoint names below are the implementation target; any
renaming must be recorded in the implementation plan before coding.

Required endpoints:

- `POST /api/students/{student_id}/writing-castle/classroom`
  - Create a classroom composition essay from teacher topic text.
- `POST /api/essays/{essay_id}/topic-analysis`
  - Generate and store topic analysis cards.
- `PATCH /api/essays/{essay_id}/topic-focus`
  - Save child confirmation, edit, or skip state.
- `POST /api/essays/{essay_id}/material-questions`
  - Generate and store 3 material questions.
- `PATCH /api/essays/{essay_id}/material-answers`
  - Save child answers and question skip states.
- `POST /api/essays/{essay_id}/material-cards`
  - Organize answers into editable material cards.
- `PATCH /api/essays/{essay_id}/material-cards`
  - Save card edits, deletion, and order.
- `POST /api/essays/{essay_id}/outline`
  - Generate an outline from retained cards.
- `PATCH /api/essays/{essay_id}/outline`
  - Save child confirmation, edits, or skip state.
- `POST /api/essays/{essay_id}/first-draft`
  - Submit the child's first draft for a prewriting essay, create
    `EssayVersion.first_draft`, and run existing `essay_feedback`.
- Existing `POST /api/students/{student_id}/essays`
  - Continue to support direct existing-draft submission.
- Existing `POST /api/essays/{essay_id}/revision`
  - Continue unchanged for revision submission.

The direct existing-draft route must remain backward compatible and tested. It
must not be overloaded with prewriting state transitions.

### 12.1 Idempotency And Repeat Clicks

Generation endpoints are idempotent by default.

- Repeating `topic-analysis`, `material-questions`, `material-cards`, or
  `outline` without `regenerate: true` returns the saved result for that step.
- `regenerate: true` is allowed only before the child has edited, confirmed, or
  skipped that step.
- After child edits or confirmation, regenerate attempts return `409` with a
  child-friendly recoverable message. Reset/regenerate-after-edit is out of
  scope for V0.6a.
- Repeated POSTs must not create duplicate card sets, duplicate outline
  sections, or overwrite child edits.
- PATCH endpoints must be safe for repeated identical saves.

## 13. Frontend UX

The child-facing flow should feel like a short wizard, not a form wall.

Required views:

- Writing Castle mode shell.
- Classroom topic entry.
- Topic analysis cards with child focus confirmation.
- Three material questions.
- Material card editor.
- Outline editor.
- First draft editor with scaffold reference.
- Existing feedback, revision, comparison, and settlement views.

UX requirements:

- The main path should fit a 5-minute topic-to-outline target for a typical
  child.
- Each prewriting page shows progress, such as `第 1 步 / 共 4 步：看懂题目`.
- Each step has a visible continue action and a visible skip action.
- Loading states use child-friendly staged copy.
- Errors offer retry or continue-with-fallback when safe.
- Text areas are sized for short child input first and use prompts such as
  `写一句就可以`.
- Card editing uses simple controls: edit, delete, move up, move down.
- The outline editor makes the child's active choices visible.
- Material card and outline pages both show a prominent `我想直接开始写` action.

The first screen should be the usable Writing Castle mode shell, not a marketing
or explanatory landing page.

## 15. Existing Loop Preservation

The existing essay loop is a release gate.

Must remain true:

- Direct first-draft entry still works.
- Existing draft submission still runs `essay_feedback`.
- Revision submission still runs `essay_revision_comparison`.
- Ability deltas from draft feedback and revision comparison remain unchanged
  unless a separate approved spec changes them.
- Settlement behavior remains unchanged.
- Existing feedback reactions continue to work for draft and revision feedback.
- Existing authentication and family access boundaries remain enforced.

## 17. Acceptance Criteria

- A child can complete classroom composition from teacher topic to outline
  confirmation in 5 minutes or less in the happy path.
- Topic analysis shows exactly three short cards.
- The child can confirm or edit the topic focus before continuing.
- Material questions show exactly three questions.
- The child can answer or skip each material question.
- Material cards produce event/detail/feeling-takeaway slots without invented
  content.
- Non-placeholder material cards include valid `source_answer_ids`.
- The child can edit, delete, and reorder material cards without drag-and-drop.
- Outline defaults to起因 / 经过 / 结果 / 感受.
- The child can confirm, edit, or skip the outline.
- Outline sections with story-specific content include valid `source_card_ids`.
- Confirmed outline content appears in the first-draft editor as reference.
- AI never generates copy-ready作文正文 in prewriting.
- `Essay.material_card` and `Essay.outline` include
  `schema_version: "v0.6a.1"` for V0.6a classroom essays.
- PATCH endpoints preserve unrelated JSON fields.
- Generation endpoints are idempotent by default and do not overwrite child
  edits on repeated clicks.
- Essay status follows the required prewriting state transition rule while
  allowing explicit skip paths.
- Parent process summary shows topic, answered questions, retained cards,
  outline confirmation/edit state, and downstream draft/revision completion.
- Existing direct draft -> AI feedback -> revision -> comparison -> settlement
  flow remains green in automated tests.

## 18. Risks And Mitigations

Risk: The flow is still too long for a child.

Mitigation: Every step can be skipped, and V0.6a optimizes for
topic-to-outline completion rather than perfect material collection.

Risk: AI silently invents better素材.

Mitigation: Contracts, prompts, fallback tests, and QA samples must enforce
source-from-child-answer behavior.

Risk: The outline feels like a generated answer.

Mitigation: Outline sections are short bullets, mapped to child-confirmed cards,
and require child confirmation or edit.

Risk: Existing essay loop regresses.

Mitigation: Keep prewriting separate from `EssayVersion.first_draft` until the
child submits a draft, and make old direct draft path a release gate.

Risk: Three-mode shell creates false expectations.

Mitigation: Classroom composition is the only complete V0.6a path. Other modes
remain weak, direct, or clearly deferred.

## 19. V0.6b Deferrals

Move these to a later spec:

- Full AI topic作文 path.
- Full free-writing path with distinct scaffolding.
- Topic-type-specific outline templates.
- Strong grade-level adaptation beyond current `grade_label` context.
- Rich parent weekly report integration.
- Topic bank with 10-20 recommendations.
- More advanced card interactions.
